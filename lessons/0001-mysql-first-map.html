先记一句：MongoDB 和 MySQL 都是数据库产品；差别主要在于它们组织数据和表达关系的方式不同。

1. 先分清三个角色

MySQL Server

真正保存数据、执行查询的服务。项目代码最终连接的是它。

Workbench

一个图形化客户端，方便人查看、查询和管理 MySQL；它不是数据库本身。

项目代码

通过驱动或 ORM 访问 Server。这个连接层可以交给 vibe coding 实现。

官方说明也把 Workbench 描述为用于可视化建模、SQL 开发和管理的工具。见 Community Edition 说明。

2. MongoDB 和 MySQL 怎么对照

你熟悉的 MongoDBMySQL 中接近的概念PM 视角的区别
Collection 集合Table 表MySQL 通常先定义表的列和类型，再放入记录。
Document 文档Row 行一条业务记录通常占一行，而不是一个自由结构的文档。
Field 字段Column 列列通常有明确类型、是否必填和约束。
嵌套对象或数组关联表，或 JSON 列需要先判断它是不是独立业务对象；不能默认全部塞进一列。
ObjectIdPrimary Key 主键都是“这条记录是谁”的身份标识，具体格式是实现决策。
Mongo 查询SQL查询语言不同；迁移不是简单替换几个函数名。

3. 套回当前项目

当前项目不是只有一类数据。代码里已经有用户、项目、工作记录、标签页、消息、文件上下文、项目文件、原型快照和操作记录等模型。

users -> projects -> work_records -> tabs -> messages
你需要把关的不是字段怎么写，而是这四件事：
  • 一个用户只能看到自己的项目和项目文件。
  • 删除项目时，应该一起消失的数据不能留下孤儿记录。
  • 迁移失败可以重试，不能让用户误以为成功。
  • 迁移前后，用户看到的核心产品行为保持一致。

这些就是产品经理的数据库知识边界：理解数据的业务关系、完整性和风险，不要求你亲自写建表脚本。
