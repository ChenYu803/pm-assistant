第 2 课 · 安装与验收

安装 MySQL：只做你该做的判断

你不需要研究安装器的每个选项。你只需要知道下载目标、几个关键选择和“成功”长什么样。

预计 10 分钟不改项目代码不卸载 MongoDB

先说结论

下载的是 MySQL Community Server，它才是保存数据的服务；Workbench 只是可选的图形化管理工具。

为了项目稳定，版本优先选官方标注的 LTS，不要因为数字最大就选择 Innovation 版本。具体版本由后续实现方案确认，先不凭感觉拍板。

1. 从哪里下载

  1. 打开 MySQL Community Server 官方下载页。
  2. 选择 Windows 和官方标注为 LTS 的版本；不要从来路不明的软件下载站下载。
  3. Windows 页面常见 MSI Installer 和 ZIP Archive。对初学者，优先选择 MSI Installer；ZIP 需要更多手动配置，不适合作为第一步。
  4. 如果安装器页面另有 web-community 和完整安装包：网络稳定可选 web-community，网络不稳定可选完整包。两者都是安装方式，不是两个不同的数据库产品。

官方当前下载页的版本和文件大小会变化；本课以页面上的 LTS 标记和文件类型为准，不把某个固定数字写死。

2. 安装界面只关心四项

安装项建议你要理解的原因
安装内容Server；Workbench 可选Server 才保存数据。Workbench 方便你看数据，但项目代码不依赖它。
管理员密码自己保存，不进 Git这是数据库最高权限凭据。后续代码应使用单独的应用账号，不应把管理员密码写进仓库。
端口先使用默认 3306本机客户端和项目默认会按这个端口寻找 MySQL；如果冲突，再让实现者处理。
Windows 服务建议启用自动启动电脑重启后 MySQL 能自动运行，减少“项目连不上数据库”的人为原因。

官方 Windows 文档把 MySQL Installer 列为简单且推荐的安装方式，并说明可将服务器配置为 Windows 服务。见 官方安装说明。

3. 安装成功的验收信号

不要以“安装器显示完成”作为唯一标准。至少确认下面三件事：

  • Workbench 能连接到本机的 MySQL Server，地址通常是 localhost，端口通常是 3306。
  • 能创建一个练习数据库，例如 pm_assistant_lab；这不是当前项目的正式数据。
  • 能执行最小查询 SELECT 1; 并得到结果 1。

这三个信号分别证明：服务在运行、你有权限、客户端和服务器能正常对话。任何一个失败，都先记录完整错误信息，再交给 vibe coding 或老师判断。

4. 这几件事暂时不要做

  • 不要卸载 MongoDB。迁移完成并验收前，它是回退和对照来源。
  • 不要把当前项目的 MONGODB_URI 直接改成一个猜出来的 MySQL 地址。
  • 不要把管理员密码、数据库备份或真实用户数据提交到 Git。
  • 不要把“能连上数据库”误认为“迁移完成”；迁移还需要关系、数据、权限和业务回归验收。

完成后告诉我这四件事

是否安装成功、你选的版本是否为 LTS、Workbench 能否连接、SELECT 1; 是否返回 1。遇到失败就贴完整错误，不要只说“报错了”。
