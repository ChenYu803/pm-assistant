# ADR-0002 — PRD 的读者是 AI，不是人

MVP 的 prd.md 落地版采用「五维度」结构（用户流程/状态机/字段规范/文案规范/异常处理），是给 PM 阅读的文档。v1.0 定稿时确认：**PRD 的读者是 AI**（「只会执行的程序员」），「直接拿去 vibe coding」是字面要求——用户把 PRD 丢给 Claude 即可开工，不能指望用户中途补写技术细节。

**决策**：v1.0 重构 PRD 结构，以「AI 无追问可执行」为验收标准，走**路线 A——业务规格完整，技术决策留给 AI**：PRD 补全页面清单、实体级数据模型、功能优先级、验收标准等业务语义，但 API 路由命名、schema 建法、代码组织等由 Claude Code 自行决定。现有五维度结构对人友好、对 AI 太粗犷（缺页面清单、实体级数据模型、功能优先级、验收标准；「文案规范」对 AI 零价值）。

**被否备选**：维持人读 PRD（无法满足「直接 vibe coding」的硬验收）；路线 B——PRD 写死数据模型/API 契约，AI 纯执行（PRD 变技术设计文档，脆、难维护、人读性崩坏）。

**后果**：PRD Agent 的 system prompt 需要随结构重构（超出原「方案 B」纪律微调范围）；v1.0 验收 = 作者本人拿真实 PRD 实际 vibe coding 一次跑通。
