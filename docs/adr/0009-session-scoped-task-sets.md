# 任务拆分会话各自生成并更新自己的文件集

2026-11-09，用户在 v1.45 澄清 Q27、Q32 中确认：同一产品迭代的任务拆分阶段可有多个会话，每个会话首次输出新建自己的整套任务文件，同会话再次输出更新自己那套，各套分别支持整套回退一版。即使注入了旧文件，也不取得覆盖其他会话成果的授权，不提供跨会话覆盖目标选择。

这取代 v1.41“每个产品迭代至多一套任务文件夹、该迭代的不同任务会话共同更新同一套”的数量与更新归属约定，以保留不同聊天产生的方案并延续“新会话新成果”的统一行为。任务文件仍是项目资产，保留来源迭代与会话；整套原子更新、整套回退及项目文件生命周期等未冲突的约定继续适用。

该决定要求后续实现区分不同会话的任务文件集，并明确现有数据的过渡关系；集合命名、存储与迁移方案另在实施输入中细化。此处记录已确认的产品边界，不代表代码或数据库已完成改造。
