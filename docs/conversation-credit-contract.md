# 会话积分调用与终态契约（v1.44 #07）

## 范围与发布边界

正式四环对话与旧会话共用 createAIStream 的调用授权；文件润色经 createAICompletion 使用同一契约。Replay 不访问供应商、不预留、不扣积分。管理员正常使用产品与普通账号同样检查余额。

本契约覆盖 #07 正常结算、#08 润色、#09 停止与故障终态及 #10 后台恢复与到期。此中间状态不能单独发布生产；相关迁移仅在随机隔离数据库验证，未升级日常或生产数据库。

## 调用身份与事务顺序

客户端为一次逻辑生成保存 requestId，账号内唯一；服务端保存会话、消息、请求参数 SHA-256 摘要。相同身份和参数返回原成功/失败结果；参数不同返回 409。进行中的相同请求或同会话其他生成返回 409。HTTP 500/502、网络断开、缺少 SSE result 均不能证明未提交，必须保留身份原样重试；明确 400/401/402/403/404 才可清理身份。成功确认后清理，下一次操作生成新身份。

所有资金写入遵循：锁 users 账号行 → 调用记录/来源及其他业务对象。首次预留在同一个短事务内完成账号状态检查、同会话互斥、赠送优先的来源分配、来源 available→reserved、调用/流水/model_requests 写入、每日额度占用。任一失败全部回滚；提交后才访问供应商。余额不足不访问上游，也不消耗每日次数。生成期间没有数据库长事务。

模型终态与资金处理同一短事务提交：先锁账号，再更新 model_requests、结算调用及流水。正式四环还与完整回复、候选、HTML 快照共同提交。独立结算在事务外先确定账号，再开始事务和锁账号，避免 REPEATABLE READ 在等待账号锁前建立过时余额快照。调用方传入已有 connection 时必须已经先锁账号。

业务消息创建早于资金授权，失败时保留用户输入。调用表不级联依赖项目、迭代、会话或消息；context_snapshot 保存稳定 ID、阶段、名称和迭代编号，禁止保存正文、系统提示、密钥或原始异常。删除业务对象不删除资金、来源分摊和追溯快照。

## 预算与实际发送边界

conversationBudget 接收实际发送的完整 messages：系统提示、全部选入历史、注入文件均先组装完毕，再计算预算。同一 messages 原样发送给 SDK，不截短正文。仅支持 string content 的 system/user/assistant；图片、工具、多模态和额外消息字段拒绝，新增输入形态须先建立费用边界。

输入预算 = JSON 序列化 messages 的 UTF-8 字节数 + 每消息 256 + 固定 4096。这是保守预算方法，**不是精确 token 计量，也未证明是当前供应商输入的硬上界**，详见下一节。

输出按操作类型设置：需求分析和旧普通对话 16384；原型、PRD、任务拆分及旧冻结生成 32768。长文交付保留较大预算，不以隐式缩短正文降低费用。实际 max_tokens 与预算使用同一个值；供应商 finish_reason=length 时显式提示内容未完成、请拆分任务，本次不扣积分，不将截断内容保存为成功候选。

预留人民币 = 输入预算 × 2 / 1000000 + 输出上限 × 8 / 1000000；积分 = 人民币 × 2000，向上保留八位小数。使用已核实峰时未命中价，不依赖缓存折扣。保存预算方法版本、输入摘要、输入边界、输出上限和价格依据，便于重算。实际结算复用 #06 的可靠 usage 和当次价格快照，允许缓存命中及空闲价降低实耗，不能把预留当成实耗。

### 已核查证据与未解决限制

2026-11-03 核查官方价格与 token 文档：

- https://api-docs.deepseek.com/zh-cn/quick_start/pricing
- https://api-docs.deepseek.com/zh-cn/quick_start/token_usage
- 官方离线 V4 tokenizer 包：https://cdn.deepseek.com/api-docs/deepseek_v4_tokenizer.zip

本轮下载的 tokenizer.json 为 6367096 字节，SHA-256 为 89085f12ef79460ac5f66d1119325ddfc694b4ab209d80bbd81d35f081dc9614。结构核查为 BPE，128000 vocab、127741 merges、256 个单字节 token，normalizer 不扩展文本，ByteLevel 不添加前缀空格。由此可推导该分词器的纯文本 token 数不超过 UTF-8 字节数；这不等于已经验证当前 Flash 服务的整个聊天请求计量。官方文档也明确实际计量以 usage 为准。

当前别名由供应商更新服务版本；离线 V4 样本不能证明服务端当前 tokenizer、隐藏包装、角色模板和推理前缀完全一致。每消息 256/固定 4096 是工程余量，供应商没有承诺其硬上界。专项验证完整输入没有丢失、预留公式和实际输出限制一致，**没有证明隐藏包装余量严格充分**。

影响：能证明账本不会扣成负余额、重复扣费或因未知成本估算扣费；尚不能宣称预留严格覆盖全部供应商成本或严格防透支。可靠 usage 超过输入/输出预算或实际费用超过预留时转 pending/budget_exceeded，保留原冻结、不追加扣分；网站可能承担差额。此保护不能代替可靠的调用前成本上界。

最小修正：取得与当前服务版本一致且包含角色/隐藏包装的官方 tokenizer+chat template，或官方 token-count 接口，并覆盖系统提示、历史、注入文件和推理前缀验证；没有该证据时，可改用已核实的模型硬上下文上限兜底，代价是显著增加冻结和准入门槛。接入新模型、价格、工具或多模态前重新核实，不沿用当前余量冒充硬保证。

## 状态与幂等终态

| 调用状态 | 资金含义 | 后续动作 |
| --- | --- | --- |
| reserved | 已原子授权，来源冻结 | 允许供应商调用；同会话互斥 |
| pending | 回复结束但缺可靠用量/价格，或超预算 | 保留该笔冻结；其他可用余额可继续使用 |
| settled | 可靠成本 × 2000 已消费 | 只释放未用部分；重试不重复扣款 |
| released | 网站承担故障，消费 0 | 全额释放；重发返回原失败结果 |

model_requests.running/processing 不是可直接收费终态。正常完成但 usage 或价格未知，consumed=NULL，记录 pending_since 与 reason，不能写零费用、猜测消费或立即释放。已确认零费用仍为 settled/0，与未知费用不同。故障免单不删供应商成本。stopped 有可靠用量时按实耗结算，否则待核对；停止与断线规则见下文。

终态结算重试是幂等的，settled/released 不再产生资金变化。pending 可在期限内补齐可靠证据后重试；恢复任务只走同一账号锁及结算入口。#10 已提供独立数据库扫描、过期 running/processing 处理、遗留 reserved 恢复和 24 小时免单；实际生产需启用 systemd timer，不能只启动网站。完整输入预算限制与目标机发布闸仍保留，详见 [恢复机制与启用](pending-usage-recovery.md)。

## 来源与流水数值

所有计算使用 10^8 单位 bigint，数据库 DECIMAL(28,8)，API 字符串。赠送优先，其次购买，同类按来源创建顺序。结算从原分摊中先消费赠送，再消费购买；剩余返还原来源，原实付不覆盖。

model_reserve/model_release 为可用与冻结之间转移，amount=0；allocations 保存实际移动金额，before/after 保存各来源分类的完整余额。model_settle 才记录负消费。逐来源、逐阶段快照连续推进：赠送 → 购买、消费 → 释放，避免同一总变化被重复计入两行。不能把冻结流水金额再次当成支出。调用记录另存 reserved 与 consumed，可与来源和供应商成本独立核对。

## 查询与 UI

readCreditStatement 在同一只读一致性事务中返回账号两类余额、流水和 reserved/pending 列表。工作台显示整个账号的可用/冻结合计，每条回复展示本次预留及实耗/待核对/免单状态；生成期间轮询只合并费用，不覆盖本地流式正文。账号余额每三秒、focus、页面重新可见和生成结束刷新。个人中心使用同一个查询与账本。跨设备依靠服务端事实恢复，正常调用无需逐次确认弹窗。

验收和证据见 [专项验证记录](verification/v144-conversation-credits.md)。


## 文件润色（v1.44 #08）

润色复用同一账号锁、预算、来源分摊和结算入口。调用身份为账号 + requestId；摘要绑定用途、项目、文件及完整输入。文件 UUID 作为调用互斥范围；同文件不同操作串行，润色与阶段会话可并行，最终由同一账号余额决定是否准入。三个真实模型入口（旧会话、新阶段、文件润色）均经 ai.ts；live 缺少 creditCall 或预算时拒绝，不保留润色例外。

polish-generation.ts 负责请求幂等与结果恢复。模型结果先处于 processing，仅 finish=stop 且有非空正文才接受完整预览。迁移 0030 新建 polish_generation_results；预览正文、completed 状态与资金结算在同一账号锁事务内提交。未应用、关闭或刷新不回滚正常费用；应用只修改编辑草稿，文件写入仍经既有显式保存接口。截断、空正文或生成故障免单，供应商成本记录保留。缺可靠用量的完整预览可使用，同时保留 pending 冻结。

润色 GET 按已授权账号、项目和文件查询指定 requestId 或最近结果，只读取持久事实；POST 相同身份和输入返回原结果/运行状态，不重发上游，变更输入返回 409。业务文件删除不会级联删除积分调用、供应商记录或预览；个人流水的文件名与修订快照仍保留来源。预览含用户正文，不进入管理员成本列表。

useFilePolish 按账号、项目和文件隔离浏览器 sessionStorage 草稿及待确认请求。网络错误、未知 500 和冲突保留原身份，只能按原输入重试；查询恢复后展示服务端费用。存储失败时保留界面正文并暂停新调用。手工编辑、保存、查看、下载及非模型上下文管理不计费。不采用结果会记住该选择，重开不会再次自动弹出同一预览。

#09 的停止与异常细分见下节，#10 负责进程崩溃遗留及到期扫描；本票的重启证据只覆盖已完成和 pending 事实，不宣称运行中任务自动恢复。完整输入预算仍受上文隐藏包装边界限制。验证入口：npm run verify:v144-polish-credits；证据见 [润色积分验证](verification/v144-polish-credits.md)。


## 主动停止与故障（v1.44 #09）

迁移 0031 在 model_requests 增加 stop_requested_at。停止入口先锁账号，再将业务消息停止及模型停止意图同事务提交；润色 DELETE 在同一 ownership 校验后按账号、requestId、文件登记意图。真实供应商请求每 250ms 查询该意图，并将独立上游 AbortController 标记为 user_stop；浏览器关闭、网络断开或取消读取响应只结束传输，服务端继续保存实际结果及计量。数据库暂时查询失败不能当作主动停止或零成本。

有可靠 usage、结束证据及适用价格的 stopped 调用按实耗结算，reason=stopped_confirmed；缺少可靠成本则 pending，reason=stopped_usage_unconfirmed，保留本调用冻结并持久显示待核对。停止后 SDK 抛出取消异常与供应商 HTTP、协议、断流异常分别处理；供应商失败或网站正文/预览/结算写入故障立即免单释放本次预留，其他并行预留不受影响。故障已知供应商成本保留，未知成本不记零。

模型终态与结算使用同一账号锁串行化。先成功提交的 settled/released 为不可逆资金终态，重复停止、重放与结算不再改账。停止先提交时，迟到正常完成转 stopped；正常完成先提交时，迟到取消返回原终态。明确故障免单后，迟到可靠证据仅补充网站成本，不恢复付费。结算事务失败后回滚，再尝试以网站故障免单；若前次 commit 实际已成功，终态保护返回原结果。数据库持续不可用时保留原持久记录，恢复任务由 #10 收口，不能宣称所有数据库失联均即时释放。

阶段回复、旧消息及冻结正文、润色预览在各自账号锁事务内确认完成与费用。编辑/重生成停止时，已有调用的失败回复继续保留费用载体；无模型调用的临时占位可清理。润色停止是可查询终态，两个文件编辑器共用停止按钮及费用提示；切换文件后迟到的停止响应不会更新新文件。个人流水和后台从同一持久事实读取。

本票不新增供应商事后用量查询接口，也不实现进程崩溃扫描或 24 小时到期；专项证据见 [停止与故障结算验收](verification/v144-stop-billing.md)。


## 后台恢复与到期（v1.44 #10）

pending_since 是 UTC 的首次进入待核对时间，重试不刷新期限。settleConversationCredits 在账号锁内同时判断 24 小时到期，到期写 released/consumed=0/reason=pending_expired 并标记网站承担；与迟到证据竞争也只能形成一份资金终态。model-metering 为首次完成保留 windowConfirmed 及原结束价格，迟到证据补齐不改变正文完成状态、不用核对时价格代替原请求价格。已有免单仅补成本，不追扣。未有原窗口可靠证明的历史证据保持未知。

recoverPendingUsage 分批扫描持久任务、每笔独立事务，错误回滚且不阻塞后续记录；失败项在下轮重扫。提供独立 CLI、每分钟 systemd timer 及持久补跑；不新增生产证据注入或时间推进接口。隔离时钟沿用已有严格门禁。可恢复状态与生产启用依据见 [处理说明](pending-usage-recovery.md)，专项证据见 [#10 验收](verification/v144-pending-usage.md)。
