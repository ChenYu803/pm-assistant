# v1.41 专项质量与视觉验收（23 号票）

## 运行与边界

```powershell
npm run verify:v141-quality-visual-gate
npm run verify:v141-markdown-progress
```

完整入口先执行有硬超时保护的 Markdown 渲染回归，再串行运行 19—22 专项和 23 号视觉场景。每项创建自己的随机空 MySQL 测试库和应用账号，使用正式工作区源码的隔离副本与 `AI_MODE=replay`；不调用真实模型，不清理日常业务库。生产构建与这些回放必须串行：隔离应用位于 `.next` 下，`next build` 的清理会破坏同时运行的隔离服务。

本票汇总专项结果并整理正式工作台的视觉，不代替 24 号从空库开始的完整连续发布回放。依据为当前 ticket、v1.41 视觉故事 101—115、正式界面和用户授权的设计调整，无新增原型输入。

## 正式界面调整

- 保留暖纸色、墨黑会话栏和珊瑚色强调，拉开对话阅读面、文件区与会话区的层级；弱化重复边框与大面积深色消息块。
- 明确中文无衬线字体、统一导航与面板标题、消息与候选排版；Agent 正文复用安全 Markdown 渲染，用户输入保留文本展示。
- 长候选文件名保留完整值与 title，展示按两行摘要和单行路径收束；文件树保持截断和完整路径，来源正文继续换行并独立滚动。
- 统一 SVG 文件、关闭、下载图标，以及移动端候选确认、上下文移除、预览关闭、会话创建/删除等触控尺寸；横屏压缩输入区，核心发送与停止可达。
- 修复既有 Markdown 解析器遇到半截标题或非完整水平线时不推进索引的问题，防止格式化对话冻结页面；兜底仍经原有安全转义处理。

视觉检查覆盖四环空阶段、长项目/迭代/会话/文件名、真实待确认候选、文件树、上下文、来源时间线、生成中停止、消息读取失败与重试、独立草稿、键盘切换及焦点。额外检查 320×740、768×900、1100×800、844×390、1101×800、1280×800，以及 720×450 的桌面 200% 缩放等效 CSS 重排；后者不是浏览器缩放按钮的实际操作记录。浏览器使用 reduced-motion 偏好，不添加装饰性入场动效。

## 失败与修复记录

1. [初次视觉预检](v141-quality/23-first-pass.json) 为 62 通过、4 失败：刷新后保留内存草稿的错误预期，以及未将长卡片底部按钮本身滚入视口的检查；另有入口的失败计数。改为同阶段会话切换制造读取故障，检查按钮真实滚动可达，不改变业务契约。
2. [首次完整质量闸](v141-quality/first-full/summary.json) 为 748 通过、2 失败。19—22 全部通过；23 因停止后的异步读取与新建会话选择守卫竞态中断。夹具现在显式选择实际创建的新会话，继续严格核对被选身份、独立草稿与读取失败恢复，不修改正式会话业务逻辑。
3. Spec 复核发现 Markdown 空转，实际组件的 [红证据](v141-quality/markdown-progress-red.json) 有 6 项子进程硬超时，修复后 [12 项回归](v141-quality/markdown-progress.json) 通过。覆盖半截标记、连续内容、列表边界、空白、未闭合围栏的终止性，以及安全转义和危险链接拒绝。
4. [环境中断](v141-quality/environment-interruption/summary.json) 记录构建与回放并发造成的 19 号隔离服务启动失败，[构建错误](v141-quality/environment-interruption/build.json) 单独保留。后续只重跑受影响的 19 号；恢复前后逐项比对同一源码指纹，合并摘要明确标注恢复，不将其描述为一次完整连续发布回放。
