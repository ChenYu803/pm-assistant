# v1.41 任务与权限专项回放（21 号票）

运行入口：

```powershell
npm run verify:v141-task-permission-replay
```

使用本机 `db:init` 相同的 MySQL 维护配置，要求 `AI_MODE=replay`、依赖已安装且 Playwright 能启动 Edge。无需产品经理准备原型或业务数据。脚本通过 `scripts/verify-v141-isolated-replay.mjs` 创建随机命名的独立空库和专用应用账号，重复初始化正式 schema，并在注册前核对全部业务表为空；不会连接日常开发服务或清空现有业务库。

验收应用使用执行时正式工作区源码的隔离副本，覆盖开工前已有但尚未提交的实现。网站进程不继承维护账号，不复制 `.env.local`，使用随机本机端口；结束时只清理本次确实创建的测试库、账号和源码副本。提交仅包含本票增量，不替其他会话收口未提交实现。

## 验收范围

桌面 1440×900 和移动 390×844 分别执行连续流程：注册、建立项目与产品迭代、开启任务阶段会话、生成 replay Agent 候选、审阅和整套确认，再通过手动提案构造混合差异、失败重试、整套撤回和权限检查。任务文件通过正式产品动作产生，MySQL 查询用于观察最终结果，不直接注入任务成果。

| 票据要求 | 验证边界 |
| --- | --- |
| 每迭代至多一个文件夹，序号不复用 | 创建与重复创建的公开响应、文件夹持久归属、删除及撤回后的新增编号 |
| 所属可改，其他迭代只读 | 正式文件树、正文预览、下载和上下文操作，以及编辑、改名、删除、提交和撤回请求 |
| 只能整套确认或放弃 | 同一候选的新增、更新和删除差异、完整正文、正式确认与放弃控件、成功后的完整集合 |
| 失败无半套，候选可重试 | replay 故障注入后的公开失败反馈和数据库正文、稳定身份、修订、序号、唯一旧集合与来源记录 |
| 一次撤回完整恢复 | 恢复旧身份、序号、路径及正文，移除新增、恢复删除、消耗快照、拒绝重复撤回 |
| 跨项目及跨用户不泄露 | 文件夹、目录、正文、下载、详情、上下文和候选请求的拒绝响应及持久状态 |

跨项目检查使用同一账号的另一个项目，跨用户检查使用独立浏览器上下文中的另一个正式注册账号；响应内容不能包含被保护的正文或名称。测试不以隐藏按钮替代服务端权限证据，也不以拒绝状态码替代数据库结果核对。

## 请求参数与故障观察

共享环境入口只在本次隔离副本的 `createAIStream` 边界记录实际 `agentType` 和 `messages`，不替换正式 prompt、用户输入或 replay 输出。加载任务文件后，通过唯一消息探针关联实际请求，检查正文注入。证据验证请求事实，不评估真实模型的理解或遵从能力。

事务失败使用产品已有的非生产 replay 故障头 `x-pm-assistant-test-task-failure`；不伪造成功响应或直接改库制造失败。完整回放与故障日志、逐条断言、权限矩阵、截图、供应商请求参数及清理结果保存在运行时输出的临时证据目录。

本票只提供任务与权限专项证据，不替代 24 号最终四环连续回放，不运行真实模型。

## 验收发现的界面修复

整套撤回已在数据库恢复被删 issue，但目录刷新仍在进行时，用户立即打开树上的删除占位，会把“已删除”复制到弹窗状态。原实现不会随新目录修正这个状态，弹窗因而一直停在来源详情，无法预览已经恢复的正文。

`ProjectFileTree.tsx` 现在随新目录同步已选文件的事实；删除状态变化时切换正文预览或来源详情，正文修订变化时重新读取当前正文。只在目录引用变化时调整本组件状态，避免循环；该调整方式参照 [React 官方状态同步指南](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes)。不改变服务端写入、撤回或权限协议。

回归用例用受控 Promise 延迟本次公开目录 GET 的真实响应：整套撤回成功后，在旧删除占位上立即打开文件，再释放新目录。无需关闭重开，原弹窗必须恢复正文预览和编辑入口。该触发条件在两个视口分别验证，不用固定等待时间绕过问题。
