# v1.44 #03 最小管理员入口与账号停用验收

日期：2026-11-03。工单：`.scratch/v1.44/issues/03-minimal-admin-account-controls.md`。风险等级：L2（账号权限、存储迁移、共享模型入口）。

## 实现与配置

- 复用既有邮箱密码认证。服务端环境变量 `ADMIN_EMAILS` 以英文逗号分隔指定账号的完整邮箱，不提供默认管理员、测试账号提权或公开注册提权。数据库账号邮箱与白名单完整匹配，客户端角色、请求头和操作者字段均不参与授权。
- 指定且正常的管理员在个人主页看到「管理后台」，访问 `/admin`。页面和 `GET /api/admin/users`、`POST /api/admin/users/[id]/disable` 各自授权。匿名跳登录/接口401，普通用户页面拒绝访问/接口403，拒绝响应不含其他账号资料。
- 账号邮箱字面查询或完整ID查询、正常/停用筛选、每页20位、稳定排序与数量汇总。只展示账号及运营所需停用元数据，无对话和文件正文浏览入口；既有跨账号正文访问权限保持不变。
- 停用必须填写1–500个字符的业务说明。服务端锁定操作者与目标并再次授权，账号状态与操作者、时间、原因及审计事件同事务提交。禁止停用自己；重复提交不覆盖首次停用记录。没有恢复或删除审计的后台接口。
- 迁移 `0025_v144_account_controls` 仅增加账号状态/停用字段、索引和审计表。旧账号默认正常，项目、文件和正文保持。部署迁移需另按生产纪律先备份并验证可恢复性，本次未操作日常库和生产库。
- 普通登录拒绝已停用账号；所有业务API鉴权读取实时状态，Stream/Completion共享模型边界再次检查，旧JWT不能恢复模型能力；密码重置也不重置停用状态。已开始的生成不在本票主动终止范围。
- 管理接口不记录请求正文、密码或模型密钥，错误只打印固定文案。停用原因属于业务审计资料。成功管理响应标记 `private, no-store`。

## 验证方法与边界

正式应用服务、浏览器与HTTP/API加随机隔离MySQL；只替换外部邮件投递和模型供应商边界。管理员由本轮随机邮箱显式指定，未配置专项则清除继承的管理员配置。真实SDK请求只到127.0.0.1的HTTP供应商，不记录提示词或凭据。统计launcher汇总时不重复加内部断言。

## 生产交接

生产指定管理员邮箱尚未由运营者明确，因此本次没有配置真实管理员或宣称目标机验收。运营者需提供已经注册且由其控制的完整邮箱，在受控服务器环境配置 `ADMIN_EMAILS` 并重启服务；不得把隔离测试邮箱填入生产。正式迁移、服务重启、真实管理员/普通账号/匿名验收由后续发布步骤执行。

本次不部署、不push，不访问真实模型供应商，不更改日常/生产数据；不将隔离验收等同于生产可用。
