# v1.41 文件与上下文专项回放（20 号票）

运行入口：

```powershell
npm run verify:v141-file-context-replay
```

使用本机 `db:init` 相同的 MySQL 维护配置，要求 `AI_MODE=replay`、依赖已安装且 Playwright 能启动 Edge。无需准备原型或业务数据；脚本不连接日常开发服务，也不清空现有业务库。

每次创建随机命名的独立空测试库和专用应用账号，重复初始化正式 schema，在注册前核对全部业务表为空。共享环境入口 `scripts/verify-v141-isolated-replay.mjs` 将当前正式源码复制到同盘 `.next` 的临时目录，用依赖链接和随机本机端口启动正式 Next 应用。网站进程不继承维护账号，不复制 `.env.local`，结束时只删除本次确实创建的测试资源。19 号基础业务回放也使用该入口，场景和验收标准保持不变。

20 号专项通过桌面 1440×900 和移动 390×844 的正式界面完成文件交付及上下文操作，再用公开 API 和独立库事实交叉核对。测试正文与账号由脚本构造，不使用现有业务数据。运行证据保存在终端输出的临时目录，包括初始空库计数、逐条断言、浏览器截图、日志和资源清理结果。

## 请求参数的观察边界

只有本次隔离源码副本的 `createAIStream` 增加一条同步参数记录，写入 `provider-requests.jsonl`。记录的是聊天路由实际传入 AI 请求边界的 `agentType` 和完整 `messages`，没有替换 prompt、用户输入或固定回放回复。`provider-observation.json` 保存原始 `ai.ts` 的 SHA-256 和插桩说明；仓库正式 AI 代码不因本票修改。

上下文断言选择带唯一用户探针的实际请求，分别核对 system 上下文和历史对话。未加载的正文必须不进入 system 上下文；历史用户或 Agent 曾主动说过的文本不能被误判为自动读取文件。该证据验证注入事实，不评估真实模型是否理解或遵从提示词。

## 验收范围

| 票据要求 | 证据 |
| --- | --- |
| 固定四树枝、无当前迭代只读 | 真实界面的目录、正文预览和下载，以及持久变更与加载入口的权限 |
| 手动上下文 | 空集合、预览不加载、加载后正文与来源摘要、跨迭代更新后下一轮读取当前正文、移除后下一轮不注入、时间线不自动注入 |
| 普通文件交付 | 三个阶段的真实 replay 候选、确认前项目资产不变、确认创建/覆盖后进入对应树枝、存储与下载纯正文一致 |
| HTML 独立快照 | 预览、下载、再次打开，与项目文件和上下文集合隔离 |
| 修订与一次撤回 | 创建、覆盖、用户编辑的递增修订，唯一上一版被下一次成功正文变更替换，撤回新增修订并消耗备份，无重做 |
| 来源追溯 | 详情、改名、删除、本轮写入、Agent 与用户操作区分，删除来源会话/迭代后保留名称和路径快照 |

本票验收的是执行时的正式工作区源码，其中包含开工前已存在但尚未提交的 10 号 PRD 实现。本票提交只包含自己的增量，不替其他会话提交该实现；发布前仍须收口这些实现提交，并由 24 号对最终代码执行连续回放。

本票只提供文件与上下文专项证据，不替代 21—23 号专项或 24 号最终四环连续回放，不运行真实模型。
