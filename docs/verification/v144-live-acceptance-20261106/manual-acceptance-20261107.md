# #15 其他人工项验收流程（2026-11-07）

使用当前SSH受控连接和原专用Chrome。保留普通窗口的管理员登录；普通用户测试使用同一Chrome的无痕窗口（Ctrl+Shift+N），避免覆盖管理员会话。已通过的注册找回、微信展示、管理员赠送及正常短对话无需重复。

本次人工项：邀请码、普通用户权限、个人余额流水、文件润色。代理负责停止计量修复、供应商能力及预算核对、邮件安全配置核验与发布准备；人工操作完成不等于正式开放。当前累计已知计提0.011943元，另有一笔停止费用未知，不将未知按零计算。本流程最多增加两次模型调用：一次短文件生成、一次润色；不点击停止，不反复发送或自动重试。

## 1. 管理员查看邀请码

打开 https://ideastage.top/admin/gift-invites 。

- 若已有可用的完整邀请码，直接取其中一个作测试；页面中的邀请码ID不能当作完整兑换码。
- 若显示“初始化首批邀请码”，填写原因“#15目标环境人工验收”，点击“创建首批邀请码”一次。此操作会真实创建首批100个邀请码，每码2000赠送积分，初始化不可重复。
- 成功后立即点击“复制全部”，将完整码保存到自己的密码管理器或受限本机文件，再离开页面。完整码仅此次显示；不要发送到聊天、Git或公开文档。
- 选择一个完整码供本次兑换，其余保留。没有取得完整码时不要反复初始化；只反馈现状。

预期：初始化后显示100个码及管理记录；或者已有批次正常显示。邀请码只是试用赠送，不涉及真实付款。

## 2. 普通用户登录与后台拒绝

在上述Chrome中按Ctrl+Shift+N打开无痕窗口，访问 https://ideastage.top 。使用一个不在管理员名单中的、由你控制的邮箱登录；若没有该账号，正常注册一次，注册页邀请码先留空。验证码与密码只填网页。

在该普通账号中分别打开：

1. https://ideastage.top/admin
2. https://ideastage.top/admin/gift-invites
3. https://ideastage.top/api/admin/users
4. https://ideastage.top/api/admin/gift-invites

预期：前两项提示无权访问，不显示管理数据；后两项返回拒绝信息，不返回用户或邀请码列表。若账号刚注册，个人中心应正常打开，不能只是未登录跳转来代替普通用户权限验证。

## 3. 邀请码兑换及余额流水

普通账号打开 https://ideastage.top/profile ，记录兑换前赠送可用、购买可用和预留积分。在“赠送邀请码”输入第1步保管的一个完整码，点击“兑换积分”一次。

预期：提示兑换成功，赠送可用增加2000，购买积分不变；页面显示已领取且兑换入口关闭。刷新后余额不重复增加，明细只有一笔对应的赠送入账。切回普通窗口管理员邀请码页，刷新后应看到该码已领取，领取账号与时间对应。

可选拒绝分支：在成功兑换前先输入一个明确不存在的码，预期拒绝且余额不变。作废测试会真实永久作废一张未领取码，不要求为了凑验收随意消耗邀请码；需要验证时先保管该码，再由管理员在对应ID行填写“#15作废验收”并作废，普通账号在尚未兑换成功时验证该码被拒绝。完成有效码兑换后入口关闭，无需继续尝试。

## 4. 个人中心与后台记录对应

查看普通账号 https://ideastage.top/profile 的余额、赠送/购买区分与流水。切回管理员普通窗口，在 https://ideastage.top/admin 查询该测试账号，打开“查看积分 / 赠送与调整”，核对同一笔邀请码赠送和余额。

仅查看；无需转账、创建人工充值、退款或修改原停止请求的预留。管理员原账号的317.088待核对预留与新普通账号分属不同账户。

## 5. 文件润色（最多两次模型调用）

回到原管理员普通窗口及现有“#15验收”项目，沿用已有测试赠送积分。若已有可编辑的短Markdown文件，直接进入步骤3，省去文件生成调用。

1. 进入“需求分析”对话，发送一次：

   > 这是文件润色验收。校园二手交易产品面向本校学生，核心功能只有发布闲置、搜索和站内联系。请基于以上已知信息直接交付一份约200字的需求分析文件候选，文件名为“润色验收.md”；未知信息注明待验证，本次不要追问。

   等待自然结束；记录积分提示。若未出现文件候选或显示待核对/错误，不追加生成，保留页面并反馈。
2. 出现“需求分析文件候选”后点击“确认创建”一次，确认文件树出现该文档。仅有聊天正文不算文件创建成功。
3. 打开文件并进入编辑，记录原文，点击“AI 润色”一次，等待完成；本次不要点击“停止润色”。
4. 预期出现“AI 润色结果”、本次实际消耗、“应用润色 / 保留原文”。生成结果时即计费，关闭或不采用结果也不会免单。
5. 点击“应用润色”，再点击“保存修改”（弹窗中的保存按钮可能显示为“保存”）。重新打开文件，确认正文是保存后的内容。
6. 刷新个人中心，核对生成文件与润色各自的消耗和余额；管理员“模型请求与成本”页 https://ideastage.top/admin/model-requests 应出现对应记录。精确用量、成本和账本关联由代理只读复核，不要求人工计算。

任何一步遇到报错、重复记录或新的待核对，保留页面，不重复点击调用。后台旧停止请求仍pending不等于这次润色失败，按各自记录区分。

## 结果反馈模板

只需填写结果，不要提供邮箱密码、验证码或完整邀请码。

- 邀请码：初始化/已有批次；兑换成功/失败；增加积分；刷新是否重复。
- 普通用户：后台页面拒绝/未拒绝；两个管理API拒绝/返回了数据。
- 余额流水：普通用户与后台是否一致。
- 文件：候选创建成功/未出现；是否只调用一次生成。
- 润色：结果是否出现；本次预留和实际消耗；保存后重开是否保留。
- 异常：页面路径、大致时间、原始提示。

注册找回不重测，SES权限和正式开放不由人工页面反馈代替。停止计量另由代理修复；本机修复未部署前，原输入框残留问题仍可能存在。
