## 1. 取得一个邀请码（管理员普通窗口）

打开 https://ideastage.top/admin/gift-invites 。

- 已保管可用完整邀请码时，直接选一个，跳过初始化。页面中的邀请码 ID 不能当作兑换码。
- 若尚未初始化，填写原因“#15目标环境人工验收”，点击“创建首批邀请码”一次。会真实创建100个码，每码2000赠送积分。
- 创建后立即“复制全部”，保存到自己的密码管理器或受限本机文件；完整码仅此次显示，不发到聊天或 Git。
- 已初始化但没有完整码时，反馈现状，不反复初始化。

## 2. 普通账号访问后台（无痕窗口）

使用一个不在管理员名单中的、由你控制的普通账号登录。没有普通账号时正常注册一次，注册页邀请码留空；这是准备测试账号，无需重做已完成的注册验收。

登录后先确认个人中心可打开，再分别访问：

- https://ideastage.top/admin
- https://ideastage.top/admin/gift-invites
- https://ideastage.top/api/admin/users
- https://ideastage.top/api/admin/gift-invites

预期：管理页面拒绝访问，管理 API 返回拒绝信息，不展示用户或邀请码列表。需要是已登录普通用户的拒绝结果，未登录跳转不算。

## 3. 兑换与个人流水（普通账号）

打开 https://ideastage.top/profile ，记录兑换前赠送可用积分。在“赠送邀请码”输入第1步取得的完整码，点击“兑换积分”一次。

预期：赠送可用增加2000，购买积分不变；显示已领取且兑换入口关闭。刷新后余额不重复增加，明细只有一笔对应赠送。

本次不再手动测试无效码、作废码或永久作废邀请码，也不要求切回后台逐项对账。相关异常分支已有隔离自动验证；这次真实兑换的后台记录仍由代理另行核对，尚未记为通过。

## 4. 文件润色与保存（原管理员普通窗口）

回到现有“#15验收”项目，使用已有测试赠送积分。已有可编辑的短 Markdown 文件时，直接从第3步开始，省去生成调用。

1. 在“需求分析”对话发送一次：

   > 这是文件润色验收。校园二手交易产品面向本校学生，核心功能只有发布闲置、搜索和站内联系。请基于以上已知信息直接交付一份约200字的需求分析文件候选，文件名为“润色验收.md”；未知信息注明待验证，本次不要追问。

   等待自然结束。若没有文件候选或出现错误、待核对，保留提示并反馈，不追加生成。
2. 出现“需求分析文件候选”后点击“确认创建”一次，确认文件树出现该文件。仅聊天正文不算文件创建成功。
3. 打开文件进入编辑，点击“AI 润色”一次，等待完成，本次不点击停止。
4. 确认出现润色结果、“应用润色 / 保留原文”和实际消耗；记录页面积分提示。
5. 点击“应用润色”，再点击“保存修改”（弹窗按钮可能显示“保存”）。重新打开文件，确认内容保留。

无需再到模型请求后台手动比对 token、成本或流水；代理根据本次操作记录核对。遇到报错或新的待核对时，不重复点击模型调用。

- 邀请码：已有完整码 / 本次创建成功 / 无完整码。
- 普通账号：两个管理页面及两个管理 API 是否均拒绝访问。
- 兑换：成功 / 失败；赠送增加多少；刷新是否重复；是否出现对应流水。
- 文件：使用已有文件 / 候选确认创建成功 / 未出现候选。
- 润色：是否出现结果；页面积分提示；保存后重开是否保留。
- 异常：页面路径、大致时间、原始提示。
