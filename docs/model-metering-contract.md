# 官方模型计量契约（v1.44 #06）

共享入口为 `createAIStream` 与 `createAICompletion`（src/lib/ai.ts）。旧会话、阶段会话和润色均通过此边界；本地会话命名不调用模型。Replay 不写真实成本。每日请求次数限制仍先于上游访问，提示保持“今日次数已用完”，不冒充积分或金额余额。

## 持久事实

迁移 0028 新增 model_requests，保留原账号和业务表；当前会话只运行隔离新库迁移，不升级日常库或生产库。每次真正访问上游之前先落请求记录，保存网站调用 UUID、账号、用途、项目/会话/文件关联、请求模型、实际输出上限、stream/completion 模式、UTC 开始时间和期限。响应补充供应商调用 ID、上游 HTTP request ID、实际返回模型、结束原因、可靠用量、价格快照及成本。默认日志和后台均不保存或展示正文、系统提示、密钥或原始错误正文。

状态分开表达：请求 running/processing/completed/stopped/failed/interrupted；用量 reliable/pending；成本 confirmed/usage_unconfirmed/price_unconfirmed（运行期 awaiting_usage）；cost_cny 为 NULL 时成本未知，不能按零元结算。真实零用量经验证后可以保存已确认零成本。失败/中断由网站承担；用户免单不删除供应商费用。超过请求 timeout + 60 秒仍为 running/processing 的记录在后台显示“中断”，并计入网站承担待确认；这是进程退出/最终写库失败的保守展示，已知成本也会计入网站承担，不伪造用量或改写原始记录。

## 用量和可重算成本

可靠用量要求非负安全整数、输入 = 命中 + 未命中、总量 = 输入 + 输出，缓存别名一致，推理量不超过输出量，并已观察到非空结束原因。可从 prompt_cache_hit_tokens 或 prompt_tokens_details.cached_tokens 取得命中量；官方字段缺失但输入和命中可靠时，可按两者之差求未命中。缺少缓存分类不能猜价；非法/冲突用量标 pending。reasoning_tokens 已包含在 completion_tokens，不重复计费。延迟的 usage-only 块可以在先前 finish_reason 后补足计量。

成本 = （缓存命中量 × 命中单价 + 未命中量 × 未命中单价 + 输出量 × 输出单价）/ 1000000；单价为人民币/百万 tokens。bigint 与 DECIMAL(28,8) 避免二进制浮点误差。每笔保存使用的价格版本、核实日期、官方来源、起止价格及计量有效性，已知结果可按快照确定重算。

官方价格依据和本机 live 样本见 [核验记录](verification/v144-model-usage-cost.md)。仅对官方 HTTPS DeepSeek Flash 端点和已核实别名启用官方价格；生产其他端点不能冒用此价格。受限本机供应商替身在记录中明确 fixture=true，不是 live 费用证据。价格日历核实到 2026 年，快照从 2026-11-03 开始适用；未来年份、未知模型、跨高峰/空闲窗口、跨 UTC 日期或持续超一小时的请求保留用量但成本待确认，需要先核对定价。此保守限制不能用作扣分依据。

## 兼容扩展和后续结算

文本返回类型与流式块形状保持兼容。新增 ModelContext 用于用途与业务关联，onRequest(id) 提供调用关联，计量终态始终独立落库，是否传入回调不影响持久化；onReceipt(receipt) 仅在计量落库后通知，含 id/status/usageStatus/costCny/costReason。回调不应抛错，后续账本需按调用 ID 幂等。旧会话和阶段会话传入 awaitProcessing=true，供应商结束后先写 processing，正文及必要操作持久化后才由 completeModelProcessing 确认 completed；阶段会话在正文同一事务内完成确认。processing 不能作为扣分成功依据。润色只返回建议正文，不存在此持久化阶段。实际发送的 max_tokens 已保存，07/08 再建立预留和扣分，不在本票扣分。

上游 HTTP 失败、流式异常、取消均落终态；错误仅保存安全类别或 HTTP 状态。供应商 `insufficient_system_resource` / `content_filter` 结束原因按失败处理，即使已有文本和可靠用量也保留真实成本、标记网站承担，并让业务走失败清理；未知结束原因按中断处理。收到文本但无结束证据时，沿用既有文本行为，计量记录中断和未知成本。网站消费流中断也会通过生成器 finally 留下记录；完整消费后正文持久化失败会补标网站承担，并保留供应商已知用量和价格。若补标写库失败，仅记录安全调用 ID 供运维追查，仍继续会话、操作和冻结失败清理；原持久 processing 仍可在期限后识别为中断和网站承担，不会永久误作成功。

主动停止/断流若未收到最终可靠用量，不按文本长度推算。公开官方接口未发现按单次请求事后查询计量的能力，本票不编造自动恢复；后续核对必须取得可信供应商证据。正常故障免单和用户待核对的积分动作由 08 实现。

## 运营查询与预算

管理员页面 /admin/model-requests 和 API /api/admin/model-requests 均独立服务端授权；匿名401、普通账号403，响应 private/no-store。按完整网站调用ID、账号ID、供应商ID、上游请求ID精确查询，按请求/用量状态筛选，每页20条；全累计汇总不随列表筛选改变。

200 元为本轮开发验证至首批试用累计模型预算，不按月重置，不包含服务器/域名/邮件，也不从积分售价倒推成本。上线计量以前的历史成本和本机直接官方探测尚未写入业务数据库，后台明确提示覆盖不完整，不能给出虚构的剩余预算。探测的可确认费用与待确认次数在核验记录单列；后续发布前需核对历史账单与目标机计量。
