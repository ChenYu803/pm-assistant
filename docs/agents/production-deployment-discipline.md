# IdeaStage 上线部署纪律

适用范围：服务器配置、凭据生成、数据库初始化/迁移、域名与 HTTPS、服务启动、备份恢复及发布交接。用户要求重要操作有持久记录，重要数据有可找回的副本；聊天记录不能成为唯一依据。

## 每次接手的入口

仓库根目录为 `D:\Project\4.Project\Agent2`。按根目录 `AGENTS.md` 的开工顺序阅读；部署会话同时读取本文、`PROGRESS.md` 当前部署段和本次涉及的部署手册章节。

- 项目总纪律：根目录 `AGENTS.md`。
- 阅读与调试纪律：`docs/agents/implement-context-hygiene.md`；上下文阈值以 `AGENTS.md` 为准。
- 当前状态：根目录 `PROGRESS.md`。
- 实际部署资料与备份清单：`docs/deployment-record-2026-10-21.md`；详细事实保存在此，`PROGRESS.md` 仅留短进度和入口。
- 操作主线：`docs/deploy-ubuntu-production.md`。
- 凭据用途、字段、生成命令及找回入口：`docs/deployment-credentials-guide.md`。
- 历史实现与验收依据：当前任务引用的 `.scratch/v1.42/issues/` 工单及 `docs/verification/` 文件。

完成标准：能说明当前操作要解决什么、前置条件是否成立、哪些状态仍待用户反馈。历史文档中的地域、版本或进度与实际主机冲突时，先核实并更新活动记录。

## 面向用户解释后再操作

每次只给一小组可直接执行的命令。执行前说明：

1. 为什么现在要做，对上线有什么作用。
2. 在哪里执行：Windows 本地 PowerShell、服务器 SSH 终端，还是 MySQL 提示符中。
3. 会创建或修改哪些文件、账号、权限或数据；随机值是否生成、保存到哪里。
4. 预期看到什么、如何判断成功；无输出只能表明未见明显错误，需要时补针对性核对。
5. 如何找回、备份或撤销；需要用户自行填写的部分逐项说明。

用户反馈“不理解”或质疑流程时，先解释并修正流程。用户不懂技术不等于不愿意执行细致步骤。只有需要用户选择或提供缺失信息时提问；已经授权的可逆准备工作继续完成。

## 重要数据的记录与备份

### 记录什么

项目文档记录非敏感事实：账号名及用途、主机和目录、实际版本、部署提交、执行步骤、结果、备份位置/时间/校验方式、尚未完成的验收。真实密码、API key、登录密钥、私钥及备份解密密钥保存在用户控制的受限配置、密码管理器或加密副本中，不写 Git、普通日志或聊天。

每项新凭据生成前确定用途、持久保存位置、服务器之外的副本位置，以及丢失/轮换影响。生成后核对字段已填写和权限正确，只回报状态，不要求用户粘贴真实值。随机生成可写入文件且不显示内容；仍须提供私下读取和找回方法。

### 什么时候备份

- 首次生成运行凭据后，先完成服务器之外的安全副本并确认可读取，再初始化数据库。维护凭据填写后同步保存独立副本。
- 数据库初始化后，完成包含数据库、运行配置和对应源码的完整加密备份、实际下载及隔离恢复验收。
- 更新、迁移、凭据轮换或其他重要配置变更前保存当前可用版本，变更后刷新副本和非敏感记录。
- 备份解密密钥在首次生成后独立保存到服务器之外；包和解密密钥不只有同一处副本。

### 怎样算完成

| 状态 | 所需证据 |
|---|---|
| 已记录 | 项目文档有文件/账号用途、位置、操作和结果；真实值有明确的安全保存位置 |
| 服务器已保存 | 已核对实际文件和受限权限；模板占位值不算真实配置 |
| 已有异地副本 | 用户电脑/独立位置实际存在安全副本，有时间与路径记录；服务器另一目录不算异地 |
| 副本可读取 | 用户用独立保管的凭据实际打开或解密成功，核对关键配置存在 |
| 完整恢复通过 | 在隔离库/实例实际恢复并验证登录、项目及关键正文；仅校验文件哈希不够 |

当前备份工具的包含项与排除项以 `scripts/production-backup.ts` 和凭据说明为准。尤其核对维护凭据、数据库系统账号、SSH 私钥和解密密钥是否另行保存；不要假设所有内容自动入包。密码彻底丢失时重新生成属于重设，不属于恢复原值。

## 保护现有数据与部署版本

先确认现状再重跑命令。已经填写的配置不重新安装模板，已经存在的凭据不重复随机生成。数据库初始化、清库、覆盖、恢复或切换前确认具体目标和备份；恢复演练使用隔离新库。

代码用已提交版本部署，核对真实 Git 提交与发行目录；目录名不等于提交证明。保护用户既有未提交内容，按本次范围暂存和提交。用户旧的推送许可按其授权范围适用；新提交推送前遵守根目录纪律。

版本、供应商或工具方案以成功上线为目标调整，依据实际证据评估。用户提到某个版本作举例，不视为指定；旧手册可修订，不是不可变要求。修改 Next.js 代码前读本仓库安装版本的相关指南；按 `AGENTS.md` 风险等级选验证。

## 验证与交接

按“已给出步骤 → 用户确认执行 → 结果已核验 → 恢复已验证”记录，证据到哪一步就写到哪一步。本机构建、replay、模拟测试与目标机真实验证分别标注。上线完成以正式部署手册的目标机发布闸为准。

每次阶段结束更新 `PROGRESS.md`；操作说明与持久纪律入项目文档，按范围提交。交接文档按 handoff 技能保存到 Windows 临时目录，引用项目文件而不复制整份手册，说明背景、已做事项和原因、证据边界、当前暂停点及首个下一步。交接时明确本地提交、远端和服务器的版本差异。
