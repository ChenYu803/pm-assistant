# v1.41 Implement Agent 原型输入契约

本文件只属于 v1.41。它规定 v1.41 实现票涉及产品经理原型时的开工纪律；v1.41 最终验收票完成后应删除本文件，并从 `AGENTS.md` 的开工路径移除对它的读取要求。

## 开工前必须检查

1. 读取当前 ticket 的“产品经理在 Agent 开始前提供”。
2. 打开该节列出的每一个原型、复用来源、固定文案和素材。
3. 对照产品经理的原型交付清单，确认主流程、关键状态、特殊行为和复用关系都能找到。
4. 确认原型与 spec 没有对同一行为给出互相冲突的决定。
5. 只有以上检查通过，且 ticket 的 Status 为 ready-for-agent，才开始写代码。

## 缺口处理

- 缺少关键主流程、核心视觉区域、固定文案或特殊行为时，停止实现，不用“合理默认”替产品经理做决定。
- 在 ticket 的 Status 保持或改为 needs-info，并写出具体缺口：缺哪张界面、哪条路径、哪个状态或哪项取舍。
- 不因为普通加载、网络失败、禁用、无特殊要求的移动端适配缺失而阻塞；这些由 Agent 按已确认的主界面补齐。
- 不要求产品经理提供数据库、API、React 组件、system prompt、事务、测试脚本或像素级异常状态。

## 实现时的边界

- 原型决定视觉层级、布局、控件形态、响应式表现和动效；spec 决定行为、权限和数据事实。
- 原型与 spec 冲突时，报告冲突并等待产品经理选择；不得自行改写行为。
- 实现完成后，验收必须同时证明：票据行为已实现、产品经理原型已接入、未擅自增加未确认的产品行为。

ready-for-agent 表示“产品输入已经可访问且经过检查”，不是“Agent 可以边做边猜”。
