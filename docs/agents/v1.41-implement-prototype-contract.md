# v1.41 Implement Agent 产品输入与原型纪律

本文件只属于 v1.41。它规定 Implement Agent 如何判断一张票是否需要产品经理先交付独立原型。v1.41 最终验收票完成后应删除本文件，并从 AGENTS.md 的开工路径移除对它的读取要求。

## 默认路径：正式代码直接实现

1. 读取当前 ticket 的“产品经理在 Agent 开始前提供”。
2. 按该节声明的实施模式开工：正式代码直接实现、复用已落地界面、独立原型前置或验收票。
3. 除非 ticket 明确写“独立原型前置”，否则缺少 open-design、HTML、线框图或截图不是阻塞条件，也不得把 Status 改为 needs-info。
4. 正式代码直接实现时，以当前 ticket、spec、已经落地的正式界面和项目现有视觉语言为事实来源；正式页面就是产品经理第一次验收的可交互版本。
5. 复用已落地界面时，先打开 ticket 指定的正式功能，沿用其布局、组件、状态反馈和文案层级，只实现本票新增差异。
6. 验收票不等待产品经理另行准备原型、测试数据、脚本或技术方案；Agent 根据票据验收标准构造可重复数据并执行验证。

## 何时等待产品经理

- 只有 ticket 明确标为“独立原型前置”，且列出的原型或素材不可访问时，才停止实现并记录具体缺口。
- ticket 与 spec 对同一产品行为互相冲突，或缺少一个会导致不同用户结果的产品决定时，只询问这一项决定。
- 常规布局、组件选型、加载/失败状态、响应式适配、测试数据、数据库、API、prompt、事务和验证脚本由 Agent 结合现有实现完成，不转交产品经理。
- Agent 不得因为自己更偏好先画原型，就新增原型前置条件。实施模式只能由 ticket 或产品经理改变。

## 实现与验收

- spec 和 ticket 决定行为、权限和数据事实；已落地正式界面决定可复用的视觉语言。
- ticket 提供独立原型时，原型决定其中明确表达的布局、层级、控件和交互取舍；未表达的部分仍按正式产品现状补齐。
- 正式代码直接实现后，产品经理可以在真实页面提出视觉和交互修改；这属于本票正常验收，不代表开工前必须补画独立原型。
- 完成标准是票据行为可用、验收标准通过、视觉与正式产品一致；不能用“没有独立原型”解释未完成或随意实现。

ready-for-agent 表示产品决策足以开始实现。它不表示产品经理已承诺先制作独立原型。
