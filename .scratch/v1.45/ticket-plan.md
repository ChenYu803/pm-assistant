## 拆分原则与协作方式

- 每张票交付一个可演示、可单独验证的用户行为，包含所需的页面、接口、持久状态与验证；不按前端、后端、数据库拆成互相等待的水平任务。
- 下文“主责故事”对应 spec 第 3 节编号，“行为验收”对应 T01–T20。跨票规则随各自功能落地，不集中留到最终人工验收。
- 所有票开工前均无新增前置产品材料要求。需要协作时，Agent 先做出可审阅的页面、提示词草稿或样例，再邀请用户参与；不得让用户先设计接口、数据结构或测试。
- 正式票逐票保留“产品经理在 Agent 开始前提供”和“需要用户协作的环节”。纯技术工作明确写“无新增产品输入”，由 Agent 自主实现与验证。
- 用户协作确认限于产品表达和实际体验；共享代码、接口、迁移、调用格式、计费、权限及验证由 Agent 负责。用户尚未确认的页面或提示词，不得以技术检查通过代替协作完成。
- 风险为预估，实施时先复核。L2 使用已有公开 HTTP／浏览器、隔离 MySQL 与本地模型替身；首个需要 v1.45 回放的功能票完成必要的运行器版本登记并验证，后续复用，不新造一套框架或人为增加所有功能的前置依赖。
- 确定性检查与必要的用户协作验收归各票负责。真实模型样例须说明假设、预计时长和调用范围，超过 10 分钟按仓库规则先取得用户同意。本次发布不表示已运行这些场景。
- 不另设一张包揽全版问题的人工验收票；部署、push 与生产执行不因本次拆票自动发生。

## 01：工作台合栏、滚轮与输入区可见性

**What to build:** 合并项目信息和四环导航，用户进入桌面工作台后即可操作完整输入框与发送按钮，并用滚轮阅读长对话。

**Blocked by:** 无（可直接开始）。

**风险预估：** L1。**主责故事：** 43–45、64–65。**行为验收：** T16 的布局与滚动。

**产品经理在 Agent 开始前提供：** 无新增前置输入；现有 spec 足够开始。

**需要用户协作的环节：** Agent 先提供实际可操作页面，用户反馈并确认合栏后的层级、密度和操作感；不在开工前要求用户画布局。

**拟定验收条件：**

- 项目、积分、返回入口与四环导航合并组织，减少顶部占高，保留必要信息和自由导航入口。
- 在 1440 × 900、1366 × 768 下完整输入框和发送按钮稳定可见；长回复、侧边栏开关时可操作。
- 对话区可独立滚动，鼠标滚轮有效；窄屏不丢失关键入口，基础键盘操作和焦点可用。
- 与现有消息和后续题卡采用一致的高度、溢出约束，不靠每增加一块内容就推长整个页面。
- 完成适用编译、浏览器检查与用户实际页面反馈记录；后续题卡组合状态在 14 复核。

## 02：AI 回复气泡与原文复制反馈

**What to build:** 用户能清楚区分 AI 和自己的消息、舒适阅读长文，并复制该条 AI 回复的原始内容，得到约定的轻量反馈。

**Blocked by:** 无（可直接开始）。

**风险预估：** L1。**主责故事：** 41、51–54、64–65。**行为验收：** T16 的气泡、T17。

**产品经理在 Agent 开始前提供：** 无新增前置输入。

**需要用户协作的环节：** Agent 提供短文、长文、流式及失败后保留文字的实际页面，用户确认阅读宽度和视觉区分。

**拟定验收条件：**

- AI 说明、自由回复和成果正文有清晰容器；与用户消息区分，长正文不铺满整个工作台。
- 复制逐字符采用保留的模型输出原文，包括 Markdown 与原有标记；不复制净化展示内容或渲染后的纯文本。
- 成功只有该条按钮图标暂变 √，随后恢复；按钮附近无成功文案，顶部无成功提示。
- 失败在页面顶部显示 Toast，两秒消失；不同消息的按钮状态不互相干扰。
- 停止或失败后已经展示的文字仍可阅读复制；浏览器证据覆盖原文一致性及成功、失败反馈。

## 03：后三环新会话注入提醒与真实上下文

**What to build:** 用户可直接进入任意阶段，后三环每个新会话在开始前明确提醒注入所需 Markdown，并让侧边栏选择准确控制模型可读取的文件正文。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 2、46–50、64–65。**行为验收：** T14、T15，相关 T12。

**产品经理在 Agent 开始前提供：** 无新增前置输入。

**需要用户协作的环节：** Agent 先做出提醒、开始按钮与侧边栏联动页面，用户反馈醒目程度和文案；不要求用户设计判定逻辑。

**拟定验收条件：**

- 移除按阶段状态、文件名或数量猜测“已有确认成果”的旧提示逻辑，不使用已作废的悬浮 Alert。
- 原型、PRD、任务拆分每个新会话开始前都有醒目提醒，解释不注入可能缺少前序需求、范围和约束。
- 有无文件均可点击“开始对话”；该动作不调用模型，已开始状态持久保存，刷新与切回不重复提醒。
- 加载与移除文件准确反映在后续真实模型请求中，不自动读取前序成果、全项目正文或别的会话文件；曾经出现的信息仍属对话历史。
- 通过隔离浏览器／HTTP 与供应商替身核对新会话、重开、刷新、越权及实际注入；必要的运行器版本扩展一并验证，不调用真实邮件。

## 06：邀请码完整码长期管理与批量作废

**What to build:** 管理员无需填写原因即可管理邀请码，长期查看复制完整码，并从清晰列表批量作废未领取码。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 56–60、64–65。**行为验收：** T18。

**产品经理在 Agent 开始前提供：** 无新增前置输入。

**需要用户协作的环节：** Agent 先提供真实可操作的管理页，用户确认列表、选择、批量操作和复制体验。

**拟定验收条件：**

- 创建、单个及批量作废均不要求原因，接口不强制原因；保留管理员身份校验和动作、操作者、时间记录。
- 新码持久保存完整值，管理员刷新或重登仍可查看复制；取消遮挡、仅本次显示和独立临时生成模块。
- 列表直接显示邀请码本身，领取账号与领取时间分列，保留必要状态和管理动作。
- 批量只作废未领取码，已领取记录和已到账积分保持；与领取并发时结果一致，不误伤权益。
- 普通账号不能通过页面或接口读取完整管理列表或执行管理操作；隔离验证覆盖持久查看、复制、权限及批量状态。
- 历史摘要不声称能还原完整码；旧码与 100 个新码的实际接续由 07 负责。

## 08：共写三阶段提示词并打通首轮题卡

**What to build:** 用户自由描述想法后，需求分析 LLM 基于三阶段方法生成首轮问题，并以逐题题卡呈现；具体 system prompt 由用户与 Agent 共同撰写敲定。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 1–8、22–24、42、50、63、65。**行为验收：** T01 的首轮、T05 的结构错误、相关 T06／T12／T15。

**产品经理在 Agent 开始前提供：** 无须先交完整提示词；已确认三阶段和提问原则足够开工。

**需要用户协作的环节：** Agent 先提供完整提示词草稿、相对旧规则的差异和代表性访谈／成果样例；用户参与措辞、提问方式和内容判断，最终共同敲定并留记录。

**拟定验收条件：**

- 保留“需求挖掘 → 需求取舍 → 实现方案”及其交付物内容，借鉴 grilling 的依赖、分轮和反馈调整，不取消三阶段。
- 提示词涵盖首次必开问、LLM 自主改题及推进、自检冗长和重复、信息充分和阶段结束信号、充分时总结建议输出；无固定题数、轮数及独立阶段确认。
- 打通自由开场、模型返回、轮次持久化、首轮题卡显示的完整路径，使用迭代目标和实际授权文件。
- 模型一次规划整轮，逐题显示单选及最后自由填写选项；切题不逐题调用模型，题卡不能自动授权写正式成果。
- 采用与现有供应商兼容的返回契约；完整结构校验通过才呈现，无效或截断结果不覆盖已有内容，不自动多轮修复或增加后台规划调用。
- 复用现有调用、停止、幂等与计量；隔离证据证明首轮和失败恢复，保留可继续由 09 接入的稳定问题身份。
- 提示词协作记录完成后再视为本票完成；完整补充、历史反馈和中途输出的真实效果在 14 进一步收敛。

## 09：题卡作答、一次提交与历史回看

**What to build:** 用户可逐题作答、修改草稿、提交部分或全部答案，并按轮回看；任何未提交历史轮仍能提交，已提交轮保持原快照。

**Blocked by:** 08「共写三阶段提示词并打通首轮题卡」。

**风险预估：** L2。**主责故事：** 9–11、15–18、20–21、42、65。**行为验收：** T01 的作答、T02、T04、相关 T03／T05／T06／T12。

**产品经理在 Agent 开始前提供：** 无新增产品输入。

**需要用户协作的环节：** 无新增产品决策要求；Agent 实现可运行交互，题卡最终视觉在 14 与用户共同收敛。

**拟定验收条件：**

- 上一题、下一题保留选择和自由填写；草稿、当前位置及问答关系在刷新与切回同会话后恢复，不额外请求模型。
- 可提交部分或全部答案；未答保持未答，每轮只提交一次，重复点击和网络重试不重复调用或扣分。
- 提交时带完整问题、选项、答案、未答与来源身份，模型继续规划下一轮；不把孤立字母或“是”当作全部上下文。
- 所有轮保留，可按轮回看；浏览位置不改变上下文，不混入其他会话问答。
- 未提交历史轮始终能修改并提交，已提交轮包括部分提交均不能补答后重交，原快照持续可查。
- 编辑、重生成、失败和重试不抹掉已提交轮或历史关联；无效新题卡保留已有题目和答案。
- 隔离证据覆盖部分提交、重放、刷新、会话隔离与历史状态；补充形成的新旧轮顺序组合在 10 验证。

## 10：补充打断、草稿关联与历史轮反馈

**Blocked by:** 09「题卡作答、一次提交与历史回看」。

**风险预估：** L2。**主责故事：** 12–14、17、19–21、42、65。**行为验收：** T03、T06，相关 T04／T05／T12。

**拟定验收条件：**

## 11：原型与 PRD 显式输出、会话成果与一版回退

**What to build:** 原型与 PRD 用户通过醒目输出按钮一次生成并保存自己的 Markdown 成果，同会话更新、跨会话新建，并可回退紧邻上一版。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 28–31、33–36、38、40–42、64–65。**行为验收：** 对应阶段的 T07、T09–T13，相关 T15。

**产品经理在 Agent 开始前提供：** 无新增前置输入。

**需要用户协作的环节：** Agent 提供可运行的输出与完成按钮、生成状态及错误状态，用户确认可见性和文案；协议与存储由 Agent 决定。

**拟定验收条件：**

- 输出位于“完成本阶段”左侧，两者醒目；服务端明确区分聊天与输出，只有显式输出动作能授权本票阶段正式成果的生成保存。
- 本票阶段所有历史候选、确认接口及旧兼容入口不能绕过授权；普通聊天的写入措辞和自发文件标记不保存正式成果，历史文字可看可复制。
- 新会话首次输出新建成果，即使注入旧文件；首次按“阶段名-主题.md”命名、撞名加序号，后续以稳定成果身份更新自己的文件并保持名称。
- 完整正常生成且保存成功才原子更新正文和唯一上一版；停止、故障、截断、保存失败都不改已有正文及备份，已展示文字保留；可结算不等于可保存。
- A → B → C 只可 C → B，消耗备份后不能再回 A 或重做 C；用户手工改过的实际当前正文成为被替换备份，既有编辑改名删除权限保留。
- 输出不完成或跳阶段，完成不调用模型、不生成文件；原型对话 HTML 预览继续可用，不变成正式 Markdown 交付物的替代。
- 幂等、重试、并发、停止、断线、用量和项目归属沿用现有机制；保存来源可追溯，删除会话不删除已保存资产与备份。
- 以公开入口和隔离替身覆盖成功、失败、回退及权限；共享输出调用与普通 Markdown 成果机制供 12、13 复用。

## 12：需求分析中途输出与生成前确认

**What to build:** 首轮题卡出现后，用户可随时在模型空闲时确认输出需求分析 Markdown，包含未提交作答，且不影响原题卡继续作答提交。

**Blocked by:** 10「补充打断、草稿关联与历史轮反馈」；11「原型与 PRD 显式输出、会话成果与一版回退」。

**风险预估：** L2。**主责故事：** 25–31、34–36、38、40–42、63–65。**行为验收：** T08，以及需求分析的 T07、T09–T13。

**产品经理在 Agent 开始前提供：** 无新增前置输入。

**需要用户协作的环节：** Agent 准备生成前 pop_confirm 文案、实际入口和带草稿的成果样例，与用户确认提醒和输出体验；提示词修订延续 08 的共同评审方式。

**拟定验收条件：**

- 首轮题卡出现后，模型空闲即可输出；不要求答完整轮、固定题数、阶段信息评分或原有逐项全部确认。
- 生成前提示继续回答能增加分析信息，可取消；取消零调用，确认后携带相关草稿和未答状态一次生成，不先额外提交或再调用一次整理草稿。
- 输出不把未提交题卡变成已提交，不清空草稿、不废弃历史；原未提交轮仍可作答提交。
- 需求分析的旧候选、历史确认入口和普通聊天不能保存正式成果；聊天写入措辞不改变本次授权模式。
- 按三阶段分析和已有信息组织正式成果，不强制逐项未知标签；输出不自动完成或跳阶段。
- 复用 11 的会话归属、命名、完整成功提交、幂等及一版回退，对需求分析补充验证停止、失败、截断与保存故障不改正式成果和备份。
- 保存与来源结果、实际调用数和计费有隔离证据；成果意图理解及内容质量在 14 以实际样例评审，不以按钮可用代替语义通过。

**拟定验收条件：**

- 输出入口清楚表示“整套任务文件”；同迭代 A、B 会话首次各新建一套，后续只更新各自那套，注入他人旧文件不取得覆盖权。
