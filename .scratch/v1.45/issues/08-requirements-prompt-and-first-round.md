# 08: 共写三阶段提示词并打通首轮题卡

**Type:** task

**Status:** ready-for-agent

**What to build:** 用户自由描述想法后，需求分析 LLM 基于三阶段方法生成首轮问题，并以逐题题卡呈现；具体 system prompt 由用户与 Agent 共同撰写敲定。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 1–8、22–24、42、50、63、65。**行为验收：** T01 的首轮、T05 的结构错误、相关 T06／T12／T15。

## 产品经理在 Agent 开始前提供

无须先交完整提示词；已确认三阶段和提问原则足够开工。

## 需要用户协作的环节

Agent 先提供完整提示词草稿、相对旧规则的差异和代表性访谈／成果样例；用户参与措辞、提问方式和内容判断，最终共同敲定并留记录。

## 验收条件

- [ ] 保留“需求挖掘 → 需求取舍 → 实现方案”及其交付物内容，借鉴 grilling 的依赖、分轮和反馈调整，不取消三阶段。
- [ ] 提示词涵盖首次必开问、LLM 自主改题及推进、自检冗长和重复、信息充分和阶段结束信号、充分时总结建议输出；无固定题数、轮数及独立阶段确认。
- [ ] 打通自由开场、模型返回、轮次持久化、首轮题卡显示的完整路径，使用迭代目标和实际授权文件。
- [ ] 模型一次规划整轮，逐题显示单选及最后自由填写选项；切题不逐题调用模型，题卡不能自动授权写正式成果。
- [ ] 采用与现有供应商兼容的返回契约；完整结构校验通过才呈现，无效或截断结果不覆盖已有内容，不自动多轮修复或增加后台规划调用。
- [ ] 复用现有调用、停止、幂等与计量；隔离证据证明首轮和失败恢复，保留可继续由 09 接入的稳定问题身份。
- [ ] 提示词协作记录完成后再视为本票完成；完整补充、历史反馈和中途输出的真实效果在 14 进一步收敛。
