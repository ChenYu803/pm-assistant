# 04: 个人中心视觉重做

**Type:** task

**Status:** ready-for-agent

**What to build:** 用户在清晰、易操作的个人中心管理账号与积分相关信息，由用户与 Agent 在实际页面中敲定视觉。

**Blocked by:** 无（可直接开始）。

**风险预估：** L1；若实际触及数据行为另行复核。**主责故事：** 55、64–65。

## 产品经理在 Agent 开始前提供

无新增前置素材或视觉方案。

## 需要用户协作的环节

Agent 先完成页面初稿，用户依据实际页面反馈层级、布局、密度、响应式和交互，再迭代确认。

## 验收条件

- [ ] 个人中心与邀请码管理保留为两个页面，共享现有视觉系统，账号和积分信息有清晰层级。
- [ ] 现有适用的查看及管理行为可继续完成，空状态、错误状态和加载状态可辨认。
- [ ] 桌面与窄屏可用，表单焦点和按钮名称可辨识；不得把实现细节塞进用户流程。
- [ ] 留下实际页面、用户反馈、迭代结果和协作确认；视觉完成不由静态脚本代判。

## 规格依据

[v1.45 spec](../spec.md) 第 4.8–4.9、5.3–5.4 节；用户故事与行为验收映射见本票顶部。

本票来自用户已确认的 [14 票拆分记录](../ticket-plan.md)；执行顺序见 [v1.45 任务入口](../map.md)。

## 实施与验证要求

- 开工前复核风险分级，按仓库规定完成适用编译和本票相关检查。L1 先报备所需脚本；L2 完整运行相关验证并按改动触点回归相邻范围，不用全量重复验证代替有目的的检查。
- 验证题卡、权限、文件、计量或数据接续时，优先复用公开 HTTP／浏览器、隔离 MySQL 与本地模型替身；首个需要 v1.45 回放的功能票负责必要的运行器版本登记，后续复用，不另建测试框架。
- 真实模型样例先说明假设、预计时长和调用范围；预计超过 10 分钟先按仓库规则取得用户同意。不因本票自动发送真实邮件、执行生产迁移、部署或 push。
- 验收条件当前均待实现验证。完成时在本票记录实际行为证据、检查结果、必要的用户反馈与协作确认及已知限制，再推进任务入口和 PROGRESS；不转交给一张覆盖全版的最终人工验收票。
