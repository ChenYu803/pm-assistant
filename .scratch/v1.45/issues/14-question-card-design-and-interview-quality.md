# 14: 题卡视觉协作与完整访谈效果收敛

**Type:** task

**Status:** ready-for-agent

**What to build:** 用户在合栏后的工作台内，以有组织、可追溯的题卡完成需求分析，并通过真实访谈及成果样例与 Agent 共同收敛交互和提示词效果。

**Blocked by:** 01「工作台合栏、滚轮与输入区可见性」（[票据](01-workbench-layout-and-scroll.md)）；12「需求分析中途输出与生成前确认」（[票据](12-requirements-output-and-confirmation.md)）。

**风险预估：** 视觉通常为 L1；若修改协议或共享行为，按 L2 验证相关范围。**主责故事：** 6–24、25–27、63–65，重点为 64。**行为验收：** T01–T06、T08、T16 的题卡组合，以及 spec 5.3 的提示词／视觉协作。

## 产品经理在 Agent 开始前提供

无新增前置原型或提示词全文要求；Agent 先准备完整可交互页面和样例。

## 需要用户协作的环节

用户在实际页面评审轮次选择、题卡与输入框展开方式、信息层级、动效和结果质量；对提示词必要修订共同敲定并记录。

## 验收条件

- [ ] 题卡和补充输入框有清楚入口，轮次选择可发现；历史轮持续可查，当前查看轮和可提交状态可区分。
- [ ] 覆盖长题干、长选项、自由填写、部分提交、未提交历史轮、已提交只读、生成中、失败恢复及输出前确认，不能只给静态理想页。
- [ ] 在 1440 × 900、1366 × 768 及窄屏检查布局、滚轮、输入／发送、侧边栏和键盘焦点，题卡不把工作台重新推成超长页面。
- [ ] 真实模型短程样例覆盖首次必开问、范围中途变化、历史轮反馈、信息充分收尾、携带部分草稿输出；按现有成本纪律先说明假设、时长和调用范围，不自动长程试错。
- [ ] 独立记录内容质量：意图是否理解、是否重复追问、是否忽略用户要求、明确要求的长文本是否完整；不得把题卡显示或按钮写入成功当作原有短文与跑题问题已修复。
- [ ] 不为改善体验新增固定题数、多选、充分性打分、服务器语义裁判或自动写文件；不足之处通过提示词协作和具体页面改进解决。
- [ ] 用户反馈、修改结果和最终协作确认留痕；各技术票自身验收仍各自负责，本票不承接账号、邀请码或全版剩余 bug。
