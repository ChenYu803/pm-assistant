# 03: 后三环新会话注入提醒与真实上下文

**Type:** task

**Status:** ready-for-agent

**What to build:** 用户可直接进入任意阶段，后三环每个新会话在开始前明确提醒注入所需 Markdown，并让侧边栏选择准确控制模型可读取的文件正文。

**Blocked by:** 无（可直接开始）。

**风险预估：** L2。**主责故事：** 2、46–50、64–65。**行为验收：** T14、T15，相关 T12。

## 产品经理在 Agent 开始前提供

无新增前置输入。

## 需要用户协作的环节

Agent 先做出提醒、开始按钮与侧边栏联动页面，用户反馈醒目程度和文案；不要求用户设计判定逻辑。

## 验收条件

- [ ] 移除按阶段状态、文件名或数量猜测“已有确认成果”的旧提示逻辑，不使用已作废的悬浮 Alert。
- [ ] 原型、PRD、任务拆分每个新会话开始前都有醒目提醒，解释不注入可能缺少前序需求、范围和约束。
- [ ] 有无文件均可点击“开始对话”；该动作不调用模型，已开始状态持久保存，刷新与切回不重复提醒。
- [ ] 加载与移除文件准确反映在后续真实模型请求中，不自动读取前序成果、全项目正文或别的会话文件；曾经出现的信息仍属对话历史。
- [ ] 通过隔离浏览器／HTTP 与供应商替身核对新会话、重开、刷新、越权及实际注入；必要的运行器版本扩展一并验证，不调用真实邮件。

## 规格依据

[v1.45 spec](../spec.md) 第 4.1、4.4、4.7、4.9、5.2（T12、T14–T15） 节；用户故事与行为验收映射见本票顶部。

本票来自用户已确认的 [14 票拆分记录](../ticket-plan.md)；执行顺序见 [v1.45 任务入口](../map.md)。

## 实施与验证要求

- 开工前复核风险分级，按仓库规定完成适用编译和本票相关检查。L1 先报备所需脚本；L2 完整运行相关验证并按改动触点回归相邻范围，不用全量重复验证代替有目的的检查。
- 验证题卡、权限、文件、计量或数据接续时，优先复用公开 HTTP／浏览器、隔离 MySQL 与本地模型替身；首个需要 v1.45 回放的功能票负责必要的运行器版本登记，后续复用，不另建测试框架。
- 真实模型样例先说明假设、预计时长和调用范围；预计超过 10 分钟先按仓库规则取得用户同意。不因本票自动发送真实邮件、执行生产迁移、部署或 push。
- 验收条件当前均待实现验证。完成时在本票记录实际行为证据、检查结果、必要的用户反馈与协作确认及已知限制，再推进任务入口和 PROGRESS；不转交给一张覆盖全版的最终人工验收票。
