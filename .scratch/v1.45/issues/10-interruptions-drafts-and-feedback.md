# 10: 补充打断、草稿关联与历史轮反馈

**Type:** task

**Status:** ready-for-agent

**What to build:** 用户答题中途可补充或提问、让 LLM 自主调整问题，之后仍能回旧轮提交；已提交答案通过补充更正，模型理解原决定与后续反馈的关系。

**Blocked by:** 09「题卡作答、一次提交与历史回看」（[票据](09-question-round-submission-and-history.md)）。

**风险预估：** L2。**主责故事：** 12–14、17、19–21、42、65。**行为验收：** T03、T06，相关 T04／T05／T12。

无新增产品输入。

## 验收条件

- [ ] 同会话输入框承担补充、提问和其他输入；发送时带相关未提交草稿并标明身份，不暗中提交题卡或填完某题。
- [ ] LLM 先处理补充，再自主沿用、调整、收回或重组问题；服务端只校验结构与关联，不判断反馈是否改变前提。
- [ ] 新轮出现不取消旧未提交轮的提交资格；历史轮提交带来源和后续补充顺序，不冒充新轮答案。
- [ ] 更正已提交答案走补充入口，保留原快照、原始表达与时间顺序，服务端不拼造所谓最终事实。
- [ ] 切题、编辑和回看仍零额外调用，发送补充与明确继续澄清按实际用量计费；重复请求幂等且受会话并发控制。
- [ ] 隔离供应商捕获请求证明问题、草稿、部分提交、后续补充和实际授权文件关联准确，结构失败可恢复。
