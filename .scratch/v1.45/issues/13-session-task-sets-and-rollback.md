# 13: 任务拆分按会话输出整套文件并回退

**Type:** task

**Status:** ready-for-agent

**What to build:** 不同任务拆分会话各自产出并更新自己的整套任务文件，可独立整套回退，新旧文件不会混杂。

**Blocked by:** 11「原型与 PRD 显式输出、会话成果与一版回退」（[票据](11-explicit-markdown-output-and-rollback.md)）。

**风险预估：** L2。**主责故事：** 28–32、34–35、37–42、65。**行为验收：** 任务拆分的 T07、T09–T13。

## 产品经理在 Agent 开始前提供

无新增产品输入；文件集归属遵循已确认的 ADR-0009。

## 需要用户协作的环节

无新增产品或技术设计要求；入口沿用已协作的输出／完成按钮，Agent 负责文件集协议、旧数据接续和验证。

## 验收条件

- [ ] 输出入口清楚表示“整套任务文件”；同迭代 A、B 会话首次各新建一套，后续只更新各自那套，注入他人旧文件不取得覆盖权。
- [ ] 沿用显式输出调用与计量；普通聊天、旧任务候选、手动提案及历史确认接口不能绕过唯一输出授权，并复核四环遗留写入口无遗漏。
- [ ] 文件集整套结构有效、完整生成并保存成功才原子提交；失败、截断、停止或保存故障无部分落地，不改原套和备份。
- [ ] 各套独立整套回退一版，A → B → C 仅回 B，消耗备份且无重做；手工操作后的实际被替换内容正确保留。
- [ ] 文件树、整套下载、来源记录、会话删除与项目权限识别正确文件集，不再假设每迭代只有一套；输出与完成独立。
- [ ] 旧过程／任务数据按低成本清理或过渡，不推测历史唯一归属，不做复杂无损兼容，不扩大清理账号、积分、权限和已领取权益。
- [ ] 隔离证据覆盖双会话并存、独立更新回退、并发重试、故障一致性和共享计量；生产数据接续随发布按部署纪律执行，不能用演练冒充生产结果。
