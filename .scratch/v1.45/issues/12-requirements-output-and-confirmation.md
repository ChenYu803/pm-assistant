# 12: 需求分析中途输出与生成前确认

**Type:** task

**Status:** ready-for-agent

**What to build:** 首轮题卡出现后，用户可随时在模型空闲时确认输出需求分析 Markdown，包含未提交作答，且不影响原题卡继续作答提交。

**Blocked by:** 10「补充打断、草稿关联与历史轮反馈」（[票据](10-interruptions-drafts-and-feedback.md)）；11「原型与 PRD 显式输出、会话成果与一版回退」（[票据](11-explicit-markdown-output-and-rollback.md)）。

**风险预估：** L2。**主责故事：** 25–31、34–36、38、40–42、63–65。**行为验收：** T08，以及需求分析的 T07、T09–T13。

## 产品经理在 Agent 开始前提供

无新增前置输入。

## 需要用户协作的环节

Agent 准备生成前 pop_confirm 文案、实际入口和带草稿的成果样例，与用户确认提醒和输出体验；提示词修订延续 08 的共同评审方式。

## 验收条件

- [ ] 首轮题卡出现后，模型空闲即可输出；不要求答完整轮、固定题数、阶段信息评分或原有逐项全部确认。
- [ ] 生成前提示继续回答能增加分析信息，可取消；取消零调用，确认后携带相关草稿和未答状态一次生成，不先额外提交或再调用一次整理草稿。
- [ ] 输出不把未提交题卡变成已提交，不清空草稿、不废弃历史；原未提交轮仍可作答提交。
- [ ] 需求分析的旧候选、历史确认入口和普通聊天不能保存正式成果；聊天写入措辞不改变本次授权模式。
- [ ] 按三阶段分析和已有信息组织正式成果，不强制逐项未知标签；输出不自动完成或跳阶段。
- [ ] 复用 11 的会话归属、命名、完整成功提交、幂等及一版回退，对需求分析补充验证停止、失败、截断与保存故障不改正式成果和备份。
- [ ] 保存与来源结果、实际调用数和计费有隔离证据；成果意图理解及内容质量在 14 以实际样例评审，不以按钮可用代替语义通过。
