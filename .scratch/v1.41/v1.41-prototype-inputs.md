# v1.41 产品输入与实施模式清单

本文件给产品经理和 Implement Agent 共同使用。文件名保留 prototype-inputs，是为了不破坏 v1.41 已有引用；从 03 号票开始，它不再要求产品经理逐票制作独立原型。

## v1.41 工作纪律

正式代码是默认的首个可交互版本。产品经理直接验收真实页面并提出修改，避免先验收 HTML 原型、再验收正式实现所产生的重复成本。

每张票只采用以下一种实施模式：

- 独立原型前置：只有 ticket 明确指定时使用。原型缺失会阻塞开工。
- 正式代码直接实现：Agent 根据 ticket、spec 和已落地界面直接实现，产品经理在正式页面验收。
- 复用已落地界面：Agent 先查看指定的正式功能，只实现差异，不等待新原型。
- 验收票：Agent 自行准备可重复的验收数据和脚本，不要求产品经理提供原型或技术材料。

缺少独立原型只会阻塞第一种模式。其余模式不得因此保持 needs-info。若实现中出现 ticket 与 spec 未决定、且会改变用户结果的产品分歧，Agent 只提出具体问题，不要求产品经理补画整套原型。

## 已落地例外

- 01 已按独立原型完成并落地，保持原票和实现记录不变。
- 02 已按独立原型完成工作台骨架并落地，保持原票和实现记录不变。
- 03 及之后均以 02 的正式工作台为视觉与交互基线，除非对应 ticket 明确写“独立原型前置”。

## 产品经理如何参与

03 号票之后，产品经理不需要为了让 Agent 开工而预先制作 open-design 或 HTML。Agent 完成正式代码中的第一版后，产品经理直接检查真实页面并提出修改。

如果产品经理主动判断某张未开工 ticket 存在多个高成本方向，需要先探索原型，可以明确把该票改为“独立原型前置”，并在票内写清：

- 要解决的未决问题；
- 原型需要比较或确认的范围；
- 可访问的文件或链接；
- 通过后哪些决定约束正式实现。

没有这些明确记录时，Agent 按表中的模式执行，不自行增加原型流程。
