# 10: PRD 候选与耐久交付

**What to build:** PRD 阶段 Agent 可以根据当前会话和用户加载的文件提出 PRD Markdown 候选。用户审阅后确认创建、确认覆盖或放弃；确认后纯正文进入项目文件树的 PRD 树枝，放弃或失败不改变项目文件。PRD 候选必须满足当前已确认的 PRD 结构要求。

**Blocked by:** 07: 需求分析候选与首次耐久写入

## 产品经理在 Agent 开始前提供

- 实施模式：复用已落地界面。
- 无新增输入。复用 07 已落地的候选预览、创建/覆盖、放弃和失败重试交互，只把内容结构与目标树枝替换为 PRD。

**Status:** resolved

- [x] 未确认的 PRD 候选不会出现在项目文件树、上下文文件目录或修订记录中。
- [x] 候选只能写入 PRD 树枝；确认前可以修改文件名，但不能改到其他树枝。
- [x] 目标路径不存在时标为创建，已存在时标为覆盖；确认区显示路径和操作类型。
- [x] 确认后项目文件树出现纯 Markdown PRD 正文；放弃或失败后文件、备份、修订和变更记录保持原样。
- [x] PRD 候选遵守已确认的六章结构；系统不自动追加 changelog、来源或版本说明。
- [x] 候选确认交互与 07 正式实现一致，只呈现 PRD 六章结构和本票必要差异。
