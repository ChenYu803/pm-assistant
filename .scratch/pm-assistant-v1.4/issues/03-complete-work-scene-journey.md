# 03: 完整工作场景序列与职业认知反馈

**What to build:** 用户从第一个工作场景继续完成一条固定顺序的入职任务，围绕“大学生 AI 学习助手”经历完整的场景化工作过程；每个场景都允许用户判断，并由职场前辈即时反馈，最后到达职业认知测试入口。

**Blocked by:** #02 - 入职任务简报与第一个工作场景

**Status:** resolved

## 本次实现记录

- 已接入 `/onboarding/scenes?scene=2..6`，场景 01 保持 #02 的多选实现，仅沿用其完成后的 `scene=2` 入口。
- 生产只采用 `work-scenes.html` 的 A 变体；B/C 是已舍弃的原型方案，不进入产品。
- 场景 02 至 06 固定包含 10 个四选一判断，选择后展示预编排的正确/错误前辈反馈，并沿唯一顺序继续。
- 场景 02 至 06 的已体验状态、答案和提交状态写入浏览器 `localStorage`；场景 01 继续沿用 #02 的内存状态，不向服务器写入游客用户、项目、工作记录或进度数据。#04 负责统一承接跨页面游客恢复时，不应把场景 01 的现状误认为已持久化。
- 不限制用户手动修改 `scene` 查询参数；正常按钮仍提供顺序推进和已体验场景回看。
- 回看场景 02 至 06 时保留最近一次选择和反馈，并提供“重新作答”；重答仍只更新即时反馈，不改变唯一顺序。
- #04 负责任务地图及游客跨页面恢复的产品化承接，不应重复创建服务器端游客状态，也不应改写本票的固定内容。

- 本次只补齐 #03 已确认原型的交互表现，不新增游客服务器数据，不改变固定题目、顺序或 #04 的任务地图/跨页恢复职责。

## 产品经理在 Agent 开始前提供

- `work-scenes.html`：完整工作场景序列的可点击 HTML 原型，而不是只展示一个场景。
- 工作场景清单及唯一顺序；每个场景的目标、背景、选项、正确答案、正确理由、错误理由和下一步动作。
- 内容覆盖：AI 产品经理定义、日常工作、与传统 PM/算法工程师/AI 工程师区别、AI 提效、发现 AI 价值、人机协作、AI 不可靠性、交付物和 Vibe Coding 成长位置。
- 每个场景的状态说明：未作答、已选答案、正确反馈、错误反馈、返回、下一场景和到达测试入口。
- 一个工作场景是否包含多个判断的明确说明，避免 Agent 自行改变场景数量和流程。

## Agent 负责

- 将所有固定工作场景实现为一条唯一顺序的可运行体验。
- 复用稳定的工作场景界面结构，正确承载背景、选项、前辈反馈和下一步动作。
- 保证错误选择只影响即时反馈，不改变剧情、顺序或后续可访问内容。
- 支持返回已经体验过的场景，并保持用户能继续到测试入口。
- 使用预编排内容，不调用 LLM，不把“大学生 AI 学习助手”扩展成另一个完整产品开发项目。

## Agent 不负责

- 不自行决定工作场景数量、场景顺序、题目和反馈内容。
- 不实现任务地图的完整导航和游客跨页面恢复；这些属于 #04。
- 不实现十题测试和认知文件；这些属于 #05、#06。

- [x] 用户可以从第一个场景连续走到职业认知测试入口。
- [x] 每个工作场景都使用产品经理提供的固定文案和选择。
- [x] 每个判断都有四个选项以及正确/错误的职场前辈反馈。
- [x] 任意错误选择都不会进入另一条剧情或锁死流程。
- [x] 返回和继续行为不会改变唯一场景顺序。
- [x] 全流程不调用 LLM，内容刷新后保持稳定。
