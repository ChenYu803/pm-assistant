# 04: 任务地图、回溯与游客中断继续

**What to build:** 用户可以从任务地图像选择游戏关卡一样进入任意工作场景；游客中断后可在同一设备、同一浏览器继续，登录用户可以回溯和重复体验全部场景，但不建立服务端游客进度系统。

**Blocked by:** #03 - 完整工作场景序列与职业认知反馈

**Status:** ready-for-agent

## 产品经理在 Agent 开始前提供

- `level-map.html`：任务地图桌面端和移动端原型。
- 地图节点名称、顺序、节点与工作场景的对应关系、第一关推荐方式。
- 已登录用户进入地图、游客测试通过后进入地图、返回某个工作场景、重复体验某个场景的交互状态。
- 游客离开后再次打开的“继续上次体验”状态，以及“继续/重新开始”的文案和交互说明。
- 明确哪些状态属于浏览器本地体验，哪些状态不应写入服务端。

## Agent 负责

- 实现任务地图的视觉和交互，并让每个节点进入 #03 已实现的对应工作场景。
- 已登录用户点击入口后直接进入地图，所有节点默认开放，并明确推荐第一关。
- 游客完成测试后提供进入地图的按钮。
- 实现游客在同一设备、同一浏览器中断后继续；不创建服务端游客用户、项目、工作记录或入职进度。
- 支持回溯和重复，不改变唯一剧情顺序，不调用 LLM。

## Agent 不负责

- 不把地图做成需要完成前置节点才能解锁的分支系统。
- 不实现跨设备、跨浏览器或清除浏览器数据后的恢复。
- 不自行增加积分、等级、排行榜、徽章等游戏化系统。

- [ ] 任务地图在桌面端和移动端符合 HTML 原型。
- [ ] 第一关有明确推荐，所有节点默认可选。
- [ ] 每个节点能进入正确的工作场景并支持返回。
- [ ] 游客离开后在同一浏览器可以继续或重新开始。
- [ ] 游客恢复不产生服务端用户、项目、工作记录或入职进度数据。
- [ ] 登录用户和游客都可以回溯、重复体验工作场景。
