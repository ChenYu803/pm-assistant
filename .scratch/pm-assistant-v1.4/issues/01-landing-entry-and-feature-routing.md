# 01: 落地页与入职体验入口分流

**What to build:** 将落地页 HTML 接入现有网站；“我已经准备好，开始做产品”和“开始做产品”按钮直接进入现有产品入口 `/projects`，顶部和页脚“注册 / 登录”直接进入 `/login`。本票不实现“先认识 AI 产品经理”后的入职体验分流，相关入口继续保留 Toast 占位：游客进入任务简报由 #02 负责，已登录用户进入任务地图由 #04 负责。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 产品经理在 Agent 开始前提供

- 已完成的落地页 HTML 原型及其图片、字体、图标等资源。
- 落地页交互说明：A 入口是“先认识 AI 产品经理”，B 入口是“我已经准备好，开始做产品”，右上角有“注册/登录”。
- B 入口直接进入当前产品入口 `/projects`；注册 / 登录入口直接进入 `/login`，登录页提供注册链接。
- “先认识 AI 产品经理”及底部“进入职业认知体验”继续显示 Toast 占位，不在本票中实现跳转；游客任务简报由 #02、已登录用户任务地图由 #04 负责。

## Agent 负责

- 将落地页 HTML 的视觉层级、响应式布局、交互状态和资源接入现有网站。
- 实现 B 入口和顶部/页脚注册登录入口，同时保持现有四环流程不回归。
- 保留 A 入口的明确 Toast 占位，不自行实现任务简报、任务地图或其他入职体验页面。
- 不把四个流程展示项实现为可交互按钮。

## Agent 不负责

- 不实现任务简报、完整工作场景、任务地图、测试或认知文件的正式内容。
- 不替产品经理决定产品品牌名、入职剧情、工作场景文案或视觉方向。
- 不重做现有四环 Agent、文件协议或数据库能力。

- [x] 桌面端和移动端落地页符合提供的 HTML 原型。
- [x] “先认识”主卡片和底部职业认知 CTA 保留 Toast 占位，不发生页面跳转。
- [x] 点击 B 主卡片和“开始做产品”区块按钮进入 `/projects`。
- [x] 点击顶部和页脚“注册 / 登录”进入 `/login`。
- [x] 四个产品实践流程项保持纯展示、不可交互。
- [x] 类型检查和本票相关的最轻量浏览器验证通过。

## 视觉回迁修正（2026-08-26）

首版实现曾以手工重绘替代原型迁移，造成 Hero、职业困惑列表、字体、颜色和间距偏离原型。本次已恢复原型 DOM 层级与 CSS 视觉参数，仅保留本票约定的路由和 Toast 行为适配；并验证外层滚动容器下的渐显与导航隐藏动画。
