# 01: 落地页与入职体验入口分流

**What to build:** 用户从落地页选择“先认识 AI 产品经理”后，能够进入“AI 产品经理入职体验”的正确起点；选择“我已经准备好，开始做产品”后，继续进入现有四环产品实践。落地页是入口，不实现入职体验内部内容。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## 产品经理在 Agent 开始前提供

- 已完成的落地页 HTML 原型及其图片、字体、图标等资源。
- 落地页交互说明：A 入口是“先认识 AI 产品经理”，B 入口是“我已经准备好，开始做产品”，右上角有“注册/登录”。
- 两种登录状态的跳转约定：游客点击“先认识”进入任务简报入口；已登录用户点击“先认识”进入任务地图入口；点击 B 继续现有四环流程。
- 如果 HTML 中存在占位文案或尚未实现的跳转，产品经理在说明中明确哪些内容由本票实现、哪些留给后续票。

## Agent 负责

- 将落地页 HTML 的视觉层级、响应式布局、交互状态和资源接入现有网站。
- 实现游客和已登录用户点击“先认识”后的不同入口分流。
- 实现 B 入口和右上角注册/登录入口，同时保持现有四环流程不回归。
- 为后续任务简报、任务地图和四环流程提供稳定的入口边界；后续界面尚未完成时可以使用明确的临时入口壳，但不得自行发明正式内容。
- 验证游客点击入口不会创建服务端用户、项目、工作记录或入职进度。

## Agent 不负责

- 不实现任务简报、完整工作场景、任务地图、测试或认知文件的正式内容。
- 不替产品经理决定产品品牌名、入职剧情、工作场景文案或视觉方向。
- 不重做现有四环 Agent、文件协议或数据库能力。

- [ ] 桌面端和移动端落地页符合提供的 HTML 原型。
- [ ] 游客点击“先认识”无需注册，进入任务简报入口。
- [ ] 已登录用户点击“先认识”进入任务地图入口。
- [ ] 点击 B 和右上角注册/登录保持现有行为。
- [ ] 游客入口不写入服务端用户、项目、工作记录或进度数据。
- [ ] 类型检查和本票相关的最轻量浏览器验证通过。
