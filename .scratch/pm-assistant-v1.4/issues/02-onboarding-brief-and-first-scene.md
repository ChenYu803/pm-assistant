# 02: 入职任务简报与第一个工作场景

**What to build:** 游客从落地页进入“AI 产品经理入职体验”后，先看到清晰的入职任务简报，再进入第一个工作场景并完成一次判断，形成从“刚入职”到“开始工作”的完整开场体验。

**Blocked by:** #01 - 落地页与入职体验入口分流

**Status:** ready-for-agent

## 产品经理在 Agent 开始前提供

- `mission-brief.html`：任务简报页的完整 HTML 原型。
- 第一个工作场景的 HTML 原型；可以单独提供，也可以作为 `work-scenes.html` 的第一个状态。
- 固定开场文案：用户身份、入职情境、前辈/上级、任务名称“大学生 AI 学习助手”、开始任务按钮。
- 第一个场景的背景、问题、四个选项、正确答案、正确理由、错误答案说明和进入下一场景的文案。
- `prototype-notes.md`：简报到第一个场景的跳转、返回、刷新和移动端状态说明。

## Agent 负责

- 将任务简报 HTML 实现为游客可直接访问的入职开场页面。
- 将任务简报与第一个工作场景连接起来，用户点击开始后可以完成一次固定判断。
- 实现选择后展示职场前辈反馈：正确答案、正确理由、用户选择、错误理由和继续按钮。
- 保持内容预编排，不调用 LLM，不要求用户输入自由文本。
- 为后续工作场景序列提供稳定的场景数据和交互边界。

## Agent 不负责

- 不自行设计完整入职剧情或补写未提供的职业认知内容。
- 不实现任务地图、游客长期恢复、十题测试和认知文件。
- 不把第一个场景的错误选择做成分支剧情。

- [ ] 游客可以从落地页进入任务简报，无需注册。
- [ ] 任务简报清楚说明用户身份、任务对象和开始动作。
- [ ] 用户可以进入第一个工作场景并看到四个选项。
- [ ] 选择后显示完整的职场前辈反馈，且不会改变后续路线。
- [ ] 刷新或返回不会造成重复提交或调用真实模型。
- [ ] 原型中的桌面端、移动端和关键反馈状态均可运行。
