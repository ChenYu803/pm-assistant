# AI 产品经理入职体验 v1.4 - Spec

Status: ready-for-agent

> 仓库内部项目名仍为 PM Assistant；v1.4 不决定对外产品品牌名。本文将原来的“A 路线”重新定义为正式功能“AI 产品经理入职体验”。

## Problem Statement

当前产品的主要入口直接把用户带入需求分析、原型、PRD 和任务拆分四环工作流。这个入口适合已经知道自己要做产品的人，但不适合还不了解 AI 产品经理、也不知道是否适合从事这份工作的求职者。

目标用户主要是想申请 AI 产品经理实习、缺少实际 PM 工作经验的中国大学生。他们接触了大量 AI 信息，却不知道 AI 产品经理究竟是什么、日常如何工作、与传统 PM 和技术岗位有什么区别，也不知道应该从哪里开始。

落地页已经有 HTML 原型，但落地页之后的产品体验此前只被称作“A 路线”，没有明确的功能定义、界面地图、原型交付清单和实现责任边界。因此产品经理不知道下一步该设计什么，Agent 也无法判断收到 HTML 后应该实现哪些完整行为。

## Solution

新增正式功能 **AI 产品经理入职体验**。

它不是课程目录，也不是一组孤立的选择题，而是一项场景化的入职任务：用户扮演刚入职、第一次接到任务的 AI 产品经理，接手“大学生 AI 学习助手”项目，在固定的工作场景中做出判断，由职场前辈即时解释判断结果，最终完成职业认知测试。

用户在落地页点击“先认识 AI 产品经理”后进入入职体验；点击“我已经准备好，开始做产品”则继续进入现有四环产品实践。落地页是入口，不属于入职体验本体。

### 入职体验的界面树

1. **任务简报页**：说明用户刚入职、当前身份、收到的任务和开始方式。
2. **工作场景页**：展示当前场景、背景、问题和四个选项；选择后展示职场前辈反馈，再进入下一个场景。
3. **任务地图页**：展示入职任务的全部工作场景；已登录用户从这里进入，游客通过测试后也可以进入；第一关有明确推荐。
4. **职业认知测试页**：固定十道四选一题。
5. **测试结果页**：展示得分和错题，提供回溯或直接重测；十题全对时显示祝贺。
6. **职业认知文件页**：展示登录保护、文件查看和下载；文件由产品预先编写，不是个人总结。

所有用户沿同一条剧情顺序体验工作场景。场景中的选择只触发即时反馈，不改变剧情、后续顺序或关卡开放状态。核心内容、题目和反馈全部预编排，不调用 LLM。

### 原型交付方式

采用“主要界面分别提供 HTML + 一个完整总入口 HTML”的方式。

预期原型包包含：

- 已完成：落地页 HTML；
- 后续需要：`mission-brief.html`、`work-scenes.html`、`level-map.html`、`assessment.html`、`career-document.html`；
- 最终需要：一个可以从任务简报走到职业认知文件入口的完整可点击总入口 HTML。

每个 HTML 必须包含与该界面相关的主要状态，而不是只有一张静态首屏。原型还应附带关键文案、选项、反馈、页面跳转和特殊状态说明。HTML 是视觉和交互输入；本 spec 与 ticket 是产品行为契约。

## User Stories

### 入口与任务开场

1. 作为第一次访问的求职者，我想从落地页选择“先认识 AI 产品经理”，以便在不注册的情况下开始职业体验。
2. 作为已经准备好做产品的用户，我想选择“我已经准备好，开始做产品”，以便直接进入现有四环工作流。
3. 作为游客，我想点击入口后看到任务简报，以便知道自己是谁、正在做什么以及为什么要继续。
4. 作为游客，我想在看完任务简报后直接开始第一个工作场景，以便不在开始前被注册或复杂设置打断。
5. 作为已登录用户，我想点击入口后进入任务地图，以便直接回看或选择任意工作场景。
6. 作为用户，我想从右上角注册或登录，以便在需要查看和下载认知文件时完成认证。

### 场景化入职任务

7. 作为求职者，我想扮演刚入职的 AI 产品经理，以便获得真实的职业代入感。
8. 作为刚入职的 AI 产品经理，我想接手“大学生 AI 学习助手”任务，以便通过具体工作理解岗位，而不是阅读抽象介绍。
9. 作为体验用户，我想沿唯一的工作场景顺序前进，以便不再次面对“我应该从哪里开始”的选择困难。
10. 作为体验用户，我想在每个工作场景做一个或多个判断，以便亲自体验产品经理需要做决策。
11. 作为用户，我想看到四个明确选项，以便理解当前需要我判断的问题。
12. 作为做出选择的用户，我想看到职场前辈即时反馈，以便知道这个选择为什么合适或不合适。
13. 作为答错的用户，我想看到正确答案、正确理由、我的错误答案和错误理由，以便把错误变成可理解的学习反馈。
14. 作为用户，我想知道错误选择不会导致剧情失败或进入另一条路线，以便可以放心尝试。
15. 作为求职者，我想在任务过程中理解 AI 产品经理的定义、日常工作和交付物，以便形成可复述的职业认知。
16. 作为求职者，我想理解 AI 产品经理与传统 PM、算法工程师和 AI 工程师的区别，以便建立合理的岗位边界。
17. 作为求职者，我想理解 AI 产品经理如何使用 AI 提升自身工作效率，以便知道 AI 不只是产品功能本身。
18. 作为求职者，我想理解如何发现 AI 可以提升效率或创造新收入的场景，以便知道 AI 产品经理的核心增量能力。
19. 作为求职者，我想理解如何设计人与 AI 的协作边界并处理 AI 不可靠性，以便知道产品经理需要保留判断和责任。
20. 作为求职者，我想理解 Vibe Coding 在成长路径中的位置，以便知道 AI 产品经理如何逐步扩大产研闭环能力。

### 任务地图与中断继续

21. 作为已登录用户，我想从任务地图进入任意工作场景，以便所有内容都可以回溯和重复体验。
22. 作为已登录用户，我想看到第一关的明确推荐，但不被完成状态锁定其他场景。
23. 作为游客，我想中断体验后在同一设备、同一浏览器继续，以便不必一次完成全部任务。
24. 作为游客，我接受换设备、换浏览器或清除浏览器数据后无法恢复，以便产品不为匿名用户建立服务端身份。
25. 作为游客，我不希望开始入职体验时创建服务端用户、项目、工作记录或关卡进度。
26. 作为完成测试的游客，我想获得进入任务地图的按钮，以便测试后仍能回看全部工作场景。

### 职业认知测试

27. 作为完成全部工作场景的用户，我想回答固定十道四选一题，以便检查自己是否掌握了本次体验的核心认知。
28. 作为提交测试的用户，我想看到得分和错题，以便知道哪些工作场景需要回看。
29. 作为答错的用户，我想看到每道错题对应的回溯场景，以便快速回到相关内容。
30. 作为答错的用户，我想选择先回溯或直接重新测试，以便按照自己的方式继续。
31. 作为重测用户，我想不限次数重试，以便不会因一次失误永久中断体验。
32. 作为十题全对的用户，我想看到祝贺和明确的完成反馈，以便知道入职体验已经完成。

### 认知文件

33. 作为十题全对且已登录的用户，我想直接查看固定的职业认知文件，以便沉淀刚才理解的内容。
34. 作为十题全对但未登录的游客，我想注册或登录后返回查看文件，以便不必在体验开始前注册。
35. 作为未登录游客，我不能查看或下载认知文件，以便文件不是公开落地页内容。
36. 作为已登录用户，我想下载完整认知文件，以便保存和复习。

## Implementation Decisions

- **正式功能名称**：将原“A 路线”统一称为“AI 产品经理入职体验”。A 只作为旧称，不再出现在新界面、spec、ticket 和实现命名中。
- **领域术语**：整个功能称为“入职体验”；贯穿案例称为“入职任务”；“大学生 AI 学习助手”是入职任务的工作对象；任务中的内容单元称为“工作场景”；“关卡”只可作为任务地图的游戏化 UI 文案，不作为核心领域术语。
- **产品品牌**：仓库内部项目名仍为 PM Assistant；对外产品品牌名尚未确定，v1.4 不锁定品牌名。
- **功能起点**：落地页点击“先认识 AI 产品经理”后，游客进入任务简报页；已登录用户进入任务地图页。落地页本身不计入入职体验。
- **任务简报**：任务简报必须明确用户身份、入职情境、当前任务、任务目标和开始按钮；游客不需注册即可开始。
- **工作场景**：工作场景按唯一顺序串联；每个场景可包含背景、一个或多个四选一判断、前辈反馈和进入下一场景的动作。
- **反馈规则**：选择只影响即时反馈，不改变剧情、后续顺序或解锁状态。反馈必须同时说明正确答案/理由，以及用户错误答案/理由；内容固定预编排。
- **认知覆盖**：工作场景整体必须覆盖 AI 产品经理定义、日常工作、相邻岗位区别、AI 提效、发现 AI 价值、人机协作、AI 不可靠性、交付物和 Vibe Coding 成长位置。
- **任务地图**：已登录用户点击入口后可访问任务地图，所有工作场景默认开放，第一关有视觉推荐；游客通过测试后可获得进入任务地图的按钮。地图不要求服务端保存完成状态。
- **游客恢复**：游客进度只保存在同一设备同一浏览器的本地环境；不创建服务端游客用户、项目、工作记录或进度。跨设备、跨浏览器和清除浏览器数据后的恢复不承诺。
- **测试**：末尾固定十道四选一题；提交后展示得分和错题，错题关联工作场景；可回溯或直接重测，不限次数；十题全对才通过并显示祝贺。
- **认知文件**：文件结构、内容、版本、登录保护、查看和下载属于同一项交付。文件是产品预先编写的固定内容，不是个人总结、成绩单或动态生成结果；游客通过后先注册/登录，认证后返回查看；未登录不能查看或下载。
- **B 路线**：点击“我已经准备好，开始做产品”后继续使用现有需求分析 → 原型 → PRD → 任务拆分流程；v1.4 不重做四环工作流。
- **原型责任**：产品经理在每张实现票开始前提供对应 HTML 原型、资源和状态/文案说明；Agent 负责把已确认原型和本 spec 的行为契约落地为现有应用中的可运行体验。Agent 不替产品经理决定任务剧情、核心文案、页面层级或未提供的视觉方向。
- **原型包**：需要分别提供落地页、任务简报、工作场景、任务地图、测试、认知文件 HTML，并最终提供一个可以从任务简报走到文件入口的完整可点击总入口 HTML。每个 HTML 必须包含主要状态，不是静态截图。
- **内容责任**：产品经理负责在原型或随附文案中确认场景、选项、正确答案、前辈反馈、十道测试题、错题回溯关系和认知文件正文；Agent 不得为了填补内容空缺自行改变产品认知目标。
- **最高测试 seam**：以浏览器中的完整入职体验为最高验收 seam，覆盖游客和已登录用户的入口、任务简报、工作场景、任务地图、测试、登录回跳、文件查看/下载，并验证 B 路线不回归。

## Testing Decisions

- 测试只断言用户可见页面、浏览器交互、认证边界、下载结果、游客本地恢复和既有四环入口，不断言组件名、CSS 实现、浏览器存储 API 或函数签名。
- 每张实现票必须附带能覆盖该票主要状态的 HTML 原型，回放使用固定预编排内容，不调用真实 LLM。
- 入口专项覆盖落地页 A/B 分流、游客/登录用户差异和 B 路线不回归。
- 入职开场专项覆盖任务简报和第一个工作场景的完整进入与反馈。
- 工作场景专项覆盖唯一顺序、四选一、正确/错误反馈、前辈解释和从第一场景到测试入口的连续体验。
- 地图专项覆盖第一关推荐、所有场景开放、回溯、重复进入、游客中断继续和无服务端游客数据写入。
- 测试专项覆盖十题、得分、错题映射、回溯、直接重测、无限重试和十题全对。
- 文件专项覆盖已登录直接查看、游客登录拦截、登录回跳、未登录禁止查看/下载和已登录下载。
- 最终回放覆盖完整总入口 HTML 所表达的主要桌面/移动布局和关键状态；日常验证继续使用 `AI_MODE=replay`，实现收尾执行类型检查、lint、构建、脚本语法和 diff 检查。

## Out of Scope

- A 路线这一旧称及其继续扩张为独立技术模块。
- 在入职体验中调用 LLM、根据自由输入动态生成剧情、反馈、题目或职业报告。
- 多个入职案例、多条剧情分支、用户自选行业或课程题库。
- 用户在本版本中完成完整需求分析、原型、PRD、任务拆分或真实产品交付。
- 完整课程体系、内容管理后台、导师/社群、积分、等级、排行榜和复杂游戏化。
- 服务端游客账号、游客项目、游客工作记录、游客关卡进度和跨设备匿名恢复。
- 认知文件公开查看、游客下载、个人化总结、成绩单和文件历史库。
- 在 Codex 仓库内重新设计视觉原型；视觉设计由用户在 open-design 完成并以 HTML 带回。
- 通过十题结果推断用户真实理解水平、职业适配度或求职意愿。

## Further Notes

- v1.4 的产品结果是让用户通过一次场景化入职任务知道 AI 产品经理是什么；不是让用户立即拥有可投递的作品。
- “大学生 AI 学习助手”在 v1.4 中首先是承载职业认知的工作对象，其完整产品定位和功能设计不在本版本展开。
- 原型 HTML 是实现输入，不是新的产品事实来源；当 HTML 与 spec/ticket 冲突时，以已确认的产品行为契约为准，并在实现前报告冲突。
- 产品经理的工作顺序是：先完成对应 HTML 和文案/状态说明，再把原型和 ticket 一起交给 Agent；Agent 完成后再进入下一张票。
- `ready-for-agent` 表示票可以在满足“产品经理输入”后执行，不表示相关原型已经全部完成。
