# 04 — 空库首次使用与诊断边界

**What to build:** 让 MySQL 空库按全新安装进入现有注册/项目流程，并提供符合 v1.3 决策的连接失败、初始化失败和开发重置行为。

**Blocked by:** #01 — MySQL 运行时与初始化基础；#03 — 业务一致性与核心 API 迁移

**Status:** ready-for-agent

- [ ] 空 MySQL 数据库打开网站时直接进入现有注册页，不增加数据库初始化页面或数据库类型展示。
- [ ] 注册成功后可以创建项目、工作记录并进入四环流水线；不读取或补建旧 MongoDB 用户。
- [ ] MySQL 未启动、端口错误、凭据错误或权限不足时，用户看到通俗的暂时不可用/操作失败提示，维护者可从日志或诊断信息定位原因。
- [ ] 初始化失败不新增专门用户页面；具体功能调用保留明确、可带回的错误信息。
- [ ] 若实现开发重置命令，执行前必须确认开发环境并阻止生产环境使用。
- [ ] 不实现切回 MongoDB、双写或 MySQL 数据回搬。

## 相关 spec

见 v1.3 spec 的“安装与首次使用”“故障与诊断”和“Out of Scope”。

## 验收标准

- 全新 MySQL 数据库可完成注册 → 项目 → 工作记录创建。
- 连接不可用时不显示原始数据库堆栈、密码或连接凭据。
- 开发重置（若提供）只影响明确的开发数据库，并能再次运行初始化流程。
