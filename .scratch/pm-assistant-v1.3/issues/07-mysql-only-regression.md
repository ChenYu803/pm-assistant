# 07: MySQL 单库收口与综合验收

**What to build:** PM Assistant 在不依赖 MongoDB/Mongoose 的情况下从空 MySQL 启动，并通过全部 v1.2 固定回放和一次从零四环人工冒烟，成为可交付的 v1.3。

**Blocked by:** #01 — MySQL 空库与初始化基础；#02 — 账号、项目与工作区骨架切换；#03 — 对话、恢复与并发切换；#04 — 项目成果与 tickets 交付切换；#05 — 显式冻结流程切换；#06 — 项目与工作记录级联删除切换

**Status:** in-progress

- [ ] 删除生产应用、验证脚本和配置对 Mongoose/MongoDB 的运行依赖；MongoDB 原库可以留在电脑上，但应用不再读取或写入它。
- [ ] 空 MySQL 直接进入正常注册页，不展示数据库类型、版本或初始化页面；不实现切回 MongoDB、双写或数据回搬。
- [ ] MySQL 不可用或瞬断时，当前操作明确失败并可手动重试；不无限重试、不后台排队、不泄露凭据或原始堆栈。
- [ ] 综合入口在运行前确认 MySQL 9.7.2 LTS 与固定回放模式，并覆盖全部 v1.2 专项的 UI、HTTP/SSE 和数据库可观察行为。
- [ ] 综合入口只汇总专项退出码、名称和类别；失败能区分环境、schema、业务回归和测试夹具问题，不自动切换真实模型。
- [ ] 完成一次从零人工冒烟：注册 → 项目 → 工作记录 → 需求分析 → 原型 → PRD → tickets，并确认消息、文件、快照与版本交付可回看。
- [ ] 类型检查、构建、相关静态检查和综合 replay 通过；预计超过 10 分钟或调用真实模型的验证必须先按仓库纪律报备。
- [ ] 验收记录明确：本次只验证 MySQL 9.7.2 LTS，不宣称所有 MySQL 版本兼容，也不包含实际线上部署。
