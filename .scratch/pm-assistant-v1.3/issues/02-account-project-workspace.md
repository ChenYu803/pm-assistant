# 02: 账号、项目与工作区骨架切换

**What to build:** 用户可以在空 MySQL 中重新注册和登录，随后创建、查看、重命名项目与工作记录，并进入由 MySQL 保存的工作区和 tab。

**Blocked by:** #01 — MySQL 空库与初始化基础

**Status:** implemented-pending-mysql-verification

- [ ] 新用户注册、密码校验、登录与会话中的用户标识全部以 MySQL 用户记录为事实源，不读取旧 MongoDB 用户。
- [ ] 项目和工作记录的创建、列表、详情、重命名与 ownership 校验使用 MySQL，跨用户或跨项目访问仍被拒绝。
- [ ] 用户可以创建、查看、排序和重命名 tab，并在刷新后回到正确的项目、工作记录和 tab。
- [ ] 标识符在会话、URL、API 请求和数据库关系之间采用统一语义，不留下半套 MongoDB ObjectId 校验。
- [ ] 父子关系、名称条件、排序、时间和必要唯一约束由 MySQL schema 与 API 外部行为共同保证。
- [ ] 本票不提前实现跨全部实体的物理级联删除；删除行为由 #06 统一收口。
- [ ] 完成一条可独立演示的流程：空库注册 → 登录 → 创建项目 → 创建工作记录 → 创建 tab → 刷新后仍可访问。
