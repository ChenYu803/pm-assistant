# 01 — MySQL 运行时与初始化基础

**What to build:** 为 PM Assistant 建立可配置、可重复初始化的 MySQL 运行时基础，使应用能在本机 MySQL 9.7.2 LTS 上使用项目专用连接身份启动。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 选定并接入明确支持当前 Next.js/Node.js 运行环境及 MySQL 9.7.2 LTS 的驱动/数据访问基础，不再让业务代码依赖 MongoDB 连接入口。
- [ ] 通过环境变量/本机配置提供地址、端口、数据库名、应用连接身份和密码；真实凭据不进入代码或仓库。
- [ ] 提供可重复执行的初始化/升级入口，能建立或升级数据库结构所需的基础元数据，并在重复执行时保持幂等。
- [ ] 初始化流程能够准备仅服务本项目的应用连接身份；Workbench 继续可以使用 `root`。
- [ ] 缺失配置、连接失败、版本/权限不满足时返回明确可诊断错误，不把原始数据库错误直接当作用户文案。
- [ ] 若提供开发重置命令，必须显式限制为开发环境，生产配置下拒绝执行。

## 相关 spec

见 v1.3 spec 的“安装与首次使用”“实现决策”“故障与诊断”。

## 验收标准

- 在本机 MySQL 9.7.2 LTS 上首次初始化成功，重复初始化不破坏结果。
- 应用可以使用专用连接身份完成一次数据库连接；不依赖 Workbench 手工执行 SQL。
- 错误配置和不可达服务可被维护者定位，用户层不会显示凭据或原始堆栈。
