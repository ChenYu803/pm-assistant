# 10: 项目成果 API MySQL-only 收口

**Parent:** #07 — MySQL 单库收口与综合验收

**What to build:** 项目、工作记录、文件、上下文、快照和 tickets 的公开 API 只使用 UUID/MySQL，同时完整保留文件确认、需求分析追加、下载、润色、来源记录和版本交付契约。

**Blocked by:** #04 — 项目成果与 tickets 交付切换；#05 — 显式冻结流程切换；#06 — 项目与工作记录级联删除切换

**Status:** ready-for-agent

- [ ] 项目与工作记录详情、修改和删除只使用 MySQL ownership 与事务实现，旧 ObjectId 不再触发 MongoDB 路径。
- [ ] 项目文件列表、创建/更新、读取、下载、润色和删除保持现有 JSON、下载头、版本、白名单、大小、冻结绑定与错误契约。
- [ ] 需求分析文件继续按既有 changelog/追加语义更新，其他正式文件和工作文档继续遵守各自替换规则。
- [ ] tab 文件上下文的加载、移除和过滤只使用 MySQL 关系，跨项目文件不能进入 Agent 上下文。
- [ ] 原型快照的创建、列表、详情和版本语义保持不变，且快照不出现在普通文件树或 Agent 上下文。
- [ ] tickets 候选、整套替换、另存版本、列表、选择和下载保持完整集合语义，不产生新旧版本混合或半套写入。
- [ ] 现有项目成果、文件来源、项目隔离、快照和 tickets 专项可在 MySQL 路径运行；已有未提交收口改动必须按真实 UI/API 消费逐项审计。
