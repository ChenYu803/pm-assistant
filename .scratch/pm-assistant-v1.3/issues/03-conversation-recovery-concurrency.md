# 03: 对话、恢复与并发切换

**What to build:** 用户在 MySQL 工作区中发送、停止、重生成和编辑消息时，刷新恢复、自动命名、重复请求吸收和多窗口冲突行为与 v1.2 一致。

**Blocked by:** #02 — 账号、项目与工作区骨架切换

**Status:** implemented-pending-mysql-verification

- [ ] 消息角色、正文、顺序、生成中/完成/中断/失败状态和时间由 MySQL 持久化，刷新后每条消息只显示一次。
- [ ] 生成开始即建立正式 assistant 消息；零 token 失败、停止生成和部分内容保留行为不回归。
- [ ] 重生成和编辑重发先产生候选结果，成功后再替换旧历史；失败或中断不删除原有可见结果。
- [ ] request id 幂等、消息替换链和重试语义在 MySQL 唯一约束及事务边界下保持稳定。
- [ ] tab 版本、当前操作和重放结果使用 MySQL 条件更新/事务实现；多窗口冲突仍显示既有明确提示，不静默覆盖。
- [ ] 自动命名只在工作记录仍为“未命名”时成功，迟到结果不覆盖手动名称。
- [ ] replay 流程可以独立验证发送 → 刷新 → 停止/失败 → 重试 → 重生成/编辑 → 并发冲突。
