# 04 — 项目与工作记录级联删除

**What to build:** 用户删除项目或工作记录后，所有属于删除范围的数据都被物理清理；删除失败时用户得到失败结果，重复请求可以安全补偿，不会被误报为成功。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [ ] 删除项目会清理其工作记录、tab、消息、文件上下文和项目文件。
- [ ] 删除工作记录会清理其 tab、消息和文件上下文，但保留项目级文件。
- [ ] 支持事务的部署使用事务保证删除结果；不支持事务时使用可重入补偿清理。
- [ ] 只有所有目标集合确认清理后才返回成功；中途失败返回可识别失败结果。
- [ ] 对已删除或半清理目标重复请求不会产生额外副作用，并最终得到一致的不存在结果。

## Comments

- 2026-08-23：用户授权继续。删除协调只作为数据库内部闸门，不新增用户可见的“删除中”流程；项目/工作记录可立即按不存在处理。其职责是阻止删除期间的新建工作记录、tab、消息、文件上下文、项目文件和快照写入，避免孤儿数据。
- 2026-08-23：最终审查确认当前“15 秒后回收写入许可”的补偿方案不满足零孤儿语义：普通写入若在数据库或网络中卡过期，删除会继续；该写入恢复后仍可能落到已删父级下。去掉过期回收可保住零孤儿，但异常退出会永久阻塞补偿；在不支持 MongoDB 事务、且子集合与父集合分离的现有结构中，二者不能同时原子保证。本票保持 `claimed`，等待用户决定是否接受删除在活跃慢写入时明确失败并人工/后台重试，还是调整存储/部署前提。
- 2026-08-23：用户选择“最终清理”。保留项目立即按不存在处理和正常路径的当场物理级联；若极端慢写入在删除后才落库，写入请求结束时、应用重新打开项目列表时会按 ownership 链自动清扫。允许短暂内部残留，不承诺删除响应时已达到零残留；不增加用户可见删除状态，也不需要本地部署 MongoDB 事务。
