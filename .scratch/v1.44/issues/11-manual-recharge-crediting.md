# 11: 联系充值与后台人工入账

**What to build:** 用户在个人中心进入“获取积分/联系充值”页面，与运营者确认后转账；管理员核验实际到账，通过后台给对应账号添加购买积分，用户能查到余额与流水。

**Blocked by:** [04：个人积分余额与有记录的管理员赠送、调整](04-credit-balances-admin-grants.md)

**Status:** ready-for-agent → claimed → resolved

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 4、8–11；测试决策 1–4。

**覆盖用户故事：** 51–54、63、64、67。

## 验收标准

- [x] 页面展示运营者微信联系方式与当前账号 ID，说明早期试用、人工处理，并提示先联系确认金额、积分与预计处理时间再转账。
- [x] 页面不承诺全天候或即时自动到账，不接在线支付、收款回调或自动支付订单系统；未提供真实联系方式时不展示占位值冒充可用渠道。
- [x] 指定管理员选择明确账号并录入实收人民币、交易参考号及业务说明，按 1 元 1000 购买积分入账；赠送或补偿不能伪装成实收购买。
- [x] 服务端保护管理权限和金额/账号校验，记录操作者、时间、实收金额、积分、交易参考号与前后余额，保留原充值来源供退款使用。
- [x] 同一转账重复提交、并发录入或响应丢失后的重试不重复到账；冲突返回明确可核对结果，不能把未知提交结果一律当失败后再次入账。
- [x] 用户个人中心看到购买余额及充值明细，后台可筛选分页查询充值记录；金额和显示与账本保持一致。
- [x] 入账中断不留下无审计余额变动；原有赠送余额不受充值影响，非管理员不能给自己发放购买积分。

## 验证与完成证据

- 从联系充值页到隔离后台录入、用户查账验证完整路径，使用已知金额核对购买积分与审计。
- 覆盖重复参考号、并发提交、超时重试、非法金额、跨账号及越权操作，不以真实用户转账作为测试数据。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。
