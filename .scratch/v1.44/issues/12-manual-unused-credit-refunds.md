# 12: 未消费购买积分人工退款与失败恢复

**What to build:** 管理员对未消费、未被模型调用预留的购买积分办理人工退款，关联原充值并同步扣减对应积分；外部转账或内部记账失败时有明确可恢复记录，用户可查询处理结果。

**Blocked by:** [08：文件润色接入同一积分计量与结算](08-polish-credit-settlement.md)；[11：联系充值与后台人工入账](11-manual-recharge-crediting.md)

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 4、6、8–11；测试决策 1–4。

**覆盖用户故事：** 55、56、65、67。

## 验收标准

- [ ] 只允许退款仍未消费、未预留的购买积分，金额不超过对应原实付及剩余可退部分；赠送积分不折现，不能退已消耗购买积分。
- [ ] 退款关联原充值与购买来源，支持可核对的剩余可退金额及积分扣减；不能仅凭账号总余额计算退款。
- [ ] 退款处理与新增模型预留、消费及重复退款相互约束，不能一边退同一部分积分一边继续花用，不能使购买余额或可退金额为负。
- [ ] 后台明确区分退款发起、外部转账结果和内部记账结果，保留操作者、时间、业务说明、外部参考及前后余额；不要求系统自动完成微信转账。
- [ ] 外部转账失败或内部写入失败时留下可追查、可安全恢复的状态；钱已退但内部尚未完成时相关积分不能继续使用，也不能以重试为由再次退款。
- [ ] 响应丢失、并发重复提交和恢复操作不会重复扣积分或引导重复外部转账；结果不明时明确待核实，不静默宣称退款失败或完成。
- [ ] 个人中心显示退款记录与最终余额，后台支持查询分页；服务端授权和账号隔离完整，不允许无审计改写原充值或历史消费。

## 验证与完成证据

- 使用有独立预期结果的隔离充值/消耗/预留账单，覆盖部分可退、全部已消费、赠送余额不可退和重复退款。
- 从应用入口并发发起退款与对话/润色调用，模拟转账失败、记账失败及响应丢失，验证可退额度守恒与恢复后的唯一结果。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增输入；复用 11 的人工渠道、实付记录与 08 已覆盖的全部模型预留入口。

## 实施边界与交接

用户真实资金不参与自动化测试。保留外部退款与内部账本的事实差异，恢复流程必须可操作，不能依赖直接改数据库。
