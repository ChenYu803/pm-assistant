## 验收标准

- [ ] 核实本地、远端与服务器的实际提交、生效配置、迁移状态和发布差集，以 #13 的明确已提交候选发布，包含 v1.43 视觉与 v1.44 功能；不由目录名推断版本。
- [ ] 在操作前按部署纪律说明目的、位置、影响、成功判据和恢复方式；核对已有授权，推送及实际生产变更按其授权范围执行。
- [ ] 在变更前保存当前可用源码、配置和数据库安全副本，验证服务器外副本实际存在且可读取或解密，恢复凭据独立保管；在隔离库或实例实际恢复并验证登录、项目和关键正文。
- [ ] 在现有服务器落实维护窗口或受限访问，确保 #15 完成前普通用户不会进入未验收版本；沿用已有部署条件，不默认新增服务器或迁移平台。
- [ ] 执行所需增量迁移，保留旧账号、项目、文件和资金事实，不清库、不强制重注册、不虚构邮箱验证，不使用会意外重置应用账号凭据或授权的初始化步骤。
- [ ] 启动目标版本，通过目标机 HTTP 和登录态页面核验旧账号可登录、个人中心可打开、原项目及关键正文可读；确认 v1.43 视觉与 v1.44 对应界面生效，未登录跳转不能代替登录态验收。
- [ ] 核对实际 live 模式、官方模型配置、指定管理员、运营微信和邮件配置状态；生产不启用邮件替身、伪用量或测试时钟。外部配置缺口明确交给 #15，并保持受控状态。
- [ ] 安装并启用待核对恢复调度，取得实际定时器和恢复进程运行证据，核实使用正确发行版本、运行配置与数据库；不通过修改生产时钟或故障注入冒充到期恢复证据。
- [ ] 形成与新增账本兼容的回退及失败恢复方案；不能还原旧库丢弃升级后新增积分、充值或退款事实，记录暂停写入与保护新增事实的方法。
- [ ] 记录实际发布提交、升级时间、配置核对、备份恢复、迁移及目标机基础验收结果，按部署纪律刷新变更后的安全副本，明确交付状态为“受控验收就绪”，交接 #15。

## 验证与完成证据

本票交付可实际访问的新版本和可恢复的数据，以目标服务器、真实数据库及隔离恢复结果验收；本机迁移和构建不替代这些证据。复用 #13 的有效代码与隔离回归，不在服务器重复整套替身测试。

真实邮件和新增付费模型核验集中在 #15；本票不要求先在本机完成同一套真实核验。外部配置尚未齐备时，应区分“可继续的准备”与“目标基础验收确实被阻断的部分”，不得虚构已配置或已通过。

先核实已有目标机访问方式、受限配置、服务器外备份位置和独立恢复凭据，只询问确实缺失的信息。沿用已确认的管理员身份，不重复索取已作出的决定；真实密钥不进入聊天或 Git。

本票完成实际增量升级与受控基础验收，不能仅凭部署方案标记 resolved。普通用户开放和完整生产发布结论由 #15 完成；若无法维持受控访问，应先解决该阻断再切换版本。
