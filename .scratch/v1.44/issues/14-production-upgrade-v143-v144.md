## 验收标准

- [ ] 按现状核实本地、远端与目标服务器的实际提交、生效配置及待部署范围，以已提交版本发布；包含已确认的 v1.43 视觉成果，不将其他会话的工作区改动无筛选打包。
- [ ] 沿用现有中国大陆服务器与 MySQL，执行增量升级，保留旧账号、项目和文件资料，不清库、不强制重注册、不虚构旧账号邮箱验证事实。
- [ ] 生产变更前说明目的、执行位置、影响、成功判据和恢复方式；阅读并遵守项目部署纪律，推送和生产操作按现有授权范围执行，拆票确认不替代所需操作确认。
- [ ] 变更前保存当前可用源码/提交、运行配置与数据库安全副本，确认服务器外实际存在且可读取/解密；备份解密凭据独立保管，不输出或提交真实密钥。
- [ ] 在隔离库或实例实际恢复备份，验证登录、项目及关键正文；校验哈希或仅有服务器内副本不能代替恢复成功证据。
- [ ] 核实目标机官方 Flash 模型、live 模式、邮件真实投递、指定管理员、微信展示信息、数据库持久化及 10 的自动恢复机制；不能将生产切到测试邮件、伪用量或测试时间模式。
- [ ] 在目标机使用受控账号和小规模请求核验登录/验证码、兑换与账本、真实模型调用和相关状态，并确认正常用户不能访问后台；不批量发信或动用真实用户资金作为测试。
- [ ] 核验已部署页面包含 v1.43 视觉与 v1.44 对应界面，记录实际发布提交、时间、配置核验及目标机结果；本机构建或 replay 不替代目标机发布证据。
- [ ] 提供与新增账本兼容的代码/数据库回退方案，回退和失败恢复不还原旧库丢弃发布后新增积分、充值或退款记录；资金事实有完整保护与追溯。
- [ ] 更新非敏感部署记录、备份位置/校验/恢复结果及交接进展，明确本地、远端和目标机版本是否一致及仍未完成事项。

## 验证与完成证据

- 发布完成以现有生产手册的目标机发布闸及本票新增账号、积分、自动恢复检查为准；记录可定位的实际结果。
- 按部署纪律核实安全副本并完成隔离恢复，目标机真实调用遵守累计模型预算，失败时先保护新增账本再恢复服务。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。
