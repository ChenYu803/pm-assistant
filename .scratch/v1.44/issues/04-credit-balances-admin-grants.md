# 04: 个人积分余额与有记录的管理员赠送、调整

**What to build:** 管理员对明确账号发放测试赠送或带原因调整积分后，用户在个人中心看到账号 ID、赠送/购买两类余额和分页流水；双方能核对同一笔变动的来源与前后余额。

**Blocked by:** [03：最小管理员入口与异常账号停用](03-minimal-admin-account-controls.md)

**Status:** resolved

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、4、8、10、11、12；测试决策 1–4。

**覆盖用户故事：** 8、12、30、31、47、48、50、59、66、67、69。

## 验收标准

- [x] 个人中心展示账号 ID、赠送和购买两类余额，以及可用、预留状态的明确口径；本票尚无模型预留时也从同一账本读取，不用界面常量伪造余额。
- [x] 赠送与购买来源分别记账，金额及积分使用可确定重算的精度，支持小数积分；显示精度不改变真实余额，不逐笔向上取整为 1 积分。
- [x] 管理员可为自己的测试账号或明确用户发放有记录的赠送、补偿或纠正余额；必须提供原因，并记录操作者、时间、业务类型与变动前后余额。
- [x] 调整不冒充实收充值、不无痕改写历史消耗；不得通过调整制造负余额、花掉已受保护额度或破坏原购买来源的可退款依据。
- [x] 用户可分页查看自己的流水，管理员可查询账号与流水；相同操作重发或响应丢失后的重试只能产生一份有效结果。
- [x] 账号之间不能读写彼此账本；所有管理调整服务端鉴权，管理操作本身不消耗积分。
- [x] 新账号零积分，旧账号与资料保留；增量迁移不得虚构购买、赠送或旧账号邮箱验证事实。
- [x] 提供后续兑换、预留结算、充值退款可共同使用的来源与审计契约；删除项目或会话后，相关资金记录仍有必要追溯信息。

## 验证与完成证据

- 从后台赠送/调整到用户查账验证完整闭环，刷新并重启应用后结果仍一致。
- 以独立已知小数账单、并发重复操作、非法负向调整、跨账号访问和无原因操作验证账本约束。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增输入，沿用 03 的管理员配置。

## 实施边界与交接

本票不实现人工购买入账或调用扣费；05、07、08、11、12 分别完成对应行为及各自流水展示。管理员使用产品仍由后续统一计费覆盖。
