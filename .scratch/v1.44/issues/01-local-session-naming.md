# 01: 默认名称取首条提示词，撤去模型命名

**What to build:** 用户首次发送提示词后，尚未手动命名的阶段会话直接显示首条提示词的前 10 个字符；命名在本地规则内完成，保留人工改名，不再产生隐藏的模型请求。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、5、11；测试决策 2–4。

**覆盖用户故事：** 27–29。

## 验收标准

- [ ] 默认名称只使用首条用户提示词；不足 10 个字符取全部，标点与空格按原文计入，不 trim、不清洗或概括；截取不破坏正常 Unicode 字符。
- [ ] 后续提示词不会反复改名；已有人工名称及生成期间的人工改名不被默认命名或迟到结果覆盖。
- [ ] 移除旧模型自动命名的真实请求及关联的后台触发路径；内部旧“工作记录”术语不进入新的产品界面。
- [ ] 不因改造重命名历史资料，现有会话仍可正常创建、打开和手动改名。
- [ ] 从用户创建与发送行为验证名称、刷新后持久结果及无隐藏命名成本；调整被新规则取代的旧命名断言。

## 验证与完成证据

- 覆盖中英文、短提示词、前导空格、标点、正常 Unicode 字符及人工改名竞争。
- 在模型边界观察主回复与命名行为，证明没有额外命名请求；不以私有函数调用次数作为验收。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增输入。

## 实施边界与交接

本票只改变默认命名来源，不改变阶段会话或项目文件的领域归属。
