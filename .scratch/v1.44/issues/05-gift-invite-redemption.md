# 05: 注册与个人中心兑换赠送邀请码

**What to build:** 用户在注册时选填赠送邀请码，或登录后在个人中心兑换，即可自动获得赠送积分；后台管理首批邀请码并保留领取记录，邀请码不再承担注册准入职责。

**Blocked by:** [02：邮箱验证码注册与密码找回](02-email-verification-auth.md)；[04：个人积分余额与有记录的管理员赠送、调整](04-credit-balances-admin-grants.md)

**Status:** resolved

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 2、3、4、8、10、11；测试决策 1–4。

**覆盖用户故事：** 6、7、13–18、61、62。

## 验收标准

- [x] 首批提供 100 个独立一次性码，每码赠送 2000 积分，每码最多成功领取一次、每账号最多成功领取一次；初始化或重试不得无意增发首批码。
- [x] 注册时兑换是可选项，账号通过邮箱验证成立后再领取；无效、已用、作废码或兑换失败不回滚正常注册，明确提示未获赠送并允许登录后重试。
- [x] 个人中心可兑换，成功到账后隐藏输入入口；刷新和跨设备读取相同的领取资格与余额。失败不消耗领取资格，不误标记码已使用。
- [x] 服务端原子完成资格检查、占码、赠送入账及领取记录；同码抢领、同账号同时提交多个码以及超时重发只能形成一笔有效赠送。
- [x] 若真实到账但响应丢失，重试返回可核对的已有结果，不再次赠送；写入中断不会留下已领码却未入账的静默状态。
- [x] 管理员可查询码状态、领取账号与时间并作废未使用码，相关操作留审计；作废不追回已到账积分。
- [x] 邀请码及赠送积分不自动到期；个人中心与后台流水均可核对赠送来源和变动后余额。
- [x] 两个兑换入口、服务端资格校验与管理权限均有针对性验证。

## 验证与完成证据

- 从注册与登录后的个人中心分别完成兑换，核对余额、入口隐藏与后台记录。
- 从应用入口真实并发提交同码和同账号多码，覆盖无效/已用/作废码、响应丢失及入账失败恢复。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增输入；赠送规则沿用已确认的 100 个码、每码 2000 积分，不要求产品经理逐个手工生成。

## 实施边界与交接

复用 04 的账本与 02 的账号成立结果；不恢复原共享注册口令，不以页面隐藏代替服务端每账号一次约束。
