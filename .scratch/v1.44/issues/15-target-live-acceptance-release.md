## 验收标准

- [ ] 新增付费请求前核对开发至首批试用的历史支出、待确认成本和 200 元累计模型预算，记录有依据的剩余额度、此次样本与费用上限；未知费用不能按零处理，账目不清时不宣称精确余额或直接开跑。
- [ ] 在目标环境核实事务邮件供应商、已验证发信身份和安全配置，用可控可收信邮箱分别完成注册和密码找回，实际收到邮件并用验证码完成后续操作；记录脱敏收件与应用结果，将证据对应到 #02 唯一未完成的真实收信验收项。
- [ ] 从目标网站经应用入口完成小规模正常对话、文件润色、流式自然结束和主动停止样本，逐笔记录应用请求、官方实际模型、可靠用量、价格依据、API 实际成本、预留/结算结果和页面反馈；直连供应商样本不代替应用账本证据。
- [ ] 核对停止后最终用量、隐藏包装成本与输入预算边界，区分客户端中断、上游取消和供应商最终处理/计费；无可靠用量不得记成已确认零成本。若可靠计量或成本上界不成立，保留阻断并提交最小修正方案，不静默以不可靠估算扣分或宣称验收通过。
- [ ] 使用受控账号核验登录、验证码、邀请码兑换、个人余额与流水、管理员权限和普通用户后台拒绝；测试额度采用有记录的测试赠送，不伪造真实购买/退款，不批量发信、不动用真实用户资金。
- [ ] 核验 live 调用后的业务状态和账本可持久读取，复用 #14 已有的目标机恢复调度与基础持久化证据，仅补新增调用所需的观察；不在生产启用替身、测试时间或故障注入来重复隔离场景。
- [ ] 汇总已有隔离证据、备份恢复及目标机真实结果，核实管理员、运营联系方式与正式配置；逐项处理阻断，记录尚存限制及其处置，不用修改工单掩盖原验收义务。
- [ ] 满足发布条件并在既有授权范围内解除维护或访问限制，核验正式入口和实际生效版本，记录本地、远端、服务器版本的一致性或明确差异；更新部署记录、累计成本、必要安全副本及后续事项后才给出正式发布完成结论。

## 验证与完成证据

实际注册收信、实际找回收信、应用端真实请求及账本逐笔对应必须有可定位的脱敏证据。复用 #13 和 #14 的有效结果，不重复本机真实核验或整套历史隔离脚本。

正式开放取决于本票验收；#13 仅交付候选、#14 仅交付受控升级。若供应商能力或历史费用无法确认，明确限制、影响及阻断状态；不能把替身、缺失用量或尚未证实的停止计费能力写成通过。

真实邮件服务、已验证发信身份、可收信邮箱和官方 API 配置须经受限方式提供或核实已有配置；账单访问、缺失费用证据与新增核验额度仅在确有缺口时具体询问。资料和预算可提前整理，但不再作为 #13 收口条件；不在聊天或 Git 中提交密钥。

预计超过 10 分钟的 LLM 级验证，执行前说明本轮假设、时长与费用并取得同意。工单确认不等于真实付费调用或生产操作授权。
