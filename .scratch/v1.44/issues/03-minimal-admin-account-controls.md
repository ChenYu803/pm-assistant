# 03: 最小管理员入口与异常账号停用

**What to build:** 指定管理员通过现有账号登录最小运营后台，查询用户并停用异常账号。管理权限由服务端控制，停用账号即使持有旧登录状态也不能继续登录或新增模型请求。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、10、11；测试决策 1–4。

**覆盖用户故事：** 57、60、68、73。

## 验收标准

- [ ] 提供简洁管理员入口，沿用现有账号认证；只有指定管理员可以访问页面和每项管理接口，不能仅隐藏前端入口。
- [ ] 可按账号查询、筛选并分页查看用户列表与状态，提供必要的用户数量汇总；后续各功能票在此入口增加自己的运营视图。
- [ ] 管理员可停用异常账号并留下操作者、时间与业务说明；该账号的已有登录状态不能绕过限制继续新增模型调用。
- [ ] 匿名、普通用户及跨账号请求无法读取或执行管理操作；未授权调用不泄露其他账号信息。
- [ ] 后台默认不提供浏览用户对话或文件正文的入口，日志只含运营所需元数据，不输出正文和凭据。
- [ ] 采用普通表格、汇总和分页，继承现有视觉与可访问性；不引入服务器状态面板、装饰性动效或高频刷新。
- [ ] 增量保存账号管理状态，不影响已有账号及项目资料；正常账号仍可使用既有产品能力。

## 验证与完成证据

- 用指定管理员、普通用户和匿名身份从页面及 API 分别验证权限。
- 在停用前取得登录状态，再停用账号，验证旧状态不能继续新增模型请求，且未发生上游调用。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增原型或素材。需要产品经理明确生产环境的指定管理员账号；可先用隔离账号完成实现与权限验证，不能把测试身份默认变成生产管理员。
