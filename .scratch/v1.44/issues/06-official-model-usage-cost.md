# 06: 官方模型用量、真实成本与故障可追溯

**What to build:** 运营者在后台看到官方 Flash 的真实请求、可靠用量、适用价格及成本、故障和用量待确认状态；现有对话与润色文本行为保持可用，后续积分结算有可信计量可用。

**Blocked by:** [03：最小管理员入口与异常账号停用](03-minimal-admin-account-controls.md)

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、4、5、7、10、11、12；测试决策 1–5。

**覆盖用户故事：** 23、58、71、72。

## 验收标准

- [ ] 核查现有真实模型入口与旧每日调用次数限制，覆盖对话、润色和发现的其他真实模型调用；不把次数配额当作金额账本或误报成余额不足。
- [ ] 沿用官方 Flash，不换中转站；实施时核实实际模型标识、官方计费规则、可获得用量字段及流式/非流式结束行为，记录依据，不硬编码未经核实的供应商价格和能力。
- [ ] 保存可关联调用的标识、时间、状态、可靠用量及本次适用价格依据；按实际支持的输入、输出、缓存等项目计算人民币成本，能够确定重算。
- [ ] 兼容扩展现有模型边界，在文本输出继续正常工作的同时保留用量、价格、结束/错误状态和后续结算所需元数据；不破坏现有流式响应、文件确认及上下文权限。
- [ ] 未知用量、已确认成本、故障以及网站承担成本分别表示；用户免单不能抹去供应商成本，也不能将未知成本记为零。
- [ ] 后台可筛选、分页查看请求、使用与故障，并汇总已确认成本和待确认数量/状态；以必要元数据定位，默认不展示对话或文件正文。
- [ ] 累计模型预算口径为本轮开发验证至首批试用 200 元，不按月重置；邮件、服务器及域名不计入模型成本，不能用积分充值标价推算供应商费用。
- [ ] 核实正常结束、停止和断流可取得的可靠计量及恢复条件；不假定供应商提供事后用量查询。无法建立可靠证据时明确限制，为待核对处理提供状态。
- [ ] 用已知输入/缓存/输出用量和缺失用量场景验证可追溯计算与后台显示，并记录少量必要的真实官方 API 核验结果及支出。

## 验证与完成证据

- 在供应商边界使用受限替身，验证正常、缺失、错误和延迟用量，不用输出文字长度代替真实用量。
- 真实调用仅做针对性小样本，区分隔离替身与 live 证据；后续发布核验优先复用有效证据，避免无意义重复调用。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增产品决策。真实官方核验需要有效官方 API 配置与可用余额；先安全核查现有配置，不输出凭据。配置缺失时可完成隔离实现，真实计量能力仍须明确标为待核实。

## 实施边界与交接

本票是请求到后台成本查询的完整路径，先完成兼容扩展；07、08 再接积分预留与扣分。成本与扣分是独立事实，元数据契约供后续共用。
