# 08: 文件润色接入同一积分计量与结算

**What to build:** 文件润色沿用阶段会话同一套积分预留、实际用量结算与状态展示；完成生成后无论是否应用结果都计算真实消耗，普通手工文件操作继续免费。

**Blocked by:** [07：四环阶段会话预留积分并按实际用量结算](07-conversation-credit-reservation.md)

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、4–8、11；测试决策 1–4。

**覆盖用户故事：** 25、26、45、46。

## 验收标准

- [ ] 润色发出真实请求前使用共用账号授权、预算与原子预留，余额不足不访问上游并保留用户输入或待处理内容。
- [ ] 可靠用量按实际人民币成本 × 2000 结算，赠送优先、购买其次，释放剩余预留；不采用、关闭或稍后查看已生成润色结果不撤销已发生的正常消耗。
- [ ] 润色与阶段会话并发时使用同一账号余额和来源账本，不建立独立免费额度、扣费口径或可绕过预留的入口。
- [ ] 润色结果附近明确显示本次预留、实耗、待核对或免单状态；账号冻结总额与本次费用分开，个人中心可追踪相关文件或会话来源。
- [ ] 缺失可靠用量进入同一持久待核对状态；停止与错误保留共用契约供 09 完善，恢复与到期由 10 完成。
- [ ] 手工编辑、保存、查看、下载和不调用模型的上下文管理不扣分；既有文件写入确认、修订来源、权限及上下文授权保持不变。
- [ ] 核查其他仍存在的真实模型入口：使用同一计量与结算契约，或记录其明确归属与补齐结果，不留下隐藏免费调用。

## 验证与完成证据

- 从润色操作到结果显示、选择不应用和个人流水完成验证，确认正常生成成本不会因不采用而消失。
- 并发发起润色与对话，验证共享余额守恒；回归受影响的文件写入确认、账号隔离和免费手工操作。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。
