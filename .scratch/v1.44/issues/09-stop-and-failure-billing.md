# 09: 主动停止按可靠用量结算，生成故障免单

**What to build:** 用户主动停止生成时按可靠的已发生用量结算；网站或供应商故障导致生成失败时立即免单并释放预留。对话与润色显示一致的结果，后台保留网站承担的真实成本。

**Blocked by:** [08：文件润色接入同一积分计量与结算](08-polish-credit-settlement.md)

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 4–8、10、11；测试决策 1–5。

**覆盖用户故事：** 39、40、71。

## 验收标准

- [ ] 对话和润色主动停止后，有可靠用量按当次实际成本扣分并释放未用预留；没有可靠用量且未明确故障免单时转入持久待核对，不猜测补扣。
- [ ] 网站或供应商故障导致生成失败时首版不向用户扣分，立即释放该调用预留，不等 24 小时期限；已发生的供应商成本仍保留。
- [ ] 区分主动停止、供应商错误、网站错误、浏览器断开及结果未知；不把网页断开直接视为上游已停止或用量为零，依据实际请求状态与可靠计量处理。
- [ ] 重复取消、取消与正常结束竞争、迟到用量、错误重试及结算写入失败不会重复扣费、重复释放或将已明确免单的调用改为付费。
- [ ] 明确故障免单后获得的新证据只补充网站成本，不追扣用户；其他并行调用的预留不受该次释放影响。
- [ ] 回复/润色结果附近、账号冻结余额、个人流水与后台调用状态一致，用户能区分停止按实结算、免单与待核对。
- [ ] 持久状态可在页面关闭和进程恢复后查询，重试取得原有最终结果；未终结的核对任务由 10 处理。

## 验证与完成证据

- 在外部供应商边界控制停止、断流、错误及迟到用量，从两个应用入口分别验证账单和状态。
- 覆盖请求前、上游调用后、结算写入中与响应丢失等关键边界，核对一次扣分或免单的唯一结果和资金守恒。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

无新增输入；可靠停止计量条件复用 06 的实测结论，无法恢复的用量进入已定待核对规则。
