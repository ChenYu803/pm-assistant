## 验收标准

- [x] 注册验证码为 6 位数字、10 分钟有效、60 秒后可重发；服务端校验邮箱与用途，成功使用后失效，明确重发后的单一有效性规则，旧码不能绕过验证。
- [x] 只有验证成功才创建正常可用新账号；保留邮箱规范化、密码安全存储和重复邮箱约束，重复提交不会重复建号。
- [x] 注册数量不设产品配额、不强制填写邀请码，也不因单纯注册赠送积分；本票先交付不填赠送码的完整注册路径，选填兑换由 05 接入。
- [x] 提供密码找回页面与完整重置流程；找回码不能用于注册或其他邮箱，错误、过期、已使用验证码及重发均有明确反馈。
- [x] 正常登录不重复索取验证码；不增加手机验证或常驻人机验证。发送、验证失败次数与异常请求由服务端限流，不能仅靠前端倒计时。
- [x] 邮件缺少配置或投递失败时不伪装为成功；生产响应与日志不泄露验证码或凭据，测试邮件替身仅在隔离环境启用。
- [x] 通过增量升级保留旧账号和项目资料，不强制重新注册，不虚构旧账号已经完成邮箱验证。
- [ ] 实际核实发信供应商、身份及必要配置，取得少量真实注册和找回收信证据；未取得证据时明确待核实项，不将替身结果标为真实投递通过。

## 验证与完成证据

- 从浏览器与应用 API 验证注册、登录、找回、错误/过期码、用途隔离、重发间隔、重复注册和限流。
- 使用隔离邮件边界与受限时间控制验证失败和到期；保留旧账号登录与资料可读的回归证据。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。
