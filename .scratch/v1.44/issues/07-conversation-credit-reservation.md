# 07: 四环阶段会话预留积分并按实际用量结算

**What to build:** 四环阶段会话在发出真实模型请求前预留积分，正常回复完成后按可靠实际成本结算并返还未用部分；用户实时看到账号可用与冻结总额、每次回复费用和个人流水。

**Blocked by:** [04：个人积分余额与有记录的管理员赠送、调整](04-credit-balances-admin-grants.md)；[06：官方模型用量、真实成本与故障可追溯](06-official-model-usage-cost.md)

**Status:** ready-for-agent

**Type:** task

**规格依据：** [v1.44 规格](../spec.md)；实现决策 1、4–8、10–12；测试决策 1–4。

**覆盖用户故事：** 19–24、30–38、45–50、70。

## 验收标准

- [ ] 上游请求前完成账号授权与原子预留，未预留成功不得访问供应商；管理员使用产品走同一检查与结算，不享受隐藏免费通道。
- [ ] 预留按实际发送的完整系统提示、历史和注入文件的保守输入费用，加受真实输出限制约束的最大输出费用，再乘 2000；无法确认的缓存命中不降低预留。
- [ ] 输入采用可靠计量或经验证的保守上界，不能用简单字符估算冒充精确 token 数；按操作合理设置输出预算，不静默截短长文。若不能建立可靠费用边界，记录限制、影响及最小修正方案，不宣称严格防透支。
- [ ] 正常完成按供应商可靠用量与当次价格计算实际人民币成本 × 2000，从预留中结算并仅释放未用部分；每轮回复结束即结算，不等会话关闭。保留小数，不逐笔上取整为 1 积分。
- [ ] 按可用赠送优先、购买其次预留与消费，来源可核对；不同会话可并行且共享账号余额，同一会话同时只允许一次生成。并发、重发及结算重试不能透支或重复执行。
- [ ] 零积分或不足支撑本次调用时不访问上游，保留输入并引导兑换或联系充值；不取消已获预留的调用。不调用模型的项目/迭代/会话创建、浏览、编辑、下载和上下文管理仍可使用。
- [ ] 工作台展示账号可用积分与全部未结算预留合计，涵盖其他会话；每条回复另显示本次预留、实耗或待核对状态，正常调用无逐次确认弹窗。个人中心余额和消耗流水与同一账本一致。
- [ ] 正常生成未获可靠用量时持久记录待核对并保留该笔预留，不凭估算扣分；用户其他可用积分仍可使用，后续恢复与到期由 10 完成。
- [ ] 调用、预留、结算及恢复所需状态持久化且事务一致；重启、刷新、切换会话或设备不会遗失预留与已结算结果，长模型请求不占用数据库长事务。
- [ ] 建立供 08–10 共用的调用与终态契约，包含可靠用量、取消/故障、待核对和幂等结果；删除业务对象后资金记录保留必要追溯快照。

## 验证与完成证据

- 从浏览器及应用入口验证零余额未访问上游、正常结算、赠送优先、混合来源、小数精度、完整输入和实际输出约束。
- 使用独立预期账单和真实并发请求验证共享余额、同会话互斥、重复提交、重启持久性及资金守恒；覆盖工作台与个人中心的刷新结果。
- 开工前按实际改动判级，按项目纪律选择验证；涉及账号权限、金额存储、并发或共享调用链时执行相应 L2 检查。以用户可观察行为与持久结果为依据，明确区分隔离测试、本机 live 和目标机证据。

## 产品经理在 Agent 开始前提供

无新增输入，复用 04 的账本与 06 的可靠计量和价格依据。

## 实施边界与交接

本票完成对话正常路径与持久待核对入口。08 覆盖润色，09 完善主动停止/故障，10 完成后台恢复与到期；计费中间状态不单独发布生产。
