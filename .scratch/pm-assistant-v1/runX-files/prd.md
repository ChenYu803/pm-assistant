# 校园二手交易平台 — MVP PRD

## 1. 概念

### 1.1 核心用户
本校在校大学生。

### 1.2 要解决的一件事
毕业季及日常清理与购买闲置物品时，不再依赖杂乱无序的微信群，通过网页平台实现商品发布、检索与站内沟通。

### 1.3 产品形态
响应式网页（支持手机端浏览器访问）。

### 1.4 商业模式
MVP 阶段纯信息撮合平台，不收取交易佣金；后续可探索置顶推广、认证标识等增值服务。

### 1.5 外部依赖声明
登录态：自研账号体系（手机号 + 验证码），不接第三方 OAuth（推断值）。
图片上传：自研存储，不接第三方云存储。
消息通知：站内轮询，不接推送 SDK。
无支付、无地图、无 AI 依赖。

## 2. Out of Scope

引用 需求分析.md「# 排除清单」：

- **物流配送** — 理由：线下当面交易场景为主，平台不介入物流环节，投入产出比低；取舍阶段：强烈
- **担保支付交易** — 理由：学校范围熟人社会，信任成本低，且涉及资金合规风险高，MVP 阶段不做；取舍阶段：强烈
- **移动 App（仅做网页）** — 理由：开发与维护成本高，响应式网页已满足校园移动端访问需求；取舍阶段：频率

另（功能范围中已确认排除）：
- 不做物流配送——平台不介入物流，仅做线下当面交易的撮合。
- 不做担保支付交易——纯信息撮合，不涉及任何资金流转。
- 不做移动 App——仅做响应式网页，支持手机端浏览器访问。

## 3. 页面清单

提取自 原型.md「## 页面清单」段原文（零转换）：

## 首页（广场流）

- **目的**：商品发现门户，集中展示在售商品，提供浏览、检索与分类筛选入口。
- **元素**：
  - 搜索栏（显示文案「搜索教材、台灯…」）：按关键词检索商品；结构性 UI 形态：搜索框
  - 分类导航（显示文案「全部 / 教材 / 数码 / 生活用品 / 衣物」）：按分类筛选商品；结构性 UI 形态：选项卡
  - 商品瀑布流（每张卡片显示：商品图、标题、价格、新旧程度）：展示在售商品；结构性 UI 形态：卡片流
  - 快捷入口（显示文案「发布 · 消息 · 我的」）：导航至发布、私聊、个人中心；结构性 UI 形态：侧边栏
- **操作**：
  - 输入关键词搜索：输入后回车 → 商品列表按关键词过滤
  - 点击分类：点击某个分类 → 商品列表按该分类过滤
  - 点击商品卡片：点击卡片 → 进入商品详情页
  - 点击快捷入口：点击「发布/消息/我的」 → 分别进入发布商品页 / 站内私聊页 / 个人中心页
- **入口·出口**：从任意页面通过顶部导航进入；可去往商品详情页、发布商品页、站内私聊页、个人中心页。
- **依赖**：在售商品列表数据（从发布商品页产生）；分类数据。

## 商品详情页

- **目的**：展示商品完整信息与卖家信息，作为发起交易（私聊）的入口。
- **元素**：
  - 商品大图（显示商品主图）：展示商品外观；结构性 UI 形态：图片展示区
  - 商品信息区（标题 / 描述 / 价格 / 分类 / 新旧程度）：完整描述商品；结构性 UI 形态：信息块
  - 卖家卡片（卖家昵称、是否在线，如「卖家：张三 · 在线」）：展示卖家状态；结构性 UI 形态：卡片
  - 发起私聊按钮（显示文案「发起私聊」）：发起与卖家的站内对话；结构性 UI 形态：按钮
- **操作**：
  - 点击「发起私聊」：点击按钮 → 进入与该卖家的站内私聊页；若未登录则先提示登录
  - 返回：点击返回 → 回到首页广场流
- **入口·出口**：从首页广场流点击商品卡片进入；可去往站内私聊页、首页。
- **依赖**：商品详情数据；卖家在线状态；登录态。

## 发布商品页

- **目的**：一步式填写并发布闲置商品信息，供其他学生浏览购买。
- **元素**：
  - 图片上传（显示文案「上传图片（最多 6 张）」）：上传商品图；结构性 UI 形态：上传区
  - 标题输入（显示文案「商品标题」）：填商品名称；结构性 UI 形态：输入框
  - 描述输入（显示文案「商品描述」）：填商品详细说明；结构性 UI 形态：多行输入框
  - 价格输入（显示文案「价格（元）」）：填售价；结构性 UI 形态：数字输入框
  - 分类选择（显示文案「请选择分类」）：选择商品所属分类；结构性 UI 形态：下拉选择
  - 新旧程度（显示文案「全新 / 九成新 / 七成新 / 有瑕疵」）：标注成色；结构性 UI 形态：单选组
  - 发布按钮（显示文案「发布」）：提交表单；结构性 UI 形态：按钮
- **操作**：
  - 点击「发布」：点击按钮 → 校验各项必填；通过则提交成功并跳转个人中心页（新商品状态「待出手」）；有必填项缺失则拦截并提示对应项
- **入口·出口**：从首页或个人中心点「发布」进入；提交成功则去往个人中心页；也可取消返回。
- **依赖**：登录态；分类数据；图片上传能力；发布成功后在首页与个人中心可见。

## 站内私聊页

- **目的**：买卖双方站内文字沟通，协商线下交易细节，保护双方真实联系方式。
- **元素**：
  - 对话窗口（显示历史消息列表）：展示往来消息；结构性 UI 形态：消息列表
  - 消息输入框（显示文案「输入消息…」）：输入待发消息；结构性 UI 形态：输入框
  - 发送按钮（显示文案「发送」）：发送当前输入内容；结构性 UI 形态：按钮
  - 对方状态（显示「在线 / 离线」）：提示对方当前在线与否；结构性 UI 形态：状态标签
- **操作**：
  - 输入并点击「发送」：点击按钮 → 文字消息追加到对话窗口
  - 返回：点击返回 → 回到来源页（商品详情页或首页）
- **入口·出口**：从商品详情页「发起私聊」进入；也可从个人中心「我的消息」进入；可返回来源页。
- **依赖**：会话双方在线状态；登录态；历史消息数据。

## 个人中心页

- **目的**：集中管理个人资料、我发布的商品、站内消息入口与交易评价记录。
- **元素**：
  - 用户信息（昵称、头像）：展示当前登录用户；结构性 UI 形态：信息卡片
  - 我的发布（显示文案「我发布的商品」）：查看自己发布的商品列表；结构性 UI 形态：列表入口
  - 我的消息（显示文案「站内消息」）：进入私聊会话列表；结构性 UI 形态：列表入口
  - 我的评价（显示文案「收到的评价」）：查看交易后他人对我的评价；结构性 UI 形态：列表入口
- **操作**：
  - 点击「我发布的商品」：进入我发布的商品列表页（可编辑/下架）
  - 点击「站内消息」：进入站内私聊页
  - 点击「收到的评价」：进入我的评价列表（可对被评交易进行互评）
- **入口·出口**：从首页「我的」快捷入口进入；可去往发布商品页、站内私聊页、我的评价列表。
- **依赖**：登录态；用户发布的商品数据；消息会话数据；评价数据。

## 4. 实体级数据模型

### 4.1 用户 User

#### 定义
平台注册用户，本校在校大学生。既是买家也是卖家。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|---|---|---|
| 昵称 | 短文本 | 展示用，默认生成 |
| 头像 | 引用（图片） | 可上传，默认头像 |
| 手机号 | 短文本 | 登录凭证，唯一（推断值） |
| 在线状态 | 枚举：在线 / 离线 | 控制私聊页对方状态标签 |

#### 状态机
无（在线状态为即时属性，不构成状态机）。

#### 关系
- 用户 1—N 商品（发布）
- 用户 1—N 评价（作为被评人 / 作为评价人）
- 用户 1—N 会话（参与）

---

### 4.2 商品 Product

#### 定义
学生发布的闲置商品，是平台核心内容单元。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|---|---|---|
| 标题 | 短文本 | 必填 |
| 描述 | 长文本 | 必填 |
| 价格 | 数字 | 必填，非负 |
| 分类 | 引用（Category） | 必填 |
| 新旧程度 | 枚举：全新 / 九成新 / 七成新 / 有瑕疵 | 必填 |
| 图片 | 引用（图片，1-6 张） | 必填至少 1 张，最多 6 张 |
| 发布人 | 引用（User） | 必填 |
| 状态 | 枚举：待出手 / 已下架 / 已售出 | 见状态机 |

#### 状态机
```
待出手 ──(发布者下架)──→ 已下架
待出手 ──(线下成交并标记)──→ 已售出
已下架 ──(发布者重新上架)──→ 待出手
```
> 推断值：下架后可重新上架；「已售出」由发布者在线下成交后手动标记。

#### 关系
- 商品 N—1 用户（发布人）
- 商品 N—1 分类
- 商品 1—N 会话（被私聊）
- 商品 1—N 评价（交易后评价）

#### 字段表

#### 状态机
无。

|---|---|---|

#### 状态机

#### 关系

- 会话 N—N 用户

#### 字段表
| 字段 | 业务级类型 | 说明 |
|---|---|---|
| 内容 | 长文本 | 必填 |
| 发送方 | 引用（User） | 必填 |
| 所属会话 | 引用（Conversation） | 必填 |
| 发送时间 | 日期时间 | 必填 |

#### 状态机
无。

#### 关系
- 消息 N—1 会话
- 消息 N—1 用户（发送方）

### 4.6 评价 Review

#### 定义
一笔线下交易完成后，双方互评以积累信用。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|---|---|---|
| 被评人 | 引用（User） | 必填 |
| 评价人 | 引用（User） | 必填 |
| 评分 | 数字（1-5 星） | 必填（推断值） |
| 文字评论 | 长文本 | 可选 |
| 关联商品 | 引用（Product） | 必填 |
| 是否已评 | 枚举：未评 / 已评 | 控制评价按钮显隐 |

#### 状态机
```
未评 ──(提交评价)──→ 已评
```
> 推断值：一笔交易仅可评价一次。

#### 关系
- 评价 N—1 用户（被评人）
- 评价 N—1 用户（评价人）
- 评价 N—1 商品

## 5. 用户流程 + 验收标准

提取自 原型.md「## 用户流程」段原文（零转换）：

## 用户流程：搜索并购买商品

- **触发**：学生用户有购买需求，通过网页平台寻找二手教材、生活用品等。
- **主路径**：进入首页（广场流）→ 浏览商品瀑布流 或 输入关键词搜索 或 按分类筛选 → 点击目标商品卡片进入商品详情页 → 查看商品信息与卖家状态 → 点击「发起私聊」进入站内私聊页 → 与卖家文字沟通、约定线下面交 → 线下成交。
- **异常分支**：
  - 搜索/筛选结果为空 → 展示空态提示「没有找到相关商品，试试其他关键词」+ 提供「去发布一件」入口
  - 卖家离线 → 私聊页展示对方「离线」，可留言，对方上线后可见
- **边界情况**：未登录时点「发起私聊」→ 拦截并提示登录；商品已被下架 → 详情页提示「该商品已不再出售」。

#### 验收标准
1. 当进入首页 → 系统展示在售商品瀑布流（每张卡片含商品图、标题、价格、新旧程度）→ 商品均可点击进入详情页。
2. 当输入关键词搜索或点击分类 → 系统按关键词或分类过滤商品列表 → 仅展示匹配商品。
3. 当搜索或筛选结果为空 → 系统展示空态「没有找到相关商品，试试其他关键词」+「去发布一件」入口 → 用户可跳转发布页。
4. 当已下架或已售出商品尝试访问 → 系统在详情页提示「该商品已不再出售」→ 不展示私聊入口。
5. 当点击「发起私聊」且未登录 → 系统拦截并提示登录 → 不进入私聊页。

## 用户流程：发布闲置商品

- **触发**：学生用户有闲置物品（毕业季清理、日常出二手）需要出售。
- **主路径**：进入首页或个人中心 → 点击「发布」进入发布商品页 → 一步式填完（图片 / 标题 / 描述 / 价格 / 分类 / 新旧程度）→ 点击「发布」提交 → 表单校验通过 → 跳转个人中心页，看到新发布的商品（状态「待出手」）；该商品同步出现在首页广场流。
- **异常分支**：
  - 未填必填项（如无图、无标题、无价格）→ 拦截提交并提示对应字段
  - 图片超过 6 张 → 提示「最多上传 6 张图片」并禁止继续上传
- **边界情况**：重复点击「发布」→ 提交后按钮置灰防止重复提交；网络失败 → 提示「发布失败，请重试」且保留已填内容。

#### 验收标准
1. 当从首页或个人中心点击「发布」→ 系统进入发布商品页 → 展示全部必填字段（图片/标题/描述/价格/分类/新旧程度）。
2. 当填写完整并点击「发布」→ 系统校验通过 → 提交成功，跳转个人中心页，新商品状态「待出手」并同步出现在首页广场流。
3. 当存在必填项缺失（无图/无标题/无价格）→ 系统拦截提交并提示对应字段 → 不提交成功。
4. 当尝试上传超过 6 张图片 → 系统提示「最多上传 6 张图片」→ 禁止继续上传。
5. 当重复点击「发布」→ 系统将按钮置灰防止重复提交 → 不产生重复商品。
6. 当提交时网络失败 → 系统提示「发布失败，请重试」→ 保留已填内容不丢失。

## 用户流程：交易后评价

- **触发**：一笔线下交易完成后，双方建立互评以积累信用。
- **主路径**：进入个人中心 → 点击「收到的评价」→ 在已完成交易列表中选择一笔 → 对对方进行打分 + 文字评论 → 提交评价 → 信用值更新，评价出现在对方「收到的评价」中。
- **异常分支**：
  - 对同一笔交易重复评价 → 已评价的交易不再显示评价按钮，仅可查看
- **边界情况**：评价列表为空 → 展示空态提示「还没有评价，去完成一笔交易吧」；评价提交加载失败 → 提示「评价提交失败，请重试」。

#### 验收标准
1. 当进入个人中心「收到的评价」→ 系统展示我收到的评价列表 → 每笔已评交易可查看评分与文字评论。
2. 当在已完成交易列表中选中一笔未评价交易 → 系统展示评价表单（1-5 星 + 文字评论）→ 提交后评价出现在对方「收到的评价」中。
3. 当对同一笔交易重复评价 → 系统不再显示评价按钮，仅可查看 → 不产生重复评价。
4. 当评价列表为空 → 系统展示空态「还没有评价，去完成一笔交易吧」。
5. 当评价提交加载失败 → 系统提示「评价提交失败，请重试」→ 保留已填评分与文字。

### 补充流程：管理我的发布（源自原型「可编辑/下架」，推断扩展）

#### 验收标准
1. 当进入个人中心「我发布的商品」→ 系统展示我发布的商品列表及其状态（待出手/已下架/已售出）。
2. 当对「待出手」商品点击下架 → 系统将状态改为「已下架」→ 商品从首页广场流消失，仅自己可见。
3. 当对「已下架」商品点击重新上架 → 系统将状态改回「待出手」→ 商品重新出现在首页广场流。
4. 当对「待出手」商品点击编辑 → 系统进入编辑页并预填原信息 → 保存后更新商品并在首页同步展示。

## 6. 文案基调

**语气**：校园化、亲切、口语化，面向学生，避免生硬商业腔。

**示例**：
- 搜索栏占位：「搜索教材、台灯…」
- 空态提示：「没有找到相关商品，试试其他关键词」「还没有评价，去完成一笔交易吧」
- 错误提示：「发布失败，请重试」「最多上传 6 张图片」

**命名约定**：
- 快捷入口：「发布 · 消息 · 我的」
- 分类：「全部 / 教材 / 数码 / 生活用品 / 衣物」
- 商品状态：「待出手 / 已下架 / 已售出」
