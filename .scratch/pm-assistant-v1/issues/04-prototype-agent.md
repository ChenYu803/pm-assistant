# 04 — 原型 Agent（新 Agent 全栈）

**What to build:** 原型阶段完整闭环：用户在需求分析完成后打开「原型」tab（自动加载 需求分析.md），原型 Agent 以提案式访谈（先给方案再问）产出页面清单 + 用户流程的结构化文本；对话中声明并输出单文件 HTML 原型快照，前端提供「下载 HTML 原型」按钮（浏览器可打开，HTML 是可视化媒介、不进文件树、不参与交付）；用户指正后每轮修订都重新生成 HTML 快照；用户显式确认「完满」（肯定词校验）后原型.md 整文件写入并出现在文件树。

**Blocked by:** 02 — Agent 类型基础设施

**Status:** ready-for-agent

- [ ] 原型 tab 创建时自动加载 需求分析.md（存在时）
- [ ] 对话为提案式访谈：先给方案再问，非诘问式
- [ ] Agent 主动声明可生成 HTML 原型；对话内输出 HTML 快照，前端提供下载按钮，下载后浏览器可打开
- [ ] 用户提出修改后：结构化文本修订 + HTML 快照重新生成（确认闭环）
- [ ] 用户「完满」确认（肯定词）前不写入文件；确认后原型.md 整文件替换写入
- [ ] 原型.md 内容 = 页面清单（目的/元素/操作/入口出口/依赖）+ 用户流程，出现在文件树、可下载/预览/编辑
- [ ] 验证脚本覆盖原型环节（提案 → 快照可下载 → 冻结 → 落盘断言）

**备注：** 产品设计浓度最高的 ticket——开始前需与用户开 PM 决策 mini 会，拍板：提案的呈现粒度与候选数量、「完满」的判定标准、结构化文本的字段粒度、对话中指正的定位方式。冻结校验复用现有肯定词机制（不新增协议标记）。
