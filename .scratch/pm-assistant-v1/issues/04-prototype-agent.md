# 04 — 原型 Agent（新 Agent 全栈）

**What to build:** 原型阶段完整闭环：用户在需求分析完成后打开「原型」tab（自动加载 需求分析.md），原型 Agent 以提案式访谈（先给方案再问）产出页面清单 + 用户流程的结构化文本；对话中声明并输出单文件 HTML 原型快照，前端提供「下载 HTML 原型」按钮（浏览器可打开，HTML 是可视化媒介、不进文件树、不参与交付）；用户指正后每轮修订都重新生成 HTML 快照；用户显式确认「完满」（肯定词校验）后原型.md 整文件写入并出现在文件树。

## Comments

### Mini 会决策记录（2026-08-07，已逐条拍板；借鉴 /prototype skill——原型 = 回答问题的可丢弃媒介，HTML 快照形态参考其 LOGIC 分支「领域语言 + 当前状态 + 自由玩/引导演练」）

1. **提案粒度 = 每轮 1 个方案**，用户指正后修订重给。新手 MVP 要低信息量 + 强流程的清晰度，不做多候选对比（skill 的 3 变体惯例被否，理由：目标用户是新手）；页面级候选粒度留给未来的新手/老手模式切换。
2. **「完满」判定 = Agent 自检清单（相对客观）+ 用户亲口确认 + 写入前弹「确定」按钮**：「走通」是主观概念，Agent 冻结前先做客观自检（页面清单覆盖需求分析结论、主路径 + 异常分支齐全）并展示结果；用户肯定词确认后，原型.md 整文件写入前复用需求分析.md 的确认弹窗（用户亲手点确定）。
3. **字段粒度 = 结构不动（spec 定稿五字段）+ 内容写满 + UI 形态进 / 视觉不进 + 显示文案进**：五字段「目的/元素/操作/入口·出口/依赖」是 PRD 第 3 章结构契约不动（05 才定稿 PRD 模板，原型.md 是先例不是迁就方）；内容深度拉满（元素列全、操作写清触发方式+去向+反馈、用户流程覆盖主路径+异常分支+边界情况）；结构性 UI 形态（卡片/列表/侧边栏/主操作位置）进，视觉细节（配色/字体/圆角/动效）不进——ADR-0002 逻辑类推（读者是 AI，视觉零价值，视觉交给 HTML 快照媒介）；显示文案是「元素」条目内部的内容深度（表头不动、格子写满），非结构改动。
4. **指正定位 = 自由定位**：Agent 自行判断指正是局部修订（动相关部分 + 重生成快照）还是方向调整（重提方案），不做定位限制。

**范围说明：** 原 ticket 范围 + 前端「下载 HTML 原型」按钮（Blob 下载，不新增存储/API）、chat route 冻结执法从 mvp_prd 特判泛化到 prototype、verify-protocols.mjs 断言覆盖 prototype 新协议。
