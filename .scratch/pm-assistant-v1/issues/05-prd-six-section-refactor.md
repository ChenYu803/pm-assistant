## Comments

### Mini 会决策记录（2026-08-08，已逐条拍板；prompt 重写大幅参考 to-spec skill——被验证的优秀范本，九条原则照抄级吸收）

1. **业务规则 grilling = 补缺式走查**：按实体清单逐个问「需求分析/原型未覆盖」的规则点，每实体 ≤2 问封顶（对齐 03 轻量精神）。to-spec「不访谈、纯综合」→ grilling 是流程里唯一提问环节，只补缺口不重挖需求。
2. **外部依赖识别 = Agent 推断**：Agent 从需求分析推理候选依赖 → 对照常见类别（支付/登录/消息通知/地图/云存储/AI）自检防漏 → 候选清单用户一次性确认 → 概念章单源声明。
3. **验收标准粒度 = 维持 spec 原文**：三段式「当 X → 系统 Y → 结果 Z」+ 每条 3-5 条上限。先做出来看效果，不行再迭代（spec US26 不动）。
4. **概念版落盘（升级 spec US28「不写入文档」）**：概念版不丢，写进文件树可回看，但**不可加载进 Agent 上下文**（context panel 排除——AI 永远只读 prd.md 单源）；写入前弹显式确认框（复用需求分析.md 确认弹窗路径）。此设计化解 ADR-0003「双重身份破坏单源」：人回看存档与 AI 单源两不相扰。

**to-spec 吸收清单（照抄级，写入 MVP_PRD_PROMPT）**：① 不访谈纯综合（二次确认不重挖）② 领域词汇不发明新词 ③ 接缝前置（验收标准 = 执行者唯一自检接缝）④ 用户故事格式「作为一个 \<角色\>，我想要 \<功能\>，以便 \<收益\>」⑤ extensive 覆盖所有方面（用户故事撰写职责）⑥ 禁文件路径/代码片段（字段用业务级类型）⑦ 原型决策编码内嵌零转换 + trim 到决策富集部分 ⑧ 只测外部行为 ⑨ 即产即发（六章齐全 + 冻结后一次写入，不二次评审）。
