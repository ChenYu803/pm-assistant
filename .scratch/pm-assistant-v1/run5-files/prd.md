# 校园二手交易平台 — MVP PRD

## 1. 概念

### 1.1 核心用户
本校在读大学生（本科生及研究生），毕业季/学期末集中清理闲置，或日常买卖二手教材与生活用品。

### 1.2 要解决的一件事
用有检索、有结构化流程、有信任评价的网页平台，取代低效且无信任的微信群二手交易。

### 1.3 产品形态
Web 网页版（响应式布局，兼容手机/平板/电脑浏览器）。

### 1.4 商业模式
MVP 阶段免费，不设交易抽成；后续可引入付费置顶、竞价排名等增值服务（推断值）。

### 1.5 外部依赖声明
- 图片上传存储走第三方云存储（如对象存储服务，OBS/COS/S3），不自研存储
- 用户登录采用学校统一身份认证（CAS），不自建账号体系（推断值）
- 消息通知为纯站内消息（应用内轮询），不自研实时推送通道（推断值）
- 支付、地图、AI 均不涉及，本轮无相关依赖

## 2. Out of Scope

### 2.1 排除清单（引自 需求分析.md）
- 物流配送 — 理由：校园二手交易以当面交易为主，配送成本高且价值低；取舍阶段：频率（低频）
- 担保交易 — 理由：涉及资金托管与支付体系，复杂度高，MVP 阶段不引入；取舍阶段：强烈（非核心需求）
- 移动 App — 理由：网页版已能满足使用场景，降低开发成本；取舍阶段：强烈（非核心需求）

### 2.2 功能范围中的「不做 Y」排除项
- 不搞物流配送 — 校园二手交易典型场景为同校当面交易，配送成本高且平台价值低
- 不做担保交易 — 涉及资金托管与支付体系，复杂度高，MVP 阶段不引入
- 不做移动 App — 只做网页版，降低开发成本，方便用户在电脑或手机浏览器上直接使用

### 2.3 P2 暂缓功能（本轮不实现）
- 商品收藏（商品详情页「收藏」按钮为占位，不触发任何行为）
- 个人主页展示历史发布（不在 MVP 页面范围内）

### 2.4 其他推断排除项（推断值）
- 不做第三方登录（除学校 CAS 外不接微信/QQ 等登录方式）
- 不做图片压缩处理（原图直传云存储）
- 不做消息已读/未读状态 — 只展示会话列表与最后消息，不区分已读未读（推断值）
- 不做举报/违规内容治理功能 — MVP 阶段不引入内容审核机制（推断值）

## 3. 页面清单

### 首页 · 商品广场

- **目的**：平台统一入口，让买家快速浏览、搜索并进入感兴趣的商品
- **元素**：
  - 搜索框（「搜索教材、生活用品…」）：通过关键词搜索商品；搜索框为居中置顶的表单式输入条
  - 分类导航（教材/数码/生活/其他）：按分类筛选商品列表；横向标签式导航
  - 商品卡片列表（每张卡显示 图片·标题·价格·新旧程度·交易地点）：展示在售商品，点击进入详情；卡片式列表
  - 「+ 发布闲置」按钮：进入商品发布页；页角悬浮按钮
  - 「消息」入口（信封图标）：进入消息页；顶栏图标式入口
- **操作**：
  - 搜索/点分类：在输入框输入关键词或点分类标签 → 列表实时刷新展示匹配商品
  - 点商品卡片：点击卡片 → 进入该商品详情页
  - 点「+ 发布闲置」：点击 → 进入商品发布页
  - 点「消息」图标：点击 → 进入消息页
- **入口·出口**：平台默认落地页，用户登录即到；可前往商品详情页、商品发布页、消息页
- **依赖**：依赖商品数据库（商品标题、价格、图片、分类、新旧、地点）；搜索依赖关键词索引

### 商品详情页

- **目的**：展示单件商品的完整信息，驱动买家发起站内私聊
- **元素**：
  - 商品大图（占位图「商品图片」）：查看商品外观；顶部大图展示区
  - 标题与价格（「高数教材 第7版」「¥15」）：核心交易信息；标题下紧跟价格的一体式信息区
  - 商品信息（新旧程度·交易地点·详细描述）：了解商品状况与交易位置；信息条目式排列
  - 卖家信息（头像·昵称）：识别卖家身份；头像+昵称的紧凑条目
  - 「私聊卖家」按钮：发起站内私聊；主操作按钮
  - 「收藏」按钮（P2 暂缓，仅占位）：标记感兴趣，本轮不实现
- **操作**：
  - 点「私聊卖家」：点击 → 跳转消息页并新建/进入与该卖家的会话
  - 点「收藏」：占位，本轮不触发
- **入口·出口**：从首页商品卡片点击进入；可返回首页、可前往消息页
- **依赖**：依赖该商品的数据（图片、价格、信息、卖家）；依赖卖家的用户信息

### 商品发布页 · 单页一步表单

- **目的**：让卖家在单页表单内一步填完信息，快速上架闲置商品
- **元素**：
  - 标题输入（「商品标题」）：必填，一句话描述；单行输入框
  - 描述输入（「详细描述…」）：补充商品情况；多行输入框
  - 价格输入（「价格（元）」）：必填，数字；单行输入框
  - 图片上传（「+ 添加图片」）：最多 5 张，支持一次选多张；带加号的上传区
  - 新旧程度选择（全新/较新/一般/旧）：单选；单选按钮组
  - 交易地点（「如：东区食堂门口」）：建议填写；单行输入框
  - 「发布上架」按钮：一次性提交全部信息；底部主操作按钮
- **操作**：
  - 填写并点「发布上架」：点击 → 信息完整则发布成功，返回首页且新商品出现在列表顶部，并出现「发布成功」提示；信息不完整则提示「请填写标题和价格」并停留在本页
- **入口·出口**：从首页「+ 发布闲置」进入；发布成功后返回首页
- **依赖**：依赖买家填写表单；依赖商品数据库与图片上传存储

### 消息页 · 站内私聊

- **目的**：买卖双方站内私聊协商线下交易，交易完成后发起互评（P1）
- **元素**：
  - 会话列表（每条显示 对方昵称·商品标题·最后消息）：选择要回复的对话；列表式会话栏
  - 聊天窗口（历史消息气泡列表）：查看往来消息；气泡式对话区
  - 输入框与发送按钮（「输入消息…」「发送」）：回复对方；底部输入条+按键
  - 「完成交易·去评价」按钮：交易完成后进入互评（P1）；会话内操作按钮
- **操作**：
  - 点会话：点击列表项 → 切换对应聊天窗口
  - 输入并发送：输入文字点「发送」或回车 → 消息出现在窗口并同步给对方
  - 点「完成交易·去评价」：点击 → 进入互评流程（P1，本轮为入口占位）
- **入口·出口**：从首页「消息」图标进入，或从详情页「私聊卖家」带会话进入；可返回首页、可进入评价（P1）
- **依赖**：依赖会话数据（双方用户、关联商品、消息记录）；「去评价」依赖交易完成状态与 P1 评价功能

## 4. 实体级数据模型

### 4.1 用户

#### 定义
通过学校统一身份认证（CAS）登录的本校学生。CAS 仅用于身份认证，不直接作为展示资料；登录后引导设置昵称与头像（可跳过，跳过则使用默认昵称与默认头像）（推断值）。

#### 字段表
| 字段 | 类型 | 说明 |
|------|------|------|
| 用户ID | 引用 | 关联 CAS 认证身份，系统内唯一标识 |
| 昵称 | 文本 | 展示用，首次登录可设置或跳过（推断值） |
| 头像 | 图片 | 展示用，首次登录可设置或跳过（推断值） |

#### 状态机
无内部状态变更。同一用户身份自登录起即为有效状态，无禁用/封禁概念（推断值）。

#### 关系
- 一对多：一个用户可发布多件商品
- 一对多：一个用户可参与多个会话

### 4.2 商品

#### 定义
卖家发布的闲置物品，包含完整交易信息（标题、描述、价格、图片、新旧程度、交易地点）。发布后在首页广场与搜索结果中可被浏览。

#### 字段表
| 字段 | 类型 | 说明 |
|------|------|------|
| 商品ID | 数字 | 系统内唯一标识 |
| 发布者 | 引用 | 关联卖家用户 |
| 标题 | 文本 | 必填，一句话描述 |
| 描述 | 文本 | 补充商品情况 |
| 价格 | 数字 | 必填，单位：元 |
| 图片 | 图片列表 | 最多 5 张，存云存储 |
| 分类 | 枚举 | 教材 / 数码 / 生活 / 其他 |
| 新旧程度 | 枚举 | 全新 / 较新 / 一般 / 旧 |
| 交易地点 | 文本 | 建议填写，展示为「卖家发布时指定的面交地点」（推断值） |
| 状态 | 枚举 | 在售 / 已下架（推断值） |

#### 状态机
```
草稿（发布表单填写中，未提交）
  ↓ 点「发布上架」且信息完整
在售
  ↓ 卖家点「下架」
已下架
```
注：已下架商品不再出现在首页广场与搜索结果中；已产生的会话保留，会话内仍可见商品标题与链接，但商品详情标注「已下架」；不做物理删除（推断值）。

#### 关系
- 多对一：多件商品归属于一个卖家用户
- 一对多：一件商品可关联多个会话（不同买家私聊同一商品）

### 4.3 会话

#### 定义
买卖双方针对特定商品发起的站内私聊对话。买家从商品详情页点「私聊卖家」时创建或进入。

#### 字段表
| 字段 | 类型 | 说明 |
|------|------|------|
| 会话ID | 数字 | 系统内唯一标识 |
| 买家 | 引用 | 发起私聊的用户 |
| 卖家 | 引用 | 商品的发布者 |
| 关联商品 | 引用 | 会话所针对的商品 |
| 创建时间 | 时间 | 会话创建时刻 |
| 最近消息时间 | 时间 | 最后一条消息的时刻；用于列表排序（推断值） |

#### 状态机
无独立状态变更（推断值）。会话随消息往来持续存在，无关闭/归档机制；商品下架不影响已存在会话。

#### 关系
- 多对一：一个会话与一个商品关联
- 一对二：一个会话恰有买卖双方两名参与者
- 一对多：一个会话含多条消息

### 4.4 消息

#### 定义
会话内的单条站内私聊消息，由会话参与者发送。

#### 字段表
| 字段 | 类型 | 说明 |
|------|------|------|
| 消息ID | 数字 | 系统内唯一标识 |
| 会话ID | 引用 | 所属会话 |
| 发送者 | 引用 | 发送消息的用户 |
| 内容 | 文本 | 消息正文 |
| 发送时间 | 时间 | 消息发出时刻 |

#### 状态机
```
发送中（用户点「发送」）
  ↓ 成功
已发送（出现在双方聊天窗口）
  ↓ 失败
发送失败（提示「发送失败，请重试」，内容保留在输入框）
```
注：发送按钮在消息发出后 0.5 秒内置灰，防止重复提交（推断值）；不做已读/未读状态（推断值）。

#### 关系
- 多对一：多条消息归属于一个会话
- 多对一：多条消息归属于一个发送者

## 5. 用户流程 + 验收标准

### 用户流程：买家浏览并协商交易

- **触发**：本校学生在首页商品广场，想找需要的二手教材或生活用品
- **主路径**：进入首页商品广场 → 在搜索框输入关键词或点分类浏览商品列表 → 点击感兴趣的卡片进入商品详情页 → 点「私聊卖家」进入消息页会话 → 与卖家协商价格与见面地点 → 约定线下当面交易，交易完成
- **异常分支**：
  - 搜索结果为空：列表显示「没有找到相关商品，换个关键词试试」，用户换词或换分类再搜
  - 卖家未在线/未回复：买家在会话中留言，卖家上线后回复，流程继续
- **边界情况**：搜索关键词无匹配、会话列表为空态（显示「暂无消息」）、交易地点为空需互相确认

#### 验收标准

1. 当我在首页搜索框输入关键词 → 系统展示标题或描述匹配关键词的在售商品列表 → 列表实时刷新
2. 当我点击分类标签 → 系统展示该分类下在售商品列表 → 列表实时刷新；关键词+分类同时使用时按双重条件过滤
3. 当搜索无任何匹配 → 系统显示「没有找到相关商品，换个关键词试试」→ 不展示商品卡片
4. 当我点击商品卡片 → 系统展示该商品完整详情（大图、标题、价格、新旧、地点、描述、卖家信息）
5. 当我点「私聊卖家」→ 系统跳转至消息页并新建/进入与该卖家的会话 → 会话关联该商品
6. 当我没有与任何人有过消息往来 → 会话列表显示空态「暂无消息」
7. 当我与多个卖家有会话 → 会话列表按最近一条消息时间倒序排列（推断值）；无消息会话按创建时间倒序插入
8. 当我发送的消息因网络异常失败 → 系统提示「发送失败，请重试」→ 内容保留在输入框不丢失

### 用户流程：卖家发布并成交

- **触发**：本校学生（毕业季/学期末）想清理闲置物品，在首页点「+ 发布闲置」
- **主路径**：进入商品发布页 → 在单页表单内一步填完标题/描述/价格/图片/新旧/地点 → 点「发布上架」→ 发布成功返回首页，新商品出现在列表顶部 → 收到买家私聊，在消息页回复协商 → 约定线下当面交易 → 交易完成后双方进入互评（P1）
- **异常分支**：
  - 发布信息不完整：发布页提示「请填写标题和价格」，补齐后再提交
  - 图片上传失败/超 5 张：提示「最多上传 5 张图片，请调整后重试」
- **边界情况**：表单必填项校验、图片数量上限校验、发布后商品立即可见

#### 验收标准

1. 当我填写完整表单并点「发布上架」→ 系统创建商品并返回首页 → 新商品出现在列表顶部，显示「发布成功」提示
2. 当我未填写标题或价格即提交 → 系统提示「请填写标题和价格」→ 不创建商品，停留在发布页
3. 当我上传超过 5 张图片 → 系统提示「最多上传 5 张图片，请调整后重试」→ 第 6 张及以后不被接受
4. 发布成功的商品立即可在首页广场与搜索/分类结果中看到
5. 当我下架自己的在售商品 → 系统从首页广场与搜索结果中移除该商品 → 商品详情标注「已下架」，原会话内容与商品标题、链接仍可见（推断值）
6. 当我看到会话中的「完成交易·去评价」按钮并点击 → 按钮为 P1 入口占位，本轮不触发评价流程

### 用户流程：登录与身份识别（推断值）

- **触发**：本校学生首次访问平台，或未登录状态下尝试使用发布/私聊功能
- **主路径**：首次访问平台 → 通过学校 CAS 统一认证登录 → 引导设置昵称与头像（可跳过）→ 进入首页商品广场 → 浏览、发布或私聊
- **异常分支**：
  - CAS 认证失败/超时：停留在登录引导，提示重新认证
  - 登录中断：返回平台后需重新登录，原意图操作需重新发起
- **边界情况**：设置昵称与头像可跳过；跳过则使用默认昵称与默认头像

#### 验收标准

1. 当我未登录访问首页 → 可浏览商品列表与详情，但点「私聊卖家」或「+ 发布闲置」→ 系统先引导登录 → 登录成功后回到原意图操作
2. 当我首次登录成功 → 系统引导设置昵称与头像 → 我可选择跳过 → 跳过则使用默认昵称与默认头像（推断值）
3. 我设置的昵称与头像展示在商品详情「卖家信息」与消息会话列表中（推断值）
4. 当 CAS 认证失败或超时 → 显示认证失败提示 → 留在登录引导页，不进入平台

## 6. 文案基调

**语气**：亲切、接地气的校园口吻，简短直白，不官方不冷硬。

**示例**：
- 发布成功：「发布成功！你的闲置已经上架啦」
- 搜索无结果：「没有找到相关商品，换个关键词试试」
