# 校园二手交易平台 — MVP PRD

## 1. 概念

### 1.1 核心用户
在校大学生（买卖双方均为本校学生）。

### 1.2 要解决的一件事
提供一个比微信群刷屏更高效、可检索、可沉淀信用评价的二手闲置商品交易平台，支持线下当面交易。

### 1.3 产品形态
网页版（Web）。

### 1.4 商业模式
暂无直接盈利（校内信任场景以规模优先）；预留信息流广告位与付费置顶作为后续变现方向（推断值）。

### 1.5 外部依赖声明
无（登录走平台账号体系，不上第三方 SDK；无支付、无地图、无云存储依赖——图片上传走平台自身存储，不依赖外部 AI/推送服务）。

---

## 2. Out of Scope

以下为本版本明确排除的范围：

**需求分析.md 排除清单**：
- **物流配送** — 理由：校园交易均为面对面，商品单价低物流成本不经济，且平台不做担保交易，物流意义不大。取舍阶段：强烈。
- **担保交易（平台代收代付）** — 理由：需要接入支付牌照与复杂风控，学生交易金额小，线下验货交易更符合信任场景。取舍阶段：真实。
- **移动 App（仅做网页）** — 理由：开发与维护双端成本高，网页版已可覆盖浏览、发布、私聊核心链路，且校园内电脑普及率高。取舍阶段：频率。

**需求分析.md 功能范围段「不做 Y」排除项**：
- 图片相似搜索 — 技术成本高，关键词已够用。
- 跨校区筛选 — 校园较小，交易地点不影响浏览。
- 语音/视频通话 — 存在隐私风险且场景单一。
- 消息已读回执 — 避免社交压力，不做推送，用户主动回访查看。
- 匿名评价 — 校园场景需实名制约束，匿名易滋生恶意差评。
- 平台仲裁 / 申诉 — 线下交易，平台不介入纠纷。

## 3. 页面清单

## 首页 · 商品广场

- **目的**：全站商品的浏览与检索入口，让买家快速找到目标商品。
- **元素**：
  - 分类导航（「教材」「数码」「生活用品」「其他」）：按分类筛选商品；横向标签式。
  - 搜索框（占位文案「搜索商品名称」）：按标题模糊匹配关键词。
  - 筛选区（价格区间 + 排序「最新 / 价格」）：进一步缩小范围。
  - 商品卡片（显示标题、缩略图、价格、新旧程度、交易校区）：单个商品的概览入口。
  - 发布入口（按钮「发布」）：进入发布商品页。
  - 空态提示（「没有找到相关商品，换个关键词试试」）：搜索无结果时展示。
- **操作**：
  - 点分类标签：切换到对应分类商品列表。
  - 输入关键词搜索：回车提交，展示匹配结果。
  - 设置价格区间 / 选择排序：实时刷新列表。
  - 点商品卡片：进入商品详情页。
  - 点「发布」按钮：进入发布商品页。
- **入口·出口**：从任意页面顶部导航进入；出口到商品详情页、发布商品页。
- **依赖**：商品列表数据（含分类、价格、新旧、校区字段）；搜索按标题匹配。

## 商品详情页

- **目的**：展示单件商品完整信息，并引导买家与卖家建立联系。
- **元素**：
  - 商品大图、标题、价格、新旧程度、交易校区、详细描述。
  - 卖家信息区（昵称、信用分、查看其评价入口）。
  - 私聊按钮（「私聊卖家」）：发起站内会话，自动带入商品名作开场白。
  - 收藏按钮（「收藏」，可选）。
  - 下架提示（「该商品已下架」）：商品不可再交易时展示，并隐藏私聊按钮。
- **操作**：
  - 点「私聊卖家」：创建/进入与该卖家的会话，自动发送「你好，请问 [商品名] 还在吗？」。
  - 点卖家评价入口：跳转卖家主页查看历史评价。
  - 点「收藏」：将该商品加入收藏（不强制）。
- **入口·出口**：从首页/搜索结果点商品卡片进入；出口到站内私聊、卖家主页、回首页。
- **依赖**：该商品数据；卖家信用数据；会话创建功能。

## 发布商品页

- **目的**：让卖家以单页表单快速发布一件闲置商品。
- **元素**：
  - 单页表单（同页一步填完）：标题、描述、图片上传（≤9 张）、价格、新旧程度（「九成新 / 八成新 / 其他」）、交易校区。
  - 提交按钮（「发布」）：校验通过即发布。
  - 校验提示（标红内联文案）：标题必填、价格需≥0、图片≤9 张。
- **操作**：
  - 上传图片：选择并预览，最多 9 张。
  - 填写各字段后点「发布」：通过校验则提示发布成功并跳转「我的」列表；失败则标红提示不提交。
- **入口·出口**：从首页「发布」按钮、我的页「发布」入口进入；出口到「我的」列表、首页。
- **依赖**：图片上传能力；发布后写入商品列表并可被搜索。

## 我的页面

- **目的**：个人中心，管理自己发布的商品、买到的商品与信用评价。
- **元素**：
  - 「我发布的」列表（含「编辑」「下架」操作）：管理自己卖出的闲置商品。
  - 「我买到的」列表（含「完成交易」操作）：查看已购买商品并发起完结。
  - 「我的评价」区（历史评价 + 平均分）：展示被评与已评记录。
  - 私聊入口（「我的私聊」）：进入会话列表。
  - 补评提示：有未完成的评价时引导补评。
- **操作**：
  - 点「编辑」：进入发布页预填该商品信息进行修改。
  - 点「下架」：商品从广场与搜索结果中移除。
  - 点「完成交易」：触发互评流程（见评价页）。
  - 点「我的私聊」：进入会话列表。
- **入口·出口**：从顶部导航「我的」进入；出口到发布页（编辑）、评价页、站内私聊。
- **依赖**：用户发布的商品数据、买入记录、评价数据。

## 站内私聊

- **目的**：买卖双方在不加微信好友的前提下协商细节与约定见面。
- **元素**：
  - 会话列表（按最近消息排序，显示对方昵称与最后一条消息）；列表式。
  - 聊天窗口（文本输入框 + 图片发送）；支持多条消息记录回查。
  - 自动开场白（「你好，请问 [商品名] 还在吗？」）：首次会话自动带入。
- **操作**：
  - 输入文本发送：消息即时出现在会话流。
  - 发送图片：选择本地图片发出。
  - 点会话：打开聊天窗口查看历史。
  - 与同一卖家重复发起：去重合为同一会话，不新建。
- **入口·出口**：从商品详情页「私聊卖家」、我的页「我的私聊」进入；出口到商品详情页、我的页。
- **依赖**：会话创建与去重；消息（文本/图片）存储。

## 评价页

- **目的**：交易完成后双方互评，沉淀信用供后续买家参考。
- **元素**：
  - 触发入口：由任意一方在「我买到的」点「完成交易」后弹出。
  - 维度一「信用态度（按时赴约）」：五颗星打分。
  - 维度二「商品/描述相符度」：五颗星打分。
  - 简短文字评价（选填）：自定义评价内容。
  - 提交按钮（「提交评价」）：提交后落库并展示在对方主页。
- **操作**：
  - 打分 + 留言后点「提交评价」：评价生效，计入对方平均分。
  - 取消：关闭本次评价（可后续在我的页补评）。
  - 重复评价：同一交易只记一次，不重复计。
- **入口·出口**：从「我买到的」完成交易操作弹出；出口到「我的」列表、对方主页。
- **依赖**：交易完成状态；评价存储与主页平均分计算。

## 4. 实体级数据模型

### 4.1 商品（Item）

#### 定义
卖家发布的一件闲置商品，平台信息撮合的基本单元。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 标题 | 文本 | 必填，搜索匹配字段 |
| 描述 | 文本 | 多行文本 |
| 图片 | 引用（最多9张） | 上传图片 |
| 价格 | 数字 | ≥0 |
| 新旧程度 | 枚举（九成新/八成新/其他） | |
| 交易校区 | 枚举 | 由校区选项决定 |
| 分类 | 枚举（教材/数码/生活用品/其他） | 发布时系统按标题自动归类，可手动改（推断值） |
| 状态 | 状态机，见下 | |
| 发布者 | 引用（用户） | |

#### 状态机
`在售 → 下架`（可随时下架）；`下架 → 在售`（可重新上架，恢复原信息，推断值）；`在售 → 已售出`（完成交易后）——已售出不可再编辑/下架。

#### 关系
一个用户发布多个商品；一个商品关联多个会话；被多个用户收藏（收藏为可选功能）。

---

### 4.2 用户（User）

#### 定义
注册的在校大学生，平台账号体系主体。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 昵称 | 文本 | 实名展示 |
| 信用分 | 数字（计算值） | 由评价平均分得出 |
| 历史评价 | 引用（多个评价） | 被评记录 |

#### 状态机
无（账号固定有效）。

#### 关系
一个用户发布多个商品；一个用户参与多个会话、多个交易、多个评价。

---

### 4.3 会话（Conversation）

#### 定义
唯一买卖双方对某一（或某类）商品沟通的站内聊天载体。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 参与者 | 引用（两个用户） | 买卖双方 |
| 关联商品 | 引用（商品，可空） | 从详情页发起时带入；允许不关联商品（从「我的私聊」发起的纯聊天，推断值） |
| 最近消息时间 | 时间 | 用于列表排序 |
| 消息数 | 数字 | |

#### 状态机
无（会话长期有效，不关闭）。

#### 关系
一个会话对应一条买卖链路；一个会话含多条消息。

---

### 4.4 消息（Message）

#### 定义
会话内的一条文本或图片消息。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 内容 | 文本 | 文本消息 |
| 图片 | 引用 | 图片消息（文本/图片二选一） |
| 发送者 | 引用（用户） | |
| 时间 | 时间 | |

#### 状态机
无。

#### 关系
多条消息属于一个会话。

---

### 4.5 评价（Review）

#### 定义
交易完成后一方对另一方的信用与商品相符度评价。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 维度一：信用态度 | 枚举（1-5星） | 按时赴约 |
| 维度二：商品相符度 | 枚举（1-5星） | 描述与实际符合程度 |
| 文字评价 | 文本（选填） | |
| 被评方 | 引用（用户） | |
| 关联交易 | 引用（交易） | 一交易一评（双向各一条） |

#### 状态机
无（提交即生效，不可修改）。

#### 关系
一个评价属于一个交易；一个用户被评多条评价。

---

### 4.6 交易（Transaction）

#### 定义
买卖双方对某件商品的线下成交记录，触发互评。

#### 字段表
| 字段 | 类型 | 说明 |
|---|---|---|
| 商品 | 引用（商品） | |
| 买方/卖方 | 引用（用户） | |
| 状态 | 状态机，见下 | |
| 完成发起方 | 引用（用户） | 谁点了「完成交易」 |

#### 状态机
`进行中 → 待互评`（一方点完成交易）→ `已完成`（双方均提交评价）；`待互评` 超 30 天自动关闭（推断值，30 天为默认值）。

#### 关系
一个交易对应一件商品、两条评价。

## 5. 用户流程 + 验收标准

## 用户流程：逛与买（主路径）

- **触发**：有购买意向的学生打开首页，浏览或搜索二手商品。
- **主路径**：
  1. 首页按分类浏览或搜索「高数教材」（首页·商品广场）→
  2. 输入关键词/价格区间筛选，按最新排序（首页·商品广场）→
  3. 点开一件商品查看大图、价格、新旧、校区、卖家信用（商品详情页）→
  4. 点「私聊卖家」自动带入商品名开场白（站内私聊）→
  5. 约定线下见面当面交易（站内私聊）→
  6. 在「我买到的」点「完成交易」（我的页面）→
  7. 弹出互评界面打分提交（评价页）。
- **异常分支**：
  - 搜索无结果 → 首页展示空态提示「没有找到相关商品」。
  - 商品已下架 → 详情页显示「该商品已下架」并隐藏私聊按钮。
  - 卖家不回复 → 买家可返回首页继续浏览其他商品。
- **边界情况**：空态提示引导换关键词；下架商品不可发起新会话。

#### 验收标准
- 当我在首页点分类标签（教材/数码/生活用品/其他）→ 系统展示该分类下全部在售商品。
- 当我输入关键词「高数教材」并按最新排序 → 系统按标题模糊匹配并返回相关结果。
- 当我设置价格区间 → 系统仅展示该价格范围内商品。
- 当我搜索无结果 → 系统展示空态提示「没有找到相关商品，换个关键词试试」。
- 当商品已下架 → 详情页显示「该商品已下架」并隐藏「私聊卖家」按钮。

## 用户流程：发布商品

- **触发**：学生有闲置商品想出售，从首页「发布」进入。
- **主路径**：
  1. 进入发布页（发布商品页）→
  2. 单页一步填完标题、描述、价格、图片、新旧、校区（发布商品页）→
  3. 点「发布」提交，校验通过即发布成功（发布商品页）→
  4. 提示跳转「我的」列表，商品进入对应分类（我的页面）→
  5. 可随时编辑或下架（我的页面）。
- **异常分支**：
  - 校验失败（标题空/价格负数/图片超 9 张）→ 标红提示，不提交。
  - 发布后立即下架 → 商品从广场与搜索结果移除。
- **边界情况**：空标题、负价格、超量图片均被拦截。

#### 验收标准
- 当我在发布页填写合法标题、价格≥0、图片≤9 张并点「发布」→ 系统提示发布成功并跳转「我的」列表。
- 当标题为空 → 系统标红提示「标题必填」，不提交。
- 当价格输入负数 → 系统标红提示「价格需≥0」，不提交。
- 当上传第 10 张图片 → 系统拒绝并提示最多 9 张。
- 当发布成功后我在「我发布的」点「下架」→ 商品从广场与搜索结果立即移除。

## 用户流程：站内私聊

- **触发**：买家在商品详情页对某件商品感兴趣，想与卖家沟通。
- **主路径**：
  1. 详情页点「私聊卖家」（商品详情页）→
  2. 自动生成开场白「你好，请问 [商品名] 还在吗？」（站内私聊）→
  3. 双方互发文本消息（站内私聊）→
  4. 必要时发送图片补充细节（站内私聊）→
  5. 会话自动保存，可随时回查（站内私聊）。
- **异常分支**：与同一卖家重复发起 → 去重合为同一会话，不新建。
- **边界情况**：历史记录可回查；开场白保证至少一条消息。

#### 验收标准
- 当我在详情页点「私聊卖家」→ 系统创建会话并自动发送「你好，请问 [商品名] 还在吗？」。
- 当我与同一卖家重复发起 → 系统去重合为同一会话，不新建。
- 当我在聊天窗口发文本 → 消息即时出现在会话流并保存。
- 当我发送图片 → 图片作为消息发出并保存。
- 当我进入会话列表 → 系统按最近消息时间倒序排列。

## 用户流程：完成交易与互评

- **触发**：线下交易完成后，任意一方在「我买到的」点「完成交易」。
- **主路径**：
  1. 点「完成交易」（我的页面）→
  2. 系统弹出互评界面（评价页）→
  3. 对「信用态度」与「商品相符度」分别打五颗星（评价页）→
  4. 填写简短文字（选填）后提交（评价页）→
  5. 评价展示在对方主页并计入平均分（我的页面）。
- **异常分支**：
  - 取消完成交易 → 流程中止，不触发互评。
  - 重复评价 → 同一交易只记一次。
  - 未评先离开 → 可在「我的」页面后续补评。
- **边界情况**：重复提交被拦截；被评方主页实时更新平均分。

#### 验收标准
- 当我在「我买到的」点「完成交易」→ 系统弹出互评界面并要求对两个维度打分。
- 当我提交 1-5 星评价 → 系统保存评价并计入对方平均分，展示在其主页。
- 当我再次对同一交易评价 → 系统拦截，只记一次。
- 当一方完成交易对方未评 → 对方在「我买到的」看到待评入口可补评。
- 当一方完成交易超 30 天对方未评 → 交易自动关闭，未评方不再接收待评入口（推断值）。

## 6. 文案基调

**语气**：校园、亲切、口语化，像同学之间的交流，不用官方商务腔。
- 示例：空态提示「没有找到相关商品，换个关键词试试」；商品下架提示「该商品已下架」。
**命名约定**：按钮用动词短语（「发布」「私聊卖家」「完成交易」「提交评价」）；状态用名词/动名词（「在售」「下架」「待互评」）；错误提示用「字段 + 必填/需XX」的直白结构（「标题必填」「价格需≥0」）。
