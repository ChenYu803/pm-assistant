# 校园二手交易平台 — MVP PRD

## 1. 概念

### 1.1 核心用户
本校在校大学生（含毕业季应届生），需要买卖二手教材、数码与生活用品。

### 1.2 要解决的一件事
用有检索、有信用、站内沟通的网页平台，替代低效且有安全隐患的微信群叫卖。

### 1.3 产品形态
响应式 Web（桌面 + 手机浏览器访问）。

### 1.4 商业模式
校园免费平台，暂不设交易佣金（非本版本重点）。

### 1.5 外部依赖声明
图片上传走平台自研存储；无支付、无第三方登录、无地图、无消息推送 SDK、无 AI 依赖。

## 2. Out of Scope

以下为本版本明确的排除项，引用自需求分析.md「排除清单」：

- **物流配送** — 理由：校园线下当面交易为主，物流成本高且非核心场景；取舍阶段：频率
- **担保交易** — 理由：涉及资金托管与第三方支付对接，复杂度高且校园小额交易频次低；取舍阶段：强烈
- **移动 App** — 理由：仅做响应式网页可降低开发与维护成本，同时覆盖桌面与移动浏览器访问；取舍阶段：强烈

## 3. 页面清单

## 商品列表页（首页）

- **目的**：浏览全部在售商品，提供分类筛选与关键词搜索入口，是平台的主入口。
- **元素**：
  - 搜索框（显示文案「搜索教材、台灯、自行车…」）：输入关键词检索商品；结构性 UI 形态：表单式
  - 分类标签（显示文案「教材 / 数码 / 生活用品 / 其他」，当前选中「数码」）：点击切换分类筛选；结构性 UI 形态：标签式
  - 发布商品按钮（显示文案「＋ 发布商品」）：跳转到发布商品页；结构性 UI 形态：按钮
  - 商品卡片（显示文案「九成新 iPad 4代 · ¥850 · 数码 · 2022级 · 已售3次」等）：列表展示商品缩略信息；结构性 UI 形态：卡片式
- **操作**：
  - 关键词搜索：输入并回车 → 列表按关键词过滤，无匹配时显示空态提示
  - 切换分类：点击分类标签 → 列表按所选分类过滤，高亮当前分类
  - 点击发布商品：点击按钮 → 跳转到发布商品页
  - 点击商品卡片：点击卡片 → 跳转到该商品详情页
- **入口·出口**：从任意页可回到本页（站内导航 / logo）；可由「发布商品按钮」→ 发布商品页；由「商品卡片」→ 商品详情页；由「消息入口」→ 消息页
- **依赖**：依赖在售商品数据列表（含分类、价格、成色、卖家）；依赖搜索与分类过滤功能

## 商品详情页

- **目的**：展示单个商品的完整信息（图片、价格、成色、描述、卖家信誉），并提供私聊与查看卖家的入口。
- **元素**：
  - 商品图片区（占位「📱 商品图片」）：展示商品主图；结构性 UI 形态：图片区
  - 商品名称（显示文案「九成新 iPad 4代」）：标识商品标题
  - 价格（显示文案「¥850」）：突出展示售价；结构性 UI 形态：文本强调
  - 属性行（显示文案「分类：数码 | 成色：九成新 | 库存：仅此一件」）：展示商品属性
  - 卖家信息（显示文案「张同学（2022级·计算机）· ★★★★☆ 4.5」）：展示卖家身份与信誉
  - 商品描述（显示文案「毕业季出，考研上岸用不到了…」）：描述成色与使用情况
  - 私聊卖家按钮（显示文案「私聊卖家」）：进入与该卖家的私聊会话；结构性 UI 形态：按钮
  - 查看卖家按钮（显示文案「查看卖家」）：跳转到该用户主页；结构性 UI 形态：按钮
  - 已下架提示（显示文案「该商品已下架或售出，无法发起私聊。」）：商品不可交易时的提示；结构性 UI 形态：警示条，默认隐藏
- **操作**：
  - 私聊卖家：点击按钮 → 跳转到消息页，并打开与当前卖家的会话
  - 查看卖家：点击按钮 → 跳转到该卖家的用户主页
  - （异常）查看已下架商品：进入页面 → 显示已下架提示，私聊入口置灰不可点
- **入口·出口**：从商品列表页点击商品卡片进入；可由「私聊卖家」→ 消息页；由「查看卖家」→ 用户主页；可返回商品列表页
- **依赖**：依赖对应商品数据（含图片、描述、价格、卖家）；依赖卖家信誉数据；依赖私聊会话建立功能

## 发布商品页

- **目的**：卖家以单页大表单一步填写商品信息，提交后立即上架。
- **元素**：
  - 标题输入框（占位「如：九成新 iPad 4代」）：必填，填写商品标题；结构性 UI 形态：表单式
  - 描述输入框（占位「描述成色、使用情况、可议价空间…」）：填写商品描述；结构性 UI 形态：表单式（多行文本）
  - 分类下拉（选项「数码 / 教材 / 生活用品 / 其他」）：必填，选择商品分类；结构性 UI 形态：下拉选择
  - 成色下拉（选项「全新 / 九成新 / 八成新 / 七成新及以下」）：选择商品成色；结构性 UI 形态：下拉选择
  - 价格输入框（占位「0.00」）：必填，填写售价（元）；结构性 UI 形态：数字输入
  - 图片上传区（显示文案「＋ 点击上传图片（支持多张）」）：必填，上传商品图片；结构性 UI 形态：上传区
  - 联系方式输入框（占位「仅展示给站内已私聊的买家」）：必填，填写站内可见联系方式；结构性 UI 形态：表单式
  - 必填提示（显示文案「带 * 为必填项，提交后立即上架。」）：提示填写要求；结构性 UI 形态：提示文本
  - 提交发布按钮（显示文案「提交发布」）：提交表单并上架；结构性 UI 形态：按钮
- **操作**：
  - 提交发布：点击按钮 → 校验必填项，通过则上架并跳转到商品列表页（新商品出现在列表顶部）；必填缺失时对应字段标红提示
  - 上传图片：点击上传区 → 选择图片上传，多张以缩略图预览
- **入口·出口**：从商品列表页「发布商品按钮」进入；可返回商品列表页；提交后返回商品列表页
- **依赖**：依赖图片上传功能；依赖商品发布接口；依赖必填校验逻辑

## 消息页（站内私聊）

- **目的**：买卖双方在站内沟通，约定交易细节，不暴露真实手机号。
- **元素**：
  - 会话列表（显示文案「张同学 / 还在吗？iPad 这个周末面交可以吗」等）：列出当前对话会话与最近消息预览；结构性 UI 形态：列表式
  - 消息气泡区：「对方消息」左侧灰气泡、「己方消息」右侧蓝气泡；结构性 UI 形态：卡片式（气泡）
  - 消息输入框（占位「输入消息…」）：输入要发送的消息；结构性 UI 形态：表单式
  - 发送按钮（显示文案「发送」）：发送当前输入的消息；结构性 UI 形态：按钮
  - 空态提示（显示文案「暂无消息，去商品详情页发起私聊吧」）：无会话时的引导；结构性 UI 形态：提示文本，默认隐藏
- **操作**：
  - 切换会话：点击会话列表项 → 右侧展示对应会话消息记录，当前会话高亮
  - 发送消息：输入内容后点击发送 → 消息追加到气泡区并清空输入框
  - （异常）无会话进入：进入页面 → 显示空态提示，引导去商品详情页发起私聊
- **入口·出口**：从商品详情页「私聊卖家」进入指定会话；从站内导航进入查看全部会话；可返回商品列表页
- **依赖**：依赖会话数据（与会话方、消息列表）；依赖消息发送功能；依赖私聊会话建立功能

## 用户主页

- **目的**：查看用户的身份信息、历史评价（星级+内容）与在售商品，辅助判断交易可信度。
- **元素**：
  - 头像（占位「👤」）：展示用户头像；结构性 UI 形态：头像区
  - 用户昵称（显示文案「张同学」）：标识用户身份
  - 评分（显示文案「★★★★☆ 4.5（共 6 次评价）」）：展示综合评分与评价数
  - 用户信息（显示文案「2022级 · 计算机学院 · 加入于 2023.9」）：展示年级、院系、注册时间
  - 评价区块标题（显示文案「近期评价」）：分隔评价区与商家信息区
  - 评价卡片（显示文案「★★★★★ 卖家很靠谱… — 李同学 · 3 天前」等）：展示单条评价的星级与内容；结构性 UI 形态：卡片式
  - 无评价提示（显示文案「该用户暂无评价。」）：无评价时的空态；结构性 UI 形态：提示文本，默认隐藏
- **操作**：
  - 查看在售商品：点击在售商品列表项 → 跳转到对应商品详情页
  - （异常）无评价用户：进入页面 → 评价区显示「该用户暂无评价」空态
- **入口·出口**：从商品详情页「查看卖家」进入；从评价卡片用户信息进入；可返回商品详情页
- **依赖**：依赖用户身份与评分数据；依赖历史评价列表；依赖该用户在售商品数据

## 4. 实体级数据模型

### 4.1 用户

#### 定义
平台注册用户，既是买家也是卖家，承载身份信息与历史信用。

#### 字段表
| 字段 | 类型 |
|------|------|
| 用户 ID | 引用（唯一标识） |
| 昵称 | 文本 |
| 年级 | 枚举（如 2022级） |
| 学院 | 枚举（如 计算机学院） |
| 注册时间 | 日期 |
| 综合评分 | 数字（0-5，可一位小数） |
| 评价总数 | 数字 |
| 站内联系方式 | 文本（仅私聊后可见） |

#### 状态机
无复杂状态（正常 / 无）。

#### 关系
发布多个商品；参与多个会话；收到/给出多个评价。

### 4.2 商品

#### 定义
卖家发布的在售物品，展示在列表页并可通过分类与关键词检索。

#### 字段表
| 字段 | 类型 |
|------|------|
| 商品 ID | 引用（唯一标识） |
| 标题 | 文本 |
| 描述 | 文本 |
| 分类 | 枚举（教材 / 数码 / 生活用品 / 其他） |
| 价格 | 数字（元） |
| 成色 | 枚举（全新 / 九成新 / 八成新 / 七成新及以下） |
| 图片 | 引用（多张，上传存储） |
| 卖家 ID | 引用（指向用户） |
| 联系方式 | 引用（继承卖家的站内联系方式） |
| 库存 | 数字（固定为 1，售出即下架） |
| 状态 | 枚举（在售 / 已下架） |

#### 状态机
`在售` → 提交发布后立即上架 → `在售`；卖家自行下架或售出 → `已下架`（无法私聊）。

> 推断值标注：联系方式跟随卖家账号，同一卖家所有商品共用一份。此为本版本无明确规定的业务决策点，按合理默认推断，确认后生效。

#### 关系
属于一个卖家（用户）；发起多个会话；可被多条评价（针对卖家而非商品）。

### 4.3 会话

#### 定义
买卖双方之间的私聊会话，承载消息记录。

#### 字段表
| 字段 | 类型 |
|------|------|
| 会话 ID | 引用（唯一标识） |
| 买家 ID | 引用（指向用户） |
| 卖家 ID | 引用（指向用户） |
| 关联商品 ID | 引用（指向商品，可选） |
| 最近消息预览 | 文本 |

#### 状态机
无复杂状态（正常 / 无历史会话时显示空态引导）。

#### 关系
包含多条消息；由商品详情页「私聊卖家」发起，或站内导航查看全部。

### 4.4 消息

#### 定义
会话内的单条消息，记录沟通内容。

#### 字段表
| 字段 | 类型 |
|------|------|
| 消息 ID | 引用（唯一标识） |
| 会话 ID | 引用（指向会话） |
| 发送者 ID | 引用（指向用户） |
| 内容 | 文本 |
| 发送时间 | 时间戳 |

#### 状态机
无。

#### 关系
属于一个会话；由发送者发出。

### 4.5 评价

#### 定义
交易双方互评记录，展示在用户主页作为信用依据。

#### 字段表
| 字段 | 类型 |
|------|------|
| 评价 ID | 引用（唯一标识） |
| 被评用户 ID | 引用（指向用户） |
| 评价用户 ID | 引用（指向用户） |
| 星级 | 枚举（1-5） |
| 内容 | 文本 |
| 评价时间 | 时间戳 |

#### 状态机
无。

> 推断值标注：评价入口在消息页的会话内，由双方主动点击「评价」发起，不依赖线下交易状态判定（本版本无担保交易，无法自动判定成交）。此为本版本无明确规定的业务决策点，按合理默认推断，确认后生效。

#### 关系
收到/给出多条评价，都属于一个用户。

## 5. 用户流程 + 验收标准

## 用户流程：买家买货

- **触发**：在校学生想购买二手商品（教材/数码/生活用品等），打开平台首页。
- **主路径**：商品列表页浏览在售商品 → 使用分类标签或关键词搜索过滤商品 → 点击商品卡片进入商品详情页，查看价格、成色、描述与卖家信誉 → 点击「私聊卖家」进入消息页，站内沟通约定面交时间地点 → 线下当面交易 → 在评价入口为卖家打分并留评（展示在用户主页）。
- **异常分支**：
  - 商品已售出/下架 → 详情页显示「该商品已下架或售出」提示，私聊入口置灰。
  - 无搜索结果/分类无商品 → 列表显示空态，可清空关键词或切换分类。
  - 卖家在私聊中不回复 → 买家可查看卖家信誉，选择放弃或等待。
- **边界情况**：搜索无结果（显示空态引导）；商品库存仅一件（售出即下架）；私聊无历史会话（显示空态引导）。

#### 验收标准
1. 当我在首页输入关键词并回车 → 系统按关键词过滤商品列表 → 展示匹配结果，无匹配时显示空态提示。
2. 当我点击分类标签 → 系统按所选分类过滤并高亮当前分类 → 只展示该分类在售商品。
3. 当商品已下架或售出 → 系统显示「该商品已下架或售出，无法发起私聊」警示条 → 私聊入口置灰不可点击。
4. 当我看用户主页 → 系统展示评分与历史评价 → 我可判断卖家可信度。
5. 当我在消息页会话内点击「评价」入口 → 系统展示评价表单（星级+内容）→ 我可提交评价。

## 用户流程：卖家卖货

- **触发**：毕业季清理闲置物品，或学期中想出售二手教材/生活用品，打开平台。
- **主路径**：从商品列表页点击「＋ 发布商品」→ 进入发布商品页，单页填写标题、描述、分类、价格、成色、图片、联系方式 → 点击「提交发布」→ 商品立即上架，出现在商品列表 → 买家发起私聊，在消息页沟通面交细节 → 线下成交 → 在评价入口为买家互评打分。
- **异常分支**：
  - 必填项缺失（标题/分类/价格/图片/联系方式） → 提交时对应字段标红提示，不跳转。
  - 图片上传失败 → 上传区显示失败提示，可重试。
  - 买家私聊后放弃交易 → 卖家可继续等待其他买家或自行下架。
- **边界情况**：必填项未填（标红拦截）；图片未上传（拦截）；重复提交（防重复提交，成功后跳转列表并置顶新商品）。

#### 验收标准
1. 当我填写全部必填项并点击「提交发布」→ 系统校验通过并上架 → 跳转到商品列表页，新商品置顶出现。
2. 当我未填写任一必填项 → 系统不跳转 → 对应字段标红提示「带 * 为必填项」。
3. 当我上传图片失败 → 上传区显示失败提示 → 我可重试上传。
4. 当我重复点击「提交发布」→ 系统防止重复提交 → 仅保留一次上架记录，成功后跳转列表。
5. 当我在消息页会话内为买家评价 → 系统记录该评价 → 更新买家综合评分与评价数。

## 6. 文案基调

**语气**：校园化、亲切、口语，带一点人情味，不用官方腔。

**示例**：
- 搜索框占位：「搜索教材、台灯、自行车…」
- 商品描述示例：「毕业季出，考研上岸用不到了…」
- 空态引导：「暂无消息，去商品详情页发起私聊吧」

**命名约定**：
