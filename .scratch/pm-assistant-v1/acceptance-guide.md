# 四环全流程人工验收指南（pm-assistant-v1 全量）

> 覆盖 01–07 全部 7 个 issue 的验收点。按顺序走一遍四环即可覆盖绝大多数；「横切验收」和「边界场景」可在流程中顺带检查。

## 0. 环境准备（3 分钟）

- [ ] dev server 运行中：`npm run dev` → 打开 http://localhost:3000
- [ ] 注册**新账号**（每次验收用新邮箱，避免旧数据干扰判断）
- [ ] 新建一个项目（如「校园二手交易平台」）→ 进入项目工作区

---

## 1. 环1 需求分析（验收 02/03 产出）

### 操作
1. 在「需求分析」标签页输入需求描述（一句话即可，如「想做校园二手交易平台」）
2. **不要一次给全信息**，看 Agent 会不会自己追问

### 看什么（怎么算对）
| 验收点 | 判定 |
|---|---|
| **诘问轮** | Agent 先追问（目标用户/核心场景/功能边界/排除项），**不直接写文档** |
| 追问质量 | 追问与需求相关，不是泛泛而谈；信息足够才停止 |
| **工作文档机制** | 对话过程中文件树出现琥珀色 📝 标记的「…工作文档」文件（静默写入，无确认弹窗） |
| 功能范围 | 确认排除项（如不做物流配送/担保交易），且排除项**附理由**（「不做 X，因为 Y」） |
| **四段结构** | 最终 需求分析.md 含四段：用户与场景 / 用户故事 / 功能范围 / 成功指标 |
| 落盘确认框 | 需求分析.md 产出时弹「确认写入」框；点「拒绝写入」→ 文件不落盘（可试一次） |

### 边界
- [ ] 中途提修改意见 → Agent 按意见修订，不推翻已确认结论

---

## 2. 环2 原型（验收 04 产出）

### 操作
1. 新建「原型」标签页（创建弹窗里四选一，带描述）
2. 发送推进指令（如「开始原型设计」）

### 看什么（怎么算对）
| 验收点 | 判定 |
|---|---|
| **提案式访谈** | Agent 先给整体方案：**页面清单 + 用户流程**，并生成 HTML 快照 |
| **HTML 快照** | 对话里出现「HTML 快照」+「下载 HTML」按钮；下载后用浏览器打开，是**完整可浏览的原型页面**（不是纯文本） |
| **指正修订** | 提修改意见（如「发布流程改单页表单」）→ Agent 只改相关页面，不推翻其他内容 |
| **冻结** | 回「完满」→ 冻结 → 输出 原型.md（弹确认框落盘） |
| 五字段 | 原型.md 每个页面含：**目的 / 元素 / 操作 / 入口·出口 / 依赖**，另有用户流程与显示文案 |
| **冻结后行为** | 冻结后再提新需求 → Agent 提示「范围已冻结」，不执行 |

## 3. 环3 PRD（验收 05 产出）

### 操作
1. 新建「MVP-PRD」标签页（应**自动加载**需求分析.md + 原型.md）
2. 发送推进指令

### 看什么（怎么算对）
| 验收点 | 判定 |
|---|---|
| **二次确认** | Agent 先复述需求分析结论（**不重新讨论**） |
| **概念版** | 对话出现概念版：七字段（核心用户/要解决的一件事/产品形态/MVP 功能/本版本不做什么/商业模式/外部依赖声明），核心内容 ≈300 字内 |
| 概念版落盘 | 用户确认后，概念版落为文件树**独立文件**「概念版（Tab N）.md」（弹确认框）——不是塞进 prd.md |
| **范围冻结** | 概念版确认后冻结；冻结后提范围修改被拒 |
| **六章齐全** | prd.md 六章：① 概念 ② Out of Scope ③ 页面清单 ④ 实体级数据模型 ⑤ 用户流程 + 验收标准 ⑥ 文案基调 |
| **零转换一致性** | 下载 原型.md 与 prd.md 对比：第 3 章页面清单、第 5 章用户流程与原型.md **逐字一致**（可复制对比） |
| **单源** | 「外部依赖声明」只在第 1 章概念出现一次，其他章节不重复声明 |

---

## 4. 环4 任务拆分（验收 06 产出）

### 操作
1. 新建「任务拆分」标签页
2. 发送推进指令

### 看什么（怎么算对）
| 验收点 | 判定 |
|---|---|
| **先草案后 quiz** | Agent 先输出切片**草案**（编号列表：标题 / Blocked by / 交付行为），再按三问确认：① 粒度对吗 ② 阻塞依赖对吗 ③ 要合并/拆分吗 |
| quiz 质量 | 问题具体（针对你的切片），不是套话 |
| 草案修订 | 提意见 → 草案更新后**再次确认** |
| **issues 文件集** | 批准后逐个弹「确认写入」（**队列化逐个弹**，不是一次全落盘） |
| 文件格式 | issues/NN-<slug>.md，标题 `# NN —`，四字段：What to build / 验收标准（AC）/ Blocked by / Status: ready-for-agent |
| **编号拓扑序** | 编号从 01 起，blocker 编号在前；首个 issue 的 Blocked by 为「无」 |
| **引用非复制** | 决策编码（schema/状态机）写「见 prd.md 第 X 章」，**不是复制 prd.md 大段原文**；AC 从第 5 章用户故事带走 |
| 拒绝落盘 | 拒绝某个 issue → 该文件不落盘，其余正常 |
| **重新切分** | 输出后发「重新切分」→ 可重新出草案（任务拆分**无冻结**，与前三环不同） |

## 5. 横切验收（流程中顺带看）

- [ ] **文件树分组**：需求分析.md / 原型.md / prd.md / 概念版（…）.md 平级显示；issues/ 目录下按 `NN-<slug>.md` 显示
- [ ] **工作文档**（琥珀色 📝）不显示「加载到 Agent」；正式文件显示该按钮；概念版也不显示（不可加载进 Agent 上下文）
- [ ] **changelog 头**：下载任一正式文件，开头是 `<!-- changelog: ... -->` 格式（工作文档没有）
- [ ] **标签页**：四个标签页可同时存在、可切换、可重命名；每个标签页对话独立
- [ ] **拒绝写入**后重看文件树：被拒文件确实不出现
- [ ] **401 兜底**（可选）：把 .env.local 的 key 加 `broken-` 前缀 → 重启 server → 对话报错弹窗提示 key 无效（错误不进对话区）→ 恢复 key 重启
