# 03 — 需求分析微调 + 方案 B（需求分析侧）

**What to build:** 需求分析 Agent 的「对话人格」升级（方案 B 五项中的需求分析侧）：
1. 功能范围段充实为「做 X + 不做 Y（附理由）」，排除项与理由在 interview 阶段问出；
2. 一次只问 1-2 个问题，回复以待回答问题结尾，未确认不推进阶段；
3. 四段分析完整性硬规则（用户与场景 / 用户故事 / 功能范围 / 成功指标 缺一 = 输出未完成，补全后再写文件）；
4. 对话流回复不使用整屏大表格（结构化内容写进文件）；
5. 阶段推进显式确认。

## Comments

### Mini 会决策记录（2026-08-07，已逐条拍板）

1. **「一次一问」判定 = 决策点制**：学习 grill-with-docs 的设计树/前沿机制。判定单位 = 一个决策点（设计树节点），一轮至多一个决策点 + 1 个子澄清；不问越过未决决策点的并行问题。不按字面问号数计数。
2. **排除项问法 = 取舍三问流程**（所有需求必经，排除理由在流程中天然产生）：
   - ① 需求是否真实（Agent 推理 + 用户敲定，不真实直接剪枝）
   - ② 需求是否强烈（Agent 先推理给倾向，用户确认/修正；三问：不满足影响产品？满足后影响收益？是否许多人要求？）
   - ③ 需求产生频率（给高频/中频/低频选项 + 场景一句话；问「谁、什么场景、多久一次」以顺带挖出用户与场景/用户故事素材）
   - 每需求 ≤3 问封顶（轻量版，防流程过重）；深挖只给保留分支
3. **表格控制边界 = 5×5 上限**（5 行 5 列，含表头），实验后按体验调整。
4. **缺段补全姿态 = 追问 + 显式豁免**：指出缺段并继续 interview；用户明确说「就按现状写」时允许带缺口输出并在文件头标注。
5. **排除项落点 = 需求分析.md 独立「排除清单」段**：每条 = 被排除的需求 + 排除理由 + 取舍阶段；PRD 第 2 章整体引用。
6. **工作文档**（新机制，需求分析 Agent 流程化配套）：
   - 每 tab 独立一份，命名带对话框标识（如「需求分析-工作文档（Tab N）.md」）
   - 文件树可见 + 特殊视觉标记（颜色/图标区分正式交付物）
   - **不可加载进 Agent 上下文**（agent context panel 不显示/不可选）
   - 生命周期：保留 + 手动删除（复用现有文件删除）
   - 落点：文件写入 API 识别文件名 → 前端标记 + context panel 排除
7. **流程形态 = 强流程三步**：引导挖掘需求 → 取舍三问 → 对保留需求考虑「做什么功能去满足」（四段分析入口）。

**范围说明：** 原 ticket 范围「只改需求分析 prompt」扩大为：prompt 重写 + 工作文档机制的配套实现（写入识别 / 文件树标记 / context panel 排除）。仅触及需求分析 Agent 相关路径，不动其他 Agent 的 prompt。
