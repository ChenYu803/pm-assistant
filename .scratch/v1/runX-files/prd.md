# 校园二手交易平台（Web）— MVP PRD

## 1. 概念

### 1.1 核心用户
本校在校大学生——毕业季批量清闲置的毕业生、开学季淘低价教材与生活用品的新生。

### 1.2 要解决的一件事
微信群买卖信息混乱、无法结构化检索、无信用评价，导致交易效率低且风险高。

### 1.3 产品形态
Web 端（校园二手交易平台），手机号一键登录，图片云存储，消息轮询近实时收发。

### 1.4 商业模式
MVP 阶段纯信息撮合，免费开放不收费；后续可考虑置顶推广、交易抽佣或校园广告位作为商业化方向。

### 1.5 外部依赖声明
登录走手机号一键登录（学号/手机号注册，实名由学校信息对接或人工核验，不自研实名认证）；图片存储走云存储（如 OSS/COS，不自建存储）；站内消息 MVP 阶段用轮询实现近实时收发，不做 App Push/SMS 推送；不做支付，不依赖支付 SDK，「立即购买」仅表达购买意向，面交时线下支付。

## 2. Out of Scope

以下排除项整体引用 需求分析.md「# 排除清单」段：

- **物流配送** — 理由：同校线下交易场景，物流成本与复杂度远高于收益；取舍阶段：真实（不强烈）。
- **担保交易** — 理由：平台定位信息撮合，不介入资金流与纠纷，避免法律与运营风险；取舍阶段：真实（不强烈）。
- **移动 App 开发** — 理由：MVP 阶段网页端已满足访问需求，原生 App 开发成本高、回报低；取舍阶段：强烈（频率低）。
- **高级筛选（价格/成色/距离）** — 理由：MVP 阶段保留基础搜索，验证核心路径后再迭代；取舍阶段：真实（不强烈）。
- **消息推送** — 理由：网页端场景以主动访问为主，推送成本高；取舍阶段：真实（频率低）。
- **评价审核与申诉机制** — 理由：MVP 阶段信任模型从简，后续视数据再补充；取舍阶段：真实（频率低）。
- **匿名评价** — 理由：同校场景实名评价才具约束力；取舍阶段：真实（不强烈）。

补充（来自 需求分析.md 功能范围段中「不做 Y」的排除项）：

- **担保交易 / 物流配送** — 平台为同校线下交易，不介入资金流与配送。
- **消息推送（App Push/SMS）** — 网页端以主动访问为主，MVP 不引入推送成本。

## 3. 页面清单

### 首页（商品列表）

- **目的**：平台主入口，展示全部商品，提供搜索与分类筛选，引导用户进入商品详情或发布。
- **元素**：
  - 搜索框（占位「搜索教材、数码、生活用品…」）：输入关键词，对标题与描述进行模糊全文检索。
  - 分类筛选（「全部 / 教材 / 数码 / 生活用品 / 其他」的胶囊按钮组）：按分类过滤商品列表。
  - 商品列表（卡片式列表）：每条含缩略图、标题、分类标签、一句描述（成色/卖点）、价格；可点击。
  - 发布入口（「＋ 发布我的闲置」按钮）：跳转商品发布页。
- **操作**：
  - 输入关键词并搜索：点击「搜索」→ [过滤列表；无结果显示空态页]
  - 点击分类：切换分类 → [列表按分类刷新]
  - 点击商品卡片：进入商品详情页
  - 点击「＋ 发布我的闲置」：进入商品发布页
- **入口·出口**：应用默认首页；可进入详情页、发布页。
- **依赖**：商品数据（标题/描述/分类/价格/图片）；搜索与分类过滤功能。

### 商品发布页

- **目的**：让卖家以单页一步表单快速发布闲置商品。
- **元素**：
  - 标题输入框（占位「例如：高等数学（第七版）」）：必填。
  - 描述多行输入框（占位「描述成色、转手原因、面交地点等（可附原价、成色说明）」）：必填。
  - 价格输入框（占位「例如：15」，单位元）：必填。
  - 分类下拉选择（「教材 / 数码 / 生活用品 / 其他」，默认教材）。
  - 图片上传区（「＋ 点击上传图片（最多9张）」虚线框）：上传商品图片。
  - 提示文字「一个表单，填完即发布，无多余步骤」。
  - 提交按钮（「一键发布」）。
- **操作**：
  - 填写并上传：点击「一键发布」→ [校验必填项；成功则返回首页，新商品出现在列表中]
  - 图片上传：点击上传区 → [选择本地图片，预览缩略图]
- **入口·出口**：从首页「＋ 发布我的闲置」进入；发布成功返回首页。
- **依赖**：图片上传功能；商品数据写入接口；发布前需登录（未登录走登录引导）。

### 商品详情页

- **目的**：展示单个商品的完整信息，供买家决策并发起私聊或购买。
- **元素**：
  - 商品主图（大图展示区）。
  - 价格（如「¥15」，醒目标注）。
  - 卖家信息（「卖家：小明 · 已实名认证 · ★★★★★ (12条评价)」）：展示信用与评价数。
  - 商品描述正文（成色、面交地点等）。
  - 操作按钮：「💬 私聊卖家」（主按钮）与「立即购买」（次按钮）。
- **操作**：
  - 点击「💬 私聊卖家」：进入与该卖家的私聊会话（未登录先引导登录）。
  - 点击「立即购买」：发起购买意向（MVP 阶段标记意向，进入私聊确认面交）。
- **入口·出口**：从首页商品卡片进入；出口为私聊页、登录引导。
- **依赖**：商品详情数据；卖家信息与评价数据；是否登录状态。

### 站内私聊（消息列表 + 会话）

- **目的**：买卖双方一对一沟通商品细节与面交安排，记录留存可回查。
- **元素**：
  - 消息列表（列表式）：每条含对方头像、最近消息预览、未读红点数字。
  - 会话窗口：气泡式聊天记录（「气泡.them」为对方消息、「气泡.me」为我方消息）、输入框（占位「输入消息…」）、「发送」按钮。
  - 提示文字「支持文字与图片 · 记录留存可回查」。
- **操作**：
  - 点击消息列表项：进入对应会话窗口。
  - 输入并点「发送」：发送文字消息（支持附带图片），追加到会话。
- **入口·出口**：从商品详情「私聊卖家」进入对应会话，或从「我的 → 我的消息」进入消息列表；可返回详情页/我的。
- **依赖**：会话与消息数据；双方用户身份；实时消息传输（MVP 轮询或简单推送）。

### 我的（个人主页）

- **目的**：管理我的在售商品、交易记录、消息入口与收到的评价。
- **元素**：
  - 个人信息行（头像、昵称「王小帅」、「在校大三 · 已实名认证」）。
  - 统计卡（「6 在售 / 3 已售出 / 4.8 信用分」）：个人交易概览。
  - 菜单项：「📦 我的在售商品」「📋 交易记录」「💬 我的消息（未读数 3）」「⭐ 收到的评价（4.8分）」。
  - 评价明细：「好评 同学很靠谱… — 买家小明」等条目（好评/中评/差评 + 文字评论）。
- **操作**：
  - 点「我的在售商品」：进入个人商品列表（复用首页列表形态）。
  - 点「交易记录」：查看历史交易。
  - 点「我的消息」：进入站内私聊消息列表。
  - 点「收到的评价」：查看收到的评价明细（也可直接在页面内平铺展示）。
- **入口·出口**：从首页底部/顶部导航进入；出口为私聊页、商品列表。
- **依赖**：用户信息、在售商品数据、交易记录、评价数据、消息未读数。

## 4. 实体级数据模型

### 4.1 用户（User）

#### 定义
平台注册用户，买家/卖家身份合一。含实名认证标记、信用分与评价数，用于展示信用与降低交易风险。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 昵称 | 文本 | 展示用，如「王小帅」 |
| 学号/手机号 | 文本 | 登录标识 |
| 实名认证 | 枚举（未认证/已认证） | [推断值]，认证方式为学号对接或人工核验 |
| 在校信息 | 枚举（在读/毕业） | 如「在校大三」，展示用 |
| 信用分 | 数字 | 由评价聚合得出，如 4.8 |
| 评价数 | 数字 | 收到评价条数，如 12 |

#### 状态机
无（用户无流转状态）。

#### 关系
- 一对多：用户 → 商品（在售/已售出）
- 一对多：用户 → 评价（作为评价者/被评价者）
- 一对多：用户 → 会话（作为买卖任一方）

### 4.2 商品（Item）

#### 定义
卖家发布的闲置物品数据单元，含标题/描述/价格/分类/图片/状态。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 标题 | 文本 | 必填 |
| 描述 | 文本 | 必填，含成色/转手原因/面交地点建议 |
| 价格 | 数字 | 必填，单位元，>0 |
| 分类 | 枚举（教材/数码/生活用品/其他） | 默认教材 |
| 图片 | 引用（云存储） | 最多 9 张 |
| 状态 | 枚举（在售/已售出/已下架） | 见状态机 |

#### 状态机
- 在售 →（卖家手动下架）→ 已下架
- 在售 →（买家发起购买意向 + 双方确认）→ 已售出
- 已下架 →（卖家重新上架）→ 在售 [推断值]
- 已售出 → 不可再上架 [推断值]

#### 关系
- 多对一：商品 → 用户（卖家）
- 一对多：商品 → 会话（绑定该商品的私聊会话）
- 一对多：商品 → 交易记录（「立即购买」发起的意向）

### 4.3 会话（Conversation）

#### 定义
买卖双方一对一沟通单元，绑定发起私聊的商品，记录留存可回查。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 关联商品 | 引用（商品） | 从商品详情发起的私聊绑定该商品 |
| 参与双方 | 引用（用户 ×2） | 买家与卖家 |
| 未读数量 | 数字 | 按参与方分别记录，展示红点 |
| 最近消息预览 | 文本 | 消息列表展示用 |

#### 状态机
无（会话无流转状态；同一对买卖双方可就同一商品复用同一会话）。

#### 关系
- 多对一：会话 → 商品
- 多对一：会话 → 用户（买/卖各一）
- 一对多：会话 → 消息

### 4.4 消息（Message）

#### 定义
会话内的单条沟通记录，支持文字与图片，留存可回查。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 所属会话 | 引用（会话） | |
| 发送者 | 引用（用户） | |
| 内容 | 文本 | 文字消息内容 |
| 图片 | 引用（云存储） | 图片消息 |
| 是否已读 | 布尔 | |

#### 状态机
无（消息为追加式，不流转）。

#### 关系
- 多对一：消息 → 会话
- 多对一：消息 → 用户（发送者）

### 4.5 交易记录（Transaction）

#### 定义
「立即购买」发起的购买意向及后续履约记录，用于交易记录页展示。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 关联商品 | 引用（商品） | |
| 买家/卖家 | 引用（用户） | |
| 状态 | 枚举（意向已发起/待面交/已完成/已取消） | 见状态机 |

#### 状态机
- 意向已发起 →（私聊确认面交）→ 待面交
- 待面交 →（双方确认完成）→ 已完成
- 意向已发起 / 待面交 →（任一环节取消）→ 已取消
- 已完成：商品变更为「已售出」；可在 7 天内互评

#### 关系
- 多对一：交易记录 → 商品
- 多对一：交易记录 → 用户（买/卖各一）

### 4.6 评价（Review）

#### 定义
交易完成后买卖双方互评，评分维度为好评/中评/差评 + 可选文字，公开显示在对方个人主页。

#### 字段表
| 字段 | 业务级类型 | 说明 |
|------|-----------|------|
| 评价者/被评价者 | 引用（用户） | |
| 关联交易 | 引用（交易记录） | |
| 评分 | 枚举（好评/中评/差评） | |
| 文字评论 | 文本 | 可选填 |

#### 状态机
无（评价提交后固定，不可修改；无申诉机制）。

#### 关系
- 多对一：评价 → 用户（被评价者，聚合为信用分）
- 多对一：评价 → 交易记录（一交易可产生 0-2 条互评）

## 5. 用户流程 + 验收标准

### 买家找货（主路径）

- **触发**：买家打开平台，想找二手教材或生活用品。
- **主路径**：首页（搜索或点分类筛选）→ 浏览商品列表 → 点击商品卡片进入商品详情页 → 点「💬 私聊卖家」→ 进入站内私聊会话 → 与卖家确认细节并约定面交。
- **异常分支**：
  - 搜索无结果 → 显示空态页「没有找到相关商品，换个关键词或看看全部商品」→ 点「返回全部商品」回首页。
  - 未登录点「私聊卖家」→ 进入登录引导页 → 手机号一键登录后回到私聊。
- **边界情况**：商品已售出或下架 → 详情页提示「该商品已下架」；私聊时对方不在线 → 消息正常发送，对方上线可回看。

#### 验收标准
- 当我在首页输入关键词并点「搜索」→ 系统按标题与描述模糊匹配 → 列表展示匹配商品；无匹配时显示空态「没有找到相关商品，换个关键词或看看全部商品」，并提供「返回全部商品」入口。
- 当我点击某个分类胶囊 → 系统按该分类过滤列表 → 仅展示该分类下的在售商品。
- 当商品已售出或已下架 → 详情页提示「该商品已下架」且不可发起私聊或购买。
- 当我未登录点「💬 私聊卖家」→ 系统引导登录 → 登录后回到该商品详情页继续操作。
- 当我从商品详情点「💬 私聊卖家」→ 系统打开与该卖家的会话（若已有该商品会话则复用，否则新建）→ 会话绑定该商品。
- 当我发送文字或图片消息 → 消息即时追加到会话，对方上线后可回看。
- 当对方不在线 → 消息正常发送成功，对方上线后可见，不丢失。
- 当我有未读消息 → 消息列表中展示未读红点数字。
- 当我从消息列表点某条会话 → 进入对应会话窗口 → 未读红点清零。

### 卖家发布（主路径）

- **触发**：卖家（如毕业季学生）想批量清理闲置物品。
- **主路径**：首页 → 点「＋ 发布我的闲置」→ 商品发布页（单页表单）→ 填写标题、描述、价格、分类、上传图片 → 点「一键发布」→ 返回首页，新商品出现在列表。
- **异常分支**：
  - 未登录点发布 → 进入登录引导页 → 登录后回发布页。
  - 必填项为空/价格非法 → 表单内提示「请填写标题/描述/价格」。
- **边界情况**：图片上传失败 → 提示重新选择；重复提交 → 按钮防重复点击。

#### 验收标准
- 当我在发布页填写标题/描述/价格并选分类、上传图片后点「一键发布」→ 校验通过则商品创建成功 → 返回首页，新商品出现在列表顶部，状态为「在售」。
- 当必填项为空或价格非法 → 系统在表单内提示「请填写标题/描述/价格」→ 不提交，表单保持原样可修改。
- 当我未登录点「＋ 发布我的闲置」→ 系统引导登录 → 登录后回到发布页。
- 当图片上传失败 → 系统提示重新选择图片 → 不阻塞其他字段填写。
- 当重复点击「一键发布」→ 按钮防重复，只创建一条商品。

### 交易后互评（主流程）

- **触发**：买卖双方完成面交后，对对方信用进行反馈。
- **主路径**：我的 → 交易记录 → 找到对应交易 → 对对方评价（好评/中评/差评 + 可选文字）→ 提交后展示在对方个人主页「收到的评价」。
- **异常分支**：未在期限内评价 → 不再开放，提示已过期。
- **边界情况**：双方均不评价 → 无强制；差评 → 展示为差评标记（MVP 无申诉机制）。

#### 验收标准
- 当交易标记为「已完成」→ 双方在 7 天内可在交易记录中找到该交易并发起互评（好评/中评/差评 + 可选文字）。
- 当提交评价 → 评价公开显示在对方个人主页「收到的评价」中，并更新对方信用分与评价数。
- 当超过 7 天未评价 → 不再开放，提示已过期。
- 当双方均未评价 → 无强制，不产生任何评价记录。
- 我可以在我的主页查看自己收到的评价明细（好评/中评/差评 + 文字）。

### 交易确认（补充流程）

- **触发**：买家对某商品点「立即购买」表达购买意向。
- **主路径**：商品详情 → 点「立即购买」→ 系统标记该商品购买意向并进入私聊 → 双方确认面交 → 商品状态变更为「已售出」，列表下架 → 交易记录标记「已完成」。
- **异常分支**：任一环节取消 → 商品恢复「在售」，交易记录标记「已取消」。
- **边界情况**：意向发起后长期未确认 → 保持在「待面交」状态不自动关闭。

#### 验收标准
- 当我点「立即购买」→ 系统标记该商品的购买意向并进入私聊 → 引导双方确认面交。
- 当双方在私聊中确认交易 → 商品状态变更为「已售出」并在列表中下架 → 详情页提示「该商品已下架」。
- 当交易任一环节被取消 → 商品恢复「在售」状态，交易记录标记「已取消」。
- 交易记录页展示每个交易的状态（意向已发起/待面交/已完成/已取消）。

### 消息推送（不为 MVP 实现）

- **说明**：不主动推送，用户被动访问查看新消息；消息列表以未读数红点提示新消息。

#### 验收标准
- 当有新消息到达 → 系统不进行 App Push/SMS 推送 → 用户下次访问平台时，消息列表红点展示未读数量。

## 6. 文案基调

**语气**：校园社区感、清爽直接。像同学之间说话，不官方、不冷冰冰。
**示例**：搜索框占位「搜索教材、数码、生活用品…」；发布页提示「一个表单，填完即发布，无多余步骤」；私聊提示「支持文字与图片 · 记录留存可回查」；空态「没有找到相关商品，换个关键词或看看全部商品」；商品列表价格「¥15」；按钮「💬 私聊卖家」「📦 我的在售商品」。
**命名约定**：功能按钮用「动词 + 对象」（如「一键发布」「私聊卖家」「立即购买」）；状态用中性词（在售/已售出/已下架/已完成/已取消）；分类固定为「教材 / 数码 / 生活用品 / 其他」。
