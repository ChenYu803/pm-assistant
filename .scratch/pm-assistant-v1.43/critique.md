# v1.43 全站视觉与动效评估

**方法：双代理评估**（A：全站设计评估；B：detector 与浏览器证据）。评估于 2026-10-30 完成。

## 整体判断

这是一个有自己性格的网站，不是廉价模板：AI 产品现场的暖纸、墨黑、珊瑚色和高对比中文衬线标题，与“新人接手真实任务”的体验贴合。简报、场景反馈、测试结果构成一条完整的职业体验；进入项目工作台后，界面收敛为清晰的工作结构。成熟感的主要阻力不在缺少动画或装饰，而在认证页品牌断层、信息密度不均和各处动效节奏尚未形成同一套规则。

评分覆盖混合型产品：工作台与项目页是 Operate，首页是 Persuade，入职场景和测评是 Experience。

## 优先问题

1. **P1｜登录和注册页切断品牌体验。** 用户走完整段体验或申请学习笔记后进入认证，页面却以内部名“PM Assistant”和白底通用表单迎接他们；`PRODUCT.md` 明确此名仅供仓库内部使用。统一现有中文品牌名称与视觉语言，不需要引入新品牌承诺。建议 `$impeccable polish`。
2. **P2｜刷新会清空游客体验的提醒偏晚。** 简报鼓励继续体验，场景页末尾才说明刷新会重置；手机用户中途离开容易误以为有自动保存。把准确的重置说明放到开始入口旁，保持既有“不保存游客进度”产品决策。建议 `$impeccable clarify`。
3. **P2｜反馈和结果页长，重点不够快扫到。** 桌面反馈区并列解释选择、纠正、答案和动作，窄列换行密；手机则把长内容串成较长页面。突出“结论 + 下一步动作”，详细论证继续保留并分层呈现。建议 `$impeccable layout`。

## 现有设计的优势

- 首页两个入口明确区分“先认识职业”和“已经准备好做产品”，且不要求先注册。
- 六个工作场景连成具体判断链；答错也有解释，不制造淘汰感。
- 工作台把四阶段、会话、对话和文件/上下文关系摆清楚，视觉强度随工作任务收敛。

## Detector 与浏览器证据

`impeccable detect --json src` 共报告 11 条 warning：9 条 `overused-font`，分布于 `CareerAssessment.module.css`、`LandingPage.module.css`、`OnboardingExperience.module.css` 和 `ProfilePage.module.css`；2 条 `side-tab` 在 `globals.css:180` 的 toast 强调边与 `MarkdownRenderer.tsx:21` 的引用边框。

这些 warning 是线索，不是美学结论。ProfilePage 中部分命中只是 Inter Tight 的 Inter fallback；MarkdownRenderer 的 `border-l-2` 是普通引用样式；toast 命中虽确有珊瑚侧边线，但它不是卡片。字体问题更该从整站字体分工与中文字形效果判断，而不是机械替换。

浏览器 detector 在桌面/手机首页显示 3/6 个 anti-pattern，登录、注册和 Projects 入口无命中；Projects 入口未登录时实际转到登录页。注入前置检查允许修改页面，但没有用户可见的 `[Human]` 浏览器标签；输出和截图来自本地浏览器控制台/采集，不构成人工覆盖层验收。B 的截图带检测器标注，不能当作纯净页面视觉基准。

## Persona 风险和负荷

- **Jordan（PM 初学者）：** 选项和提示让职业概念容易理解；长反馈容易分散主结论，认证页陌生的内部名会削弱信任。
- **Casey（手机上容易被打断）：** 单列交互可读，点击目标明确；刷新重置提醒偏晚，中断后可能失去本次体验。
- **Sam（键盘/读屏用户）：** 源码中有语义控件、输入标签和部分状态提示；本次没有完成键盘、读屏、200% 缩放或逐项对比度实测，不能宣称通过。

认知负荷主要来自题目概念和答案理由，而不是选择项数量。四选一与清楚的即时反馈控制了决策负荷；结果长文和重复说明增加了阅读负荷。收敛重点层级即可，不需要删掉学习依据。

## v1.43 动效方向：「成果接力」

动效应强调“判断如何一步步变成可交付的产品成果”。高级感来自克制、可预测、对状态有解释力的运动，不来自全页持续漂浮、粒子、视差或重型 3D。

| 动效 | 触发与表现 | 适用范围与边界 |
|---|---|---|
| 场景内的判断接力 | 用户确认选择后，当前题目收束，下一问题沿阅读方向进入；进度标记同步前进一步。建议 280–350ms，`cubic-bezier(0.16, 1, 0.3, 1)`，只动题目/标记，不让整屏飘动。 | WorkScenes 已有问题换题与错峰选项，先精炼为一套更短的点击驱动节奏，不必叠加新动画库。 |
| 反馈分层显现 | 提交后先显露“判断成立/再想一步”和“下一步项目动作”；详解原位展开或由用户打开。建议 180–280ms opacity/短距离 translate。 | 提升反馈扫描速度，同时保留全部学习事实。完整阅读不能依赖动效。 |
| 入职体验章节转场 | 进入新场景时只对场景题签/正文边界做短暂的遮罩或裁切揭示，进度沿 6 个节点推进；转页 350–500ms，章节标题最多一次轻微 stagger。 | 用于简报→首场景、场景切换、测试结果这几个真正的章节边界；不对页面所有区块套相同 fade-up。 |
| 工作台状态反馈 | 新建会话、文件确认/撤回、展开文件/上下文抽屉时，使用 150–250ms 稳定淡入/位移；生成中的状态用静态文字和一个低幅度指示器解释等待。 | 事件驱动、短促、可中断；不动长回复正文，不做闪烁或循环 shimmer。 |
| 首页滚动引导 | 保留现有内容作为默认完整静态状态；只在一个或两个关键章节边界加原生 CSS view/scroll timeline 小幅揭示，Firefox和减弱动画偏好保留终态。 | 首页已有 reveal，不应再把所有区块重复淡入。超出 CSS 能力再考虑 JS。 |

**共用节奏建议：** 即时反馈 80–180ms；常规状态 180–280ms；章节转换 350–500ms。缓动优先 ease-out-expo。只在明确的章节/状态边界使用错峰，单项间距 50–80ms；避免当前体验里较长选项错峰造成的等待感。动画只改 `transform` / `opacity` 等便宜属性；触发源是用户点击或真实滚动，不加入无意义自动循环。桌面 hover 不承载唯一状态提示。

**减弱动画：** 保留完整静止终态、进度和反馈；关闭章节揭示与大位移，状态切换降为即时或短淡入。键盘聚焦、提交、错误、生成中和成功都须在无动画时可理解。场景、项目和工作台均覆盖窄屏。

## 覆盖范围与限制

A 审查了首页、简报、7 个工作场景的截图、答题反馈、测评与桌面结果、登录/注册，以及本地现场捕获的空项目/项目总览、迭代创建、空状态工作台桌面与手机、个人主页。视口为 1440×900 和 390×844。B 检查了首页/登录/注册和未登录的 Projects 路由 detector；没有全流程浏览器交互验证。私人本地测试账号与项目已清理，API 未调用真实模型；未访问或写入线上用户数据。

本次没有实际安装任何动效。建议需在批准迭代 ticket、选定范围之后实现和验证；视口截图不等于键盘、屏幕阅读器、网络失败、性能或正式线上验收。
