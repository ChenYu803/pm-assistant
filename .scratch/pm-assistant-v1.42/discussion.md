# v1.42 上线决策讨论

状态：讨论中，尚未形成 ready-for-agent 规格或实现票。
日期：2026-09-27。

## 已确定

- 暂停 v1.41 后续迭代，启动 v1.42 上线讨论；不撤销已经完成的实现，不修改历史票状态。
- 首发平台方向为 Vercel + Supabase PostgreSQL + 阿里云购买域名。
- 保留 MySQL 相关代码，以备未来使用；具体维护承诺待定。
- 用户可提供上述平台资源；账号套餐、数据库区域、域名与部署权限尚未核实。
- 本轮先讨论和记录决策，不进行应用迁移、清库、付费开通或生产部署。

## 事实与边界

- PROGRESS.md 记录 v1.41 已完成 01—05；新工作台候选交付、修订/撤回等后续成果能力尚未完整接入。已有 UI 可操作不等于四环成果闭环已经具备发布条件。
- 当前应用依赖 mysql2，认证使用 NextAuth；采用 Supabase Database 不自动意味着采用 Supabase Auth。
- 新工作台 `src/lib/mysql-iteration-workbench.ts` 的生成上限为 600 秒，累计完整正文后保存，消息路由等待结束才返回 JSON；旧工作区的 SSE 行为不能当作新工作台现状。Vercel 适配须检查生成时限和失败后的终态恢复。
- `src/lib/generation-control.ts` 以进程内 Map 保存取消控制器；停止请求虽写入数据库状态，异实例生成仍可能继续消耗上游额度。首发需明确跨实例停止和费用边界。
- 当前注册与聊天路径尚未发现完整的邀请/额度控制；`src/lib/ai.ts` 在生产未配置 AI_MODE 时默认 live。低成本不能只按主机与数据库费用计算，部署验收应显式指定模式。
- 已有平台调查位于 `docs/research/vercel-supabase-alicloud-domain.md`（2026-09-23）。其中套餐、时长、区域和费用结论在确定套餐时需要按官方当前资料复核，不能作为价格或可用性承诺。
- 讨论文档中的建议不是已接受的产品范围；数据库迁移涉及存储与跨模块事务，实现阶段按 L2 判级。本轮只做文档变更。

## 第一轮决策前沿

1. 首发必须交付的用户结果：入职体验、四环成果闭环，以及暂停 v1.41 对首发功能的边界。
2. 首批用户与开放方式：地域、规模、预计同时使用人数，以及是否收费/用于商业活动。
3. 成本上限：基础设施与模型分别可接受的月支出，域名年费单列。
4. 时间目标：首批用户实际开始使用的目标日期；功能范围与日期的优先级。
5. 数据保留：已有账号、项目、对话、文件是否需要进入线上；云端全新数据库不等于删除本机数据。
6. MySQL 保留的承诺：保留可追溯旧实现，还是 v1.42 仍需同时支持 MySQL 运行和验收。

## 后续依赖树

- 首发结果 + 时间目标 → 最小功能闭环 → 从 v1.41 选择必要能力 → 发布验收路径。
- 用户地域 + 开放方式 + 成本上限 → 套餐/区域 → 网络验证、访问控制与模型费用限制。
- 首发范围 + 数据保留 + MySQL 承诺 → PostgreSQL 迁移范围、认证选择、数据库访问边界和验证方案。
- 套餐 + 模型需求 → 生成时限、停止/超时后恢复、跨实例状态清理。
- 以上决策收敛 → v1.42 spec / tickets → 用户确认共同理解 → 开始实现。
