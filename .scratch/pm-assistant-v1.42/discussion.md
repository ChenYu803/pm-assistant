# v1.42 上线决策讨论

状态：讨论中，尚未形成 ready-for-agent 规格或实现票。
日期：2026-09-27。

## 2026-10-02 当前问题：同机 MySQL 与 Cloudflare 实操路线

用户对海外 VPS 同机运行 MySQL 感兴趣，要求解释 CDN、美国服务器 + Cloudflare 的合理性，并比较大陆访问便利度；尚未最终选择 VPS 商家、套餐、机房或撤销 Supabase 平台 ADR。新研究见 `docs/research/v142-overseas-mysql-cloudflare-routes.md`。

已核实普通 Cloudflare 的节点取决于网络路由，不能把朋友经过香港理解为免费套餐固定香港线路；China Network 是另购 Enterprise 服务并有 ICP 要求。静态缓存可减少回源，私人数据与生成等动态请求仍由源站处理。Cloudflare 当前官方默认回源读取超时为 125 秒；现有完整生成后 JSON 返回、上游 600 秒等待有超时风险，同机 MySQL 不自动解决该问题。实施时需真正流式/心跳输出及代理缓冲配置或持久任务+轮询；先前 Vercel 300 秒限制不应直接套在常驻 VPS 上，但反向代理与 Cloudflare 限制仍需适配。

用户补充没有朋友的商家、机房、套餐或网站类型信息，不以获取这些信息为前置。朋友路线仅作为方向参考；建议选择短期小额美国 VPS 对照普通代理与 DNS-only 直连，亚洲 VPS 仅按实际大陆运营商线路测量选择，不凭城市保证速度。域名仍可在阿里云注册，DNS 托管可交由 Cloudflare；MySQL 留在服务器内部，不让浏览器或公网直接连接。当前仅解释和研究，不创建资源或执行部署。

## 2026-10-02 用户最新约束：先试海外服务器

用户决定先试海外路线，不等待大陆备案，也不接受昂贵的国内云服务器/云数据库投入。朋友已实测“美国服务器 + Cloudflare”访问较快；这作为候选链路的正向实测参考，不能据此推定本站动态 API、数据库往返或 Cloudflare 实际边缘位置已经验证。

当前问题转为 Supabase 免费数据库的具体风险、暂停时间和可承载数据量，不继续推荐大陆承载作为本轮默认。海外主机种类、是否沿用 Vercel、Cloudflare 配置及数据库位置仍未明确；先试海外不等于已选择自建 VPS 或授权部署。保留 MySQL、本机数据不迁移等已确定边界仍有效。

建议：少量面试展示可先试 Supabase Free，接受低活跃七天可能暂停，面试前检查恢复，自行导出备份并监测数据库大小。不要把“50,000 Auth MAU”解释为本站可承载五万活跃用户，也不要把粗略存储估算当压测。若用户最终购买可运行数据库的美国 VPS，可比较在该机使用已有 MySQL，其独立数据库订阅费可以为零，但消耗主机资源并需维护备份；Vercel 函数本身不能这样运行 MySQL。

用户确认 v1.41 全部完成，仓库 24 号发布闸记录也确认 01—24 已完成、MySQL/replay 验收通过。下方 2026-09-27 的“仅完成 01—05”“候选尚未接齐”与延期撤回/HTML 的建议均为历史讨论，不再作为当前功能缺口或裁剪依据。已通过固定回放不等于云端网络或真实模型已经验收。

本轮用户要求先评估 Vercel + Supabase + 阿里云域名对中国大陆用户的适用性，暂不推进 Q7—Q9。此前平台方向进入复评，尚未授权变更为其他平台，也未授权数据库迁移或部署。调查见 `docs/research/v142-mainland-hosting-review-2026-10-02.md`。

当前判断：免费额度对少量面试演示大概率足够，但大陆连通性、Supabase 闲置暂停、Vercel 请求时限和已有 MySQL 迁移成本更可能先成为约束。建议比较保留已验收 MySQL 的香港云服务器（先实测线路）与大陆云服务器（先完成相应备案）；这是供用户选择的建议，不是已接受决策。域名注册商和 `.cn` 后缀不改变网站部署位置。

## 已确定

- 暂停 v1.41 后续迭代，启动 v1.42 上线讨论；不撤销已经完成的实现，不修改历史票状态。
- 首发平台方向为 Vercel + Supabase PostgreSQL + 阿里云购买域名。
- 首发主要保留入职体验，并让实践路线具备最小四环成果闭环；具体成果操作边界待下一轮确认。
- 主要用途是用户在面试时展示个人作品，首发提供免费试用；不按公开商业产品预设规模。试用对象和访问方式尚未锁定。
- 平台费用选择 Vercel Hobby 与 Supabase Free 方向；域名倾向 `.cn`，用户预期年费三十多元，具体域名价格和续费需购买页核实。模型费用尚未确定。
- Supabase 使用全新数据库，不迁移现有账号、项目、对话或文件；本机 MySQL 数据原样保留。
- 保留现有 MySQL 实现及初始化脚本，v1.42 只对 PostgreSQL 发布验收；未来切回 MySQL 为独立任务。
- 用户可提供上述平台资源；账号实际套餐、数据库区域、域名与部署权限尚未核实。
- 本轮先讨论和记录决策，不进行应用迁移、清库、付费开通或生产部署。

## 事实与边界

- PROGRESS.md 记录 v1.41 已完成 01—05；新工作台候选交付、修订/撤回等后续成果能力尚未完整接入。已有 UI 可操作不等于四环成果闭环已经具备发布条件。
- 当前应用依赖 mysql2，认证使用 NextAuth；采用 Supabase Database 不自动意味着采用 Supabase Auth。
- 新工作台 `src/lib/mysql-iteration-workbench.ts` 的生成上限为 600 秒，累计完整正文后保存，消息路由等待结束才返回 JSON；旧工作区的 SSE 行为不能当作新工作台现状。Vercel 适配须检查生成时限和失败后的终态恢复。
- `src/lib/generation-control.ts` 以进程内 Map 保存取消控制器；停止请求虽写入数据库状态，异实例生成仍可能继续消耗上游额度。首发需明确跨实例停止和费用边界。
- 当前注册与聊天路径尚未发现完整的邀请/额度控制；`src/lib/ai.ts` 在生产未配置 AI_MODE 时默认 live。低成本不能只按主机与数据库费用计算，部署验收应显式指定模式。
- 已有平台调查位于 `docs/research/vercel-supabase-alicloud-domain.md`（2026-09-23）。其中套餐、时长、区域和费用结论在确定套餐时需要按官方当前资料复核，不能作为价格或可用性承诺。
- 2026-09-27 官方复核：[Vercel Hobby](https://vercel.com/docs/plans/hobby) 定位个人非商业用途；不能仅因用于求职展示而推断成商业用途。[函数时限](https://vercel.com/docs/functions/limitations#max-duration) 中 Hobby 当前上限为 300 秒，包含流式响应发送时间。[Supabase 价格页](https://supabase.com/pricing) 写明免费项目闲置一周暂停，[生产检查清单](https://supabase.com/docs/guides/platform/going-into-prod) 说明可从 Dashboard 恢复，未承诺恢复耗时。面试前应检查状态、必要时提前恢复并实测登录和生成流程。
- 讨论文档中的建议不是已接受的产品范围；数据库迁移涉及存储与跨模块事务，实现阶段按 L2 判级。本轮只做文档变更。

## 第二轮决策前沿

1. 演示与试用访问边界：仅本人现场操作，还是让面试官/受邀者自行体验；谁能触发模型调用。
2. 真实 AI 与费用边界：模型是否由站点统一提供、可接受的费用上限。建议真实 AI 用于实际操作，另有清晰标注的已有样例供快速展示；样例不冒充实时生成。
3. 最小四环成果闭环：建议保留四阶段对话、上下文文件、候选确认创建/覆盖、刷新读取和下载，以及任务整套交付；建议推迟撤回、完整变更时间线、HTML 快照等增强能力，尚待用户确认。

实施建议而非新增产品决策：Supabase 首期仅提供 PostgreSQL，保留现有 NextAuth 登录；不引入后台任务系统、双库同步或完整管理后台。具体请求时限与恢复方式由平台限制和代码核查决定，不能省略失败可恢复的基础行为。
