# 04: 项目成果与 tickets 交付切换

**What to build:** Agent 输出从消息进入项目文件、上下文、原型快照和 tickets 版本时，完整链路由 MySQL 保存，并继续遵守项目隔离、文件边界和消息来源规则。

**Blocked by:** #03 — 对话、恢复与并发切换

**Status:** implemented-pending-mysql-verification

- [ ] 项目文件的创建、更新、版本递增、白名单、路径、大小和 ownership 校验使用 MySQL，正式文件与工作文档的既有写入语义不回归。
- [ ] tab 与项目文件的上下文关联使用 MySQL 多对多关系；跨项目文件不能被加载，历史非法关联不会进入 Agent 上下文。
- [ ] 原型 HTML 快照按项目和版本保存、回看，仍不进入普通文件树或 Agent 上下文。
- [ ] 每次 Agent 文件创建/更新都记录消息、tab、项目、文件、操作类型和文件版本来源；重生成一致性提示只认当前消息的精确来源。
- [ ] 文件与来源记录、整套 tickets 写入在失败时不会留下用户可见的半套结果。
- [ ] tickets 候选契约、整套替换、`issues/vN/` 另存、最大版本判定、完整版本选择和下载行为保持不变。
- [ ] replay 流程可以独立验证消息输出 → 文件确认 → 上下文加载 → 快照回看 → tickets 替换/另存/下载。
