# 05: 显式冻结流程切换

**What to build:** PRD 和原型 tab 在 MySQL 上完整执行“提议 → 用户确认 → 生成 → 文件确认 → 正式冻结”，失败、取消、刷新和重复请求均不会提前或重复冻结。

**Blocked by:** #03 — 对话、恢复与并发切换；#04 — 项目成果与 tickets 交付切换

**Status:** implemented-pending-mysql-verification

- [ ] 冻结状态、冻结消息、目标文件、正文摘要和处理中的并发操作以 MySQL 持久化事实为准。
- [ ] 普通聊天、肯定词、否定句和历史消息不能触发冻结；只有明确控件请求能推进状态。
- [ ] 重复点击或网络重试不会重复生成、重复写入或跳过文件确认。
- [ ] 文件正文和绑定条件在同一一致性边界内校验；同名旧文件不能被误认成当前冻结结果。
- [ ] 正式冻结后的文件不能被普通更新或删除；取消、失败和拒绝写入不会留下错误绑定。
- [ ] 刷新或重连后可以恢复处理中、待写入、失败和正式冻结等真实状态。
- [ ] 既有冻结 replay 在 MySQL 上覆盖否定句、重复确认、生成失败、取消、写入失败和刷新恢复。
