# 09: 对话与工作区 MySQL-only 收口

**Parent:** #07 — MySQL 单库收口与综合验收

**What to build:** 用户从工作区创建和操作 tab、发送与管理消息、自动命名和执行冻结时，只经过 UUID/MySQL 路径；界面不再按新旧 ID 隐藏功能，所有既有响应和错误语义保持一致。

**Blocked by:** #08 — 补齐 tab 与消息变更行为

**Status:** implemented-pending-mysql-verification

- [x] 工作区移除 MySQL/旧 ID 双分支，UUID 项目可以使用 tab 关闭、消息删除、编辑重发、文件上下文和冻结等全部既有控件。
- [x] tab、消息、聊天流、冻结、自动命名和工作记录入口只接受统一 UUID，并以 MySQL ownership 为准；旧 ObjectId 不再触发 MongoDB 回退。
- [x] API 的成功结构、状态码、冲突码、SSE 事件和用户可见错误与 v1.2 契约对齐，不能用“暂不可用”占位替代既有功能。
- [x] MySQL 不可用或瞬断时当前操作明确失败并允许手动重试，不无限重试、不后台排队、不泄露驱动堆栈或连接信息。
- [ ] 现有工作区、消息恢复、并发和冻结专项在 MySQL 路径上可执行；静态搜索不再发现这些公开入口导入 MongoDB 运行模块。
- [x] 工作区已有未提交的批量收口尝试只能作为审计输入；实现者需逐项核对 API/UI 消费契约，不能以删除旧分支或类型检查通过代替行为验收。

见 v1.3 spec 的“既有工作流兼容”“消息、生成与冻结”“故障与诊断”和“错误语义”。
