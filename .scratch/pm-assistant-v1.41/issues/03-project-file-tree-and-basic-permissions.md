# 03: 项目级文件树与基础操作

**What to build:** 将文件资产从产品迭代中提取为项目唯一的共享文件树。所有产品迭代查看同一棵树；树固定包含需求分析、原型、PRD、任务拆分四个树枝。用户可以浏览、预览、下载和在所属权限范围内改名，但不能把文件移动到另一个树枝。

**Blocked by:** 01: 产品迭代生命周期与入口工作区。可与 02 并行实现。

**Status:** needs-info（文件树主界面原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 文件树主界面如何展示四个树枝，以及普通文件和任务拆分文件夹的层级。
- 打开文件预览、下载文件和重命名文件的主操作入口。
- 没有当前产品迭代时，文件树的只读呈现方式。
- 如果不需要新的视觉方案，明确写“复用现有文件树/预览视觉风格”。

### 可选提供

- 文件行需要优先显示的少量信息或固定文案。修订、来源和可撤回信息的完整详情由第 07 票接入。

### 不需要提供

- 文件表结构、路径校验代码、权限 API、下载实现或测试脚本。

## Agent 负责

- 保证每个项目只有一棵项目级文件树，所有产品迭代共享这棵树。
- 固定四个树枝：需求分析、原型、PRD、任务拆分；不允许用户创建第五个树枝或自定义树枝。
- 普通文件使用“类型前缀 + AI 自由描述”的命名形式；具体自由描述不由系统强行改写。
- 用户可以修改文件名，但重命名必须留在原树枝，不能占用项目中已有的精确路径。
- 按精确路径区分“创建”和“覆盖”的基础事实；候选确认和覆盖写入由第 05 票完成。
- 提供项目级目录浏览、正文预览和下载能力。
- 在没有当前产品迭代时，允许查看目录、打开正文和下载；隐藏或禁用加载上下文、编辑、重命名、撤回和删除入口，并说明原因。
- 保留既有的项目 ownership、路径安全和单文件大小边界；跨用户、跨项目请求必须拒绝。
- 文件树展示当前项目资产，不把产品迭代误显示为文件树的拥有者。

## Agent 不负责

- 不在本票实现 Agent 候选确认、普通文件修订/撤回、任务整套更新或变更时间线。
- 不允许用户移动树枝、创建第五类文件、把任务文件夹转交给其他迭代。
- 不把 HTML 原型快照当作项目文件；快照边界由第 06 票实现。
- 不因为文件属于某个来源迭代，就对其他迭代隐藏普通文件；普通文件共享，任务文件夹所属权由第 08 票补充。

## 验收标准

- [ ] 同一项目创建两个产品迭代后，两者看到相同的四树枝和项目文件目录。
- [ ] 文件树始终只有需求分析、原型、PRD、任务拆分四个树枝，不能新增树枝。
- [ ] 普通文件可以打开预览和下载；下载入口拿到的是当前文件正文。
- [ ] 用户重命名普通文件时，只能修改原树枝中的名称；已有路径冲突会被拒绝且原文件不变。
- [ ] 没有当前产品迭代时可以浏览、预览和下载，但不能加载上下文、编辑、重命名、撤回或删除。
- [ ] 跨用户和跨项目的目录、预览、下载、改名请求被拒绝。
- [ ] 项目文件树与产品迭代在界面上清楚分离；不能把文件显示成某个迭代私有的资产。
- [ ] 关键文件树主界面与产品经理提供的原型或明确复用方案一致。
