# 01: 创建与管理产品迭代

**What to build:** 用户从项目进入产品迭代列表，创建并进入一个产品迭代。每个迭代有不可修改的稳定编号、可修改的展示名称和可选的本轮目标；创建后可以继续修改展示名称和目标。项目可以同时存在多个迭代，迭代负责组织本轮工作，不拥有项目文件。

**Blocked by:** None (can start immediately)

## 产品经理在 Agent 开始前提供

原型包名称：01 产品迭代生命周期
可访问路径：`.scratch/pm-assistant-v1.41/prototypes/01-product-iteration-lifecycle.html`
主流程：从项目进入产品迭代列表，查看已有迭代，打开创建抽屉；填写名称后选择填写目标或暂不填写，暂不填写进入一次风险确认；创建成功后自动进入工作区，并可修改展示名称和本轮目标。
必须展示的状态：目标选项默认不选；填写目标分支；暂不填写分支；风险确认中的 Agent 已知/未知；返回保留草稿；确认后本次不重复警告；稳定编号不可编辑；目标为空时的可解释空状态；保存中与保存成功反馈。
固定文案：`暂不填写本轮目标？`、`Agent 已知`、`Agent 未知`、`返回重新选择`、`确认暂不填写`；风险说明为“Agent 只会知道项目、迭代编号、你手动加载的文件，以及你在对话中提供的内容。”“它不会知道本轮要改变什么，也不会根据迭代名称或文件目录替你猜测。”
复用来源：复用 `C:\Users\Administrator\OneDrive\Desktop\prototype\任务简报.html` 与 `落地页.html` 的 AI 产品现场色板、字体角色、纸色/墨黑分区、编号与编辑化信息节奏；工作场景采用 Operate 型列表、创建抽屉和工作区最小壳，完整阶段行为由后续 02-04 票补齐。
与 spec 冲突的地方：无。
开工结论：已覆盖本票关键输入，可开始实现。

**Status:** ready-for-agent

- [ ] 同一项目可以创建至少两个迭代；稳定编号递增、持久且不会因刷新或重新进入而改变。
- [ ] 展示名称是主标题并可修改；稳定编号显示为不可编辑的“迭代 NN”次级信息。
- [ ] 创建时填写目标和暂不填写均不默认选中；填写目标后保存并可重新看到。
- [ ] 直接选择暂不填写，或填写后改选暂不填写，都会先出现风险确认；返回保留草稿，确认后才创建。
- [ ] 确认暂不填写后本次不重复警告；创建后仍可补充目标，系统不自动猜测目标。
- [ ] 主流程布局和关键文案与已提供原型或复用确认一致。
