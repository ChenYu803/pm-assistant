# 01: 产品迭代生命周期与入口工作区

**What to build:** 在一个项目内创建和管理多个产品迭代。产品迭代负责承载本轮目标、四环阶段和阶段会话；项目文件不在本票中实现。用户可以从项目进入产品迭代列表，创建迭代，查看稳定编号和展示名称，并在创建后修改展示名称或补充、修改本轮目标。

**Blocked by:** None (can start immediately)

**Status:** needs-info（产品经理的关键主流程原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 项目页进入产品迭代列表的主路径。
- 创建产品迭代的主界面，以及“填写本轮目标”和“暂不填写”的选择方式。
- 暂不填写目标时的风险确认界面：用户可以返回重新选择，也可以确认暂不填写。
- 产品迭代列表和工作区中，展示名称与“迭代 NN”的层级关系：展示名称是主标题，稳定编号是不可编辑的次级信息。
- 如果不需要新的视觉方案，明确写“复用现有项目页/工作区视觉风格”。

### 不需要提供

- 数据库表结构、API 设计、组件拆分、测试脚本或其他技术方案。
- 加载、网络失败等普通状态的逐像素设计；Agent 按已确认的主界面补齐。

## Agent 负责

- 让一个项目拥有多个产品迭代，并在项目内为每个新迭代分配单调递增的稳定编号。
- 已删除迭代的编号永久作废，后续创建不得复用。
- 保存展示名称和本轮目标；展示名称可修改，稳定编号不可修改。
- 创建表单中“填写本轮目标”和“暂不填写”均默认不选中。
- 用户直接选择“暂不填写”，或从“填写目标”改选为“暂不填写”时，显示一次风险确认。风险确认必须提供“返回重新选择”和“确认暂不填写”两个结果。
- 用户返回时保留此前的选择和目标草稿；用户确认暂不填写后，本次创建不再重复同一警告，并允许之后补充目标。
- 未填写目标时，不根据迭代名称、目录或未加载的文件正文猜测目标。
- 处理刷新、重复打开、跨页面返回和权限失败，并保持已保存的编号、名称和目标一致。

## Agent 不负责

- 不实现四环阶段状态、阶段会话、项目文件树、上下文注入或文件写入；这些由后续票处理。
- 不自行改变目标风险确认的含义、文案取舍或编号展示层级。
- 不把旧的“工作记录”作为新的用户可见术语；当前用户界面统一使用“产品迭代”。

## 验收标准

- [ ] 从一个项目进入产品迭代列表可以创建至少两个产品迭代；第二个迭代的编号大于第一个。
- [ ] 编号分配在项目范围内具备不可复用的持久基础；本票不实现完整删除流程，删除确认、来源占位和任务归档由第 09 票验收。
- [ ] 展示名称可以修改，稳定编号始终不可编辑；列表和工作区均显示正确的名称与编号。
- [ ] 创建时两个目标选项均未默认选中；选择填写后保存的目标可在重新打开迭代时看到。
- [ ] 直接选择暂不填写，或填写后改选暂不填写，都会出现一次风险确认；返回会保留草稿，确认后才能继续创建。
- [ ] 创建后不重复弹出同一暂不填写警告，并且用户可以在迭代工作区补充或修改目标。
- [ ] 未填写目标的迭代不会因为名称、目录或未加载正文被系统自动补写目标。
- [ ] 关键主流程与产品经理提供的原型或明确的复用方案一致；普通加载和失败状态不破坏主流程。
