# 07: 普通文件修订、一次撤回与变更记录

**What to build:** 为项目普通文件提供有限但可靠的修订和追溯能力：每次正文变化产生递增修订号，只保留紧邻当前正文的一版备份并支持一次撤回；重命名和删除只记录操作，不伪装成正文变化。用户可以在当前产品迭代中编辑、重命名、撤回或删除文件，并在文件详情和产品迭代的“本轮写入”中看到来源事实。

**Blocked by:** 05: 普通文件候选确认与通用耐久写入

**Status:** needs-info（文件详情/撤回/变更记录关键主界面原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 文件详情入口和主界面，包括当前正文、基本元数据、编辑、重命名、撤回和删除入口。
- 撤回可用与无备份时的主要呈现方式。
- 变更时间线和产品迭代“本轮写入”的主界面或明确复用方案。
- 如果不需要新的视觉方案，明确写“复用现有文件详情/确认弹窗视觉风格”。

### 可选提供

- 你特别想显示的固定文案。完整历史正文浏览、重做等能力不在本票范围内。

### 不需要提供

- 修订表、事务、锁、来源字段、API 或验证脚本设计。

## Agent 负责

- 普通文件创建得到内容修订 1；覆盖、用户编辑和撤回都生成新的单调递增内容修订号。
- 覆盖或用户编辑前，把当前正文替换为唯一“上一版备份”，再写入新正文；下一次正文变化会替换这份备份，不保存更早版本。
- 有上一版备份时允许撤回：把备份正文作为新的 restore 修订写回，消耗备份；被撤回的新正文不保留，不能重做。
- 撤回后无备份；下一次正文变化重新建立一份新的上一版备份。
- 重命名不改变文件身份、内容修订号、最近正文来源或可撤回目标；只追加重命名操作记录。
- 删除文件时永久删除当前正文和唯一备份，不提供恢复；保留轻量已删除占位、路径快照和来源解释所需的操作记录。
- 所有正文写入、备份替换、修订递增和变更记录在同一个原子操作中完成；失败不得留下不一致的正文、备份或记录。
- 文件详情至少显示：当前路径、当前修订、创建来源、最近正文写入来源、操作者/操作方式、时间、可撤回目标和轻量变更时间线。
- 产品迭代显示“本轮写入”汇总；用户直接操作标记为用户操作，不伪造 Agent 会话或消息来源。
- 变更记录是项目级永久元数据，不依赖消息、阶段会话或产品迭代外键级联删除；来源名称和编号使用写入时快照。
- 下载和正文预览保持纯 Markdown，不注入 changelog 或元数据。

## Agent 不负责

- 不实现完整 Git 式历史、任意旧版浏览、分支、合并或重做。
- 不增加覆盖前的“内容可能过期”警告；用户确认的覆盖直接生效。
- 不允许没有当前产品迭代时的编辑、重命名、撤回和删除；基础入口由第 03 票确定。
- 不替产品经理决定详情页视觉层级、时间线文案或哪些非事实信息应该显示。

## 验收标准

- [ ] 创建文件得到修订 1；连续两次覆盖/编辑后修订号严格递增，每次只保留最近一版备份。
- [ ] 撤回把上一版写成新的 restore 修订，修订号不倒退，备份被消耗且没有重做入口。
- [ ] 撤回后再次编辑会重新建立新的上一版备份。
- [ ] 重命名不增加内容修订，不改变最近正文来源；路径冲突时重命名失败且原路径不变。
- [ ] 删除后正文和备份不可恢复，但项目级轻量记录仍能解释文件曾经存在和如何被删除。
- [ ] 注入正文写入失败时，正文、备份、修订号和变更记录均保持失败前状态。
- [ ] 文件详情和本轮写入显示的来源、操作者、修订、时间和撤回事实准确；用户操作不伪造 Agent 来源。
- [ ] 删除消息或阶段会话后，项目文件和已发生的项目级变更记录不因级联而消失；产品迭代删除后的占位显示由第 09 票继续验收。
- [ ] 文件详情/时间线主界面与产品经理提供的原型或明确复用方案一致。
