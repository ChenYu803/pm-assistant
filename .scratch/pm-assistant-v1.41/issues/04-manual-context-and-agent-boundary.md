# 04: 手动上下文与 Agent 读取边界

**What to build:** 让上下文文件区域成为 Agent 读取项目文件正文的唯一入口。用户可以从项目文件树把文件加入当前阶段会话，也可以移除；未加入的文件只以轻量目录元数据显示，Agent 不会自动读取所有项目文件。

**Blocked by:** 02: 四环导航、阶段状态与多会话；03: 项目级文件树与基础操作

**Status:** needs-info（上下文区域主界面原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 上下文文件区域的主界面，以及从文件树加入和移除文件的操作方式。
- 空上下文时用户看到的事实说明。
- 已加载文件如何在界面上区别于项目中存在但未加载的文件。
- 如果不需要新的视觉方案，明确写“复用现有上下文区域/文件树视觉风格”。

### 可选提供

- 来源摘要的展示偏好。摘要事实由 spec 固定，普通排列和收起状态由 Agent 补齐。

### 不需要提供

- prompt 拼接代码、上下文长度算法、数据库结构或 API 设计。

## Agent 负责

- 只能通过上下文文件区域加载或移除文件；点击文件、打开预览或看到目录本身不等于加载。
- 每个阶段会话独立保存自己的文件引用；切换会话后不串用其他会话的上下文文件。
- 空上下文向 Agent 提供：当前项目、当前产品迭代、当前阶段、当前目标（可能为空）和项目文件轻量目录；不提供任何未加载文件正文。
- 目录元数据至少包含路径、树枝、当前内容修订、最近正文写入迭代和可撤回状态；这些元数据不等于正文。
- 每次发送消息时，按照当前会话保存的文件引用读取文件当前正文和同一次读取得到的修订/来源摘要，不能使用过期正文快照。
- 文件被其他迭代覆盖后，下一条消息读取最新正文和最新同版元数据。
- 移除文件后，下一条消息不再注入该文件正文。
- 完整变更时间线、未加载正文、其他会话消息和项目完整设计史不自动进入普通对话。
- Agent 被问及未加载文件时必须说明自己没有读过正文，可以建议用户把具体文件加入上下文；不能假装读过。
- 加载文件本身不被解释为继承、认可、批判或修改；具体意图由用户在对话中表达。
- 没有当前阶段会话时不能创建上下文引用；没有当前产品迭代时不能加载文件。

## Agent 不负责

- 不根据文件名、目录、来源迭代或目标为空自动推断用户意图。
- 不默认全文读取项目文件，不提供“未选择文件但自动全部注入”的兜底模式。
- 不把完整时间线塞进 system prompt，也不要求用户理解 prompt 技术细节。

## 验收标准

- [ ] 空上下文时 Agent 能知道项目、迭代、阶段、目标和轻量目录，但无法从请求中获得任一未加载文件正文。
- [ ] 用户从上下文区域加载一个文件后，Agent 收到该文件当前正文和同次读取的修订/来源摘要。
- [ ] 其他迭代覆盖该文件后，下一次发送读取新正文；旧的上下文正文不会继续复用。
- [ ] 用户移除文件后，下一次发送不再包含该文件正文。
- [ ] 完整变更时间线和其他会话消息不出现在普通对话上下文中。
- [ ] Agent 明确承认未加载文件没有读过；加载动作不会被解释为继承、认可、批判或修改。
- [ ] 没有当前阶段会话或当前产品迭代时，加载入口不可用且原因清楚。
- [ ] 上下文区域主界面与产品经理提供的原型或明确复用方案一致。
