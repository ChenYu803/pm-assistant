# 10: PRD 候选与耐久交付

**What to build:** PRD 阶段 Agent 可以根据当前会话和用户加载的文件提出 PRD Markdown 候选。用户审阅后确认创建、确认覆盖或放弃；确认后纯正文进入项目文件树的 PRD 树枝，放弃或失败不改变项目文件。PRD 候选必须满足当前已确认的 PRD 结构要求。

**Blocked by:** 07: 需求分析候选与首次耐久写入

## 产品经理在 Agent 开始前提供

- 原型范围参照 `.scratch/pm-assistant-v1.41/v1.41-prototype-inputs.md` 的 10 号条目；实际 open-design 链接或仓库路径待产品经理交付，并需覆盖 PRD 候选预览、创建/覆盖/放弃和写入失败重试的主流程。
- PRD 候选确认区域的固定文案、结构展示偏好或明确复用 07 号候选确认视觉。

**Status:** needs-info

缺口：本票所需的实际可访问原型、复用来源和固定文案/特殊行为说明尚未完整交付。

- [ ] 未确认的 PRD 候选不会出现在项目文件树、上下文文件目录或修订记录中。
- [ ] 候选只能写入 PRD 树枝；确认前可以修改文件名，但不能改到其他树枝。
- [ ] 目标路径不存在时标为创建，已存在时标为覆盖；确认区显示路径和操作类型。
- [ ] 确认后项目文件树出现纯 Markdown PRD 正文；放弃或失败后文件、备份、修订和变更记录保持原样。
- [ ] PRD 候选遵守已确认的六章结构；系统不自动追加 changelog、来源或版本说明。
- [ ] 主流程与已提供原型或复用确认一致。
