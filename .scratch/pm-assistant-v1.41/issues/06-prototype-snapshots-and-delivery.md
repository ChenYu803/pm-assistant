# 06: 原型快照与原型阶段交付

**What to build:** 让原型设计阶段同时支持两种互不混淆的成果：可反复生成、回看和下载的 HTML 可视化快照，以及经用户确认后进入项目“原型”树枝的结构化 Markdown 文件。HTML 快照不是项目文件，也不是上下文文件。

**Blocked by:** 05: 普通文件候选确认与通用耐久写入

**Status:** needs-info（原型快照与结构化成果的关键主界面原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 原型阶段生成 HTML 预览、回看、下载的主界面或明确复用方案。
- 结构化原型 Markdown 候选如何进入第 05 票的普通候选确认界面。
- 你是否需要固定的预览/确认文案；未指定的普通状态由 Agent 补齐。

### 不需要提供

- HTML 存储表、快照接口、文件 marker、数据库绑定或测试脚本。

## Agent 负责

- 原型 Agent 生成的 HTML 预览保存为项目级独立快照，支持在产品内回看和下载。
- HTML 快照不进入项目文件树，不出现在上下文文件区域，不参与普通 Markdown 文件的修订和覆盖。
- 原型阶段生成结构化 Markdown 后，按第 05 票的候选规则等待用户确认；确认后写入原型树枝，放弃或失败不落盘。
- 同一产品迭代和多个平等阶段会话可以产生多个快照和候选；不以某个“主会话”或冻结状态限制交付。
- 移除旧的 scope-freeze/冻结锁定作为原型成果交付前置条件的语义；“生成快照”和“确认 Markdown 写入”是两个独立动作。
- HTML 预览失败时明确显示失败并允许重试，不伪装成已保存或已交付。

## Agent 不负责

- 不把 HTML 快照转成项目文件或自动写入原型 Markdown。
- 不替产品经理决定原型内容、视觉方向、页面布局或固定文案。
- 不在本票实现普通文件的一次撤回、完整来源时间线或产品迭代删除后的归档；分别由第 07、09 票完成。

## 验收标准

- [ ] 原型 Agent 生成 HTML 后，用户可以回看和下载；快照不出现在四个树枝和上下文文件列表中。
- [ ] 结构化原型 Markdown 进入普通候选确认区；未确认前原型树枝不改变。
- [ ] 用户确认后，结构化 Markdown 进入原型树枝；放弃或失败后不产生项目文件、修订或写入记录。
- [ ] 生成 HTML 快照不自动冻结阶段，也不自动写入 Markdown；确认 Markdown 不要求额外的冻结锁定步骤。
- [ ] HTML 生成失败时原有快照和未确认候选不被误显示为成功，并可以重试。
- [ ] 快照和原型 Markdown 的主界面与产品经理提供的原型或明确复用方案一致。
