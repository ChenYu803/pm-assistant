# 07: 需求分析候选与首次耐久写入

**What to build:** 在需求分析阶段打通第一条可演示的文件交付路径：Agent 依据当前会话内容提出需求分析 Markdown 候选，用户可以预览、修改文件名后确认创建、确认覆盖或放弃；确认后文件出现在项目文件树的需求分析树枝，放弃或失败不会改变项目文件。

**Blocked by:** 06: 手动上下文与 Agent 读取边界

## 产品经理在 Agent 开始前提供

- 实施模式：正式代码直接实现。
- 无新增输入。在 02 正式工作台内完成第一套候选审阅交互，清楚区分创建、覆盖、放弃和失败重试；该正式实现将成为 09、10、14 号票的复用基线。

**Status:** ready-for-agent

- [ ] 候选生成、预览和重新生成不会改变项目文件或文件树。
- [ ] 候选只能写入需求分析树枝；用户确认前可以修改文件名，但不能改变树枝。
- [ ] 目标路径不存在时显示创建，存在时显示覆盖；确认区同时显示目标路径和操作类型。
- [ ] 确认后文件树出现纯 Markdown 正文；放弃后文件树和记录保持原样。
- [ ] 写入失败时不出现半成品，候选保留并可重试。
- [ ] 候选审阅层级与正式工作台一致，产品经理可以直接在真实写入流程中验收并提出修改。
