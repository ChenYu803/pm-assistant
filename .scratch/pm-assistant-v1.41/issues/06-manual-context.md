# 06: 手动上下文与 Agent 读取边界

**What to build:** 让上下文文件区域成为 Agent 读取项目文件正文的唯一入口。用户可以从项目文件树把文件加入当前阶段会话，也可以移除；未加入的文件只以轻量目录元数据显示，Agent 不会自动读取整个项目的正文。

**Blocked by:** 03: 阶段会话隔离；05: 项目级文件树与基础操作

## 产品经理在 Agent 开始前提供

- 实施模式：复用已落地界面。
- 无新增输入。复用 02 已落地的“项目文件树 / 当前上下文”标签区，在正式产品中补齐加入、移除、空上下文和已加载/未加载的区别。

**Status:** resolved

- [x] 查看预览或目录不会自动加载文件；只有上下文文件区域的加载操作会加入引用。
- [x] 空上下文时 Agent 能知道项目、迭代、阶段、目标和轻量目录，但请求中没有未加载文件正文。
- [x] 目录元数据至少能看到路径、树枝、当前修订、最近正文写入迭代和可撤回状态。
- [x] 每次发送消息按当前引用读取最新正文，并注入同次读取的修订和来源摘要。
- [x] 文件被覆盖后下一条消息读取新正文；移除文件后下一条消息不再注入正文。
- [x] 完整时间线、其他会话消息和项目设计史不会自动进入普通对话；未加载文件被问及时 Agent 明确说明没有读过。
- [x] 没有当前迭代或阶段会话时加载入口不可用且原因清楚；交互沿用 02 正式文件区并可直接验收。

当前成果模型尚未记录新工作台的最近正文写入迭代和可撤回旧版；此时元数据明确显示“未记录 / 不可撤回”，后续成果票建立来源和旧版后应以真实事实替换。
