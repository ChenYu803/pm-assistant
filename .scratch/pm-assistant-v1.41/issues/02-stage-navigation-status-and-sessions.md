# 02: 四环导航、阶段状态与多会话

**What to build:** 在产品迭代工作区中提供四环一级导航和阶段会话。用户始终能看到需求分析、原型设计、PRD、任务拆分四个阶段，可以按推荐顺序工作，也可以跳过、返回或直接进入任一阶段；每个阶段有独立的持久状态，并且同一阶段可以有多个地位相同的阶段会话。

**Blocked by:** 01: 产品迭代生命周期与入口工作区

**Status:** needs-info（本票的关键导航/会话主界面原型或复用确认尚未补齐；补齐后改为 `ready-for-agent`）

## 产品经理在 Agent 开始前提供

### 必须确认

- 四环一级导航的主界面和四个阶段的推荐顺序。
- 进入阶段、创建新阶段会话、切换阶段会话和删除阶段会话的主操作方式。
- 阶段状态在界面中的呈现方式，以及“完成本阶段”“重新打开”两个操作的入口。
- 如果不需要新的视觉方案，明确写“复用现有阶段工作台/会话视觉风格”。

### 可选提供

- 你特别在意的固定文案或视觉参考。未提供的普通空、加载、失败和禁用状态由 Agent 按主界面补齐。

### 不需要提供

- 状态表、数据库、API、前端组件、并发方案或测试脚本。

## Agent 负责

- 将四个阶段作为始终可见的一级导航：需求分析、原型设计、PRD、任务拆分；显示推荐顺序但不设置硬门禁。
- 用户进入缺少前置成果的后续阶段时，说明可能影响但允许继续；用户可以跳过、返回或直接进入任一阶段。
- 为每个产品迭代分别保存四个阶段的三种状态：未开始、进行中、已完成。
- 用户第一次创建或打开某阶段会话时，将该阶段从未开始变为进行中。
- 只有用户明确点击“完成本阶段”才变为已完成；没有写入文件也可以完成。
- 生成中的 Agent 请求未结束或被停止前，禁止完成阶段。
- 待确认候选不阻止完成阶段，并继续留在产生它的原阶段会话中。
- 重新进入已完成阶段时，将该阶段恢复为进行中。
- 同一阶段允许创建多个阶段会话；每个会话的消息、过程状态和上下文文件引用相互隔离，所有会话地位相同。
- 删除阶段会话前提示：该会话中的未确认候选会随对话丢失；已经写入的项目文件和变更记录不因会话删除而消失。
- 空阶段只展示可执行的开始提示，不自动创建会话、不自动加载文件、不自动发送问候消息。
- 刷新或换设备后从服务端恢复阶段状态，而不是依赖浏览器临时状态。

## Agent 不负责

- 不根据文件是否存在、候选数量或其他迭代变化自动推断阶段状态。
- 不把前置阶段变成不可跳过的硬门禁。
- 不替产品经理决定阶段文案、视觉层级或会话删除提示的核心含义。
- 不在本票实现候选写入、项目文件版本、任务整套更新或来源时间线；这些由后续票处理。

## 验收标准

- [ ] 四个阶段始终可见，用户可以按推荐顺序，也可以直接进入任一阶段；缺少前置成果只提示影响，不阻止进入。
- [ ] 阶段状态只出现未开始、进行中、已完成；进入或打开会话后状态变为进行中，显式完成后才变为已完成。
- [ ] 无文件写入时仍可完成阶段；有待确认候选时仍可完成阶段，候选仍在原会话中。
- [ ] 生成中不能完成阶段；停止或生成结束后，完成入口按事实恢复。
- [ ] 重新打开已完成阶段会变为进行中；刷新和重新打开页面后状态仍正确。
- [ ] 同一阶段创建两个会话后，消息和上下文彼此隔离；两个会话都能提出候选，不存在主会话/子会话优先级。
- [ ] 删除会话前明确提示未确认候选会丢失；删除后已写入项目文件的来源记录仍可保留（记录保留的完整语义由第 09 票验收）。
- [ ] 空阶段不会自动发送消息或创建会话。
- [ ] 关键导航和主操作与产品经理提供的原型或明确复用方案一致。
