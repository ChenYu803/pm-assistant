# 14: 任务拆分整套提交

**What to build:** 所属迭代的 Agent 或用户可以提出一套新的任务 issue 集合。用户审阅新增、更新和删除差异后只能整体确认或整体放弃；确认后任务文件夹一次性变为候选集合的完整真相，不能出现新旧 issue 混杂。

**Blocked by:** 07: 需求分析候选与首次耐久写入；13: 任务文件夹归属与跨迭代只读

## 产品经理在 Agent 开始前提供

- 原型范围参照 `.scratch/pm-assistant-v1.41/v1.41-prototype-inputs.md` 的 14 号条目；实际 open-design 链接或仓库路径待产品经理交付，并需覆盖任务集合候选、差异审阅、整套确认/放弃和失败重试的主流程。
- 新增、更新、删除差异的呈现方式及整套确认文案；未提供的视觉复用候选确认区域。

**Status:** needs-info

缺口：本票所需的实际可访问原型、复用来源和固定文案/特殊行为说明尚未完整交付。

- [ ] 候选集合可以同时包含新增、更新和删除 issue，用户能看懂每类差异。
- [ ] 用户不能只确认部分 issue；整套确认后文件夹内容与候选集合完全一致。
- [ ] 确认失败时旧集合完全不变，候选仍可处理和重试，不出现半套结果。
- [ ] 每个 issue 保留稳定身份和递增内容修订；纯改名或删除不增加内容修订。
- [ ] 任务集合提交产生可追溯的整套变更记录，并遵守所属迭代权限。
- [ ] 主流程与已提供原型或复用确认一致。
