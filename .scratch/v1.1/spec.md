# PM Assistant v1.1 — Spec（使用体验改进）

Status: ready-for-agent

## Problem Statement

v1.0 四环流水线已跑通（作者本人走完「想法 → 需求分析.md → 原型.md → prd.md → issues」），但使用体验上仍有几类缺口：

1. **工作记录名不可控**：名称只能等 AI 在对话 3 条后自动生成，用户无法自己起名；创建时也没有命名入口。
2. **空状态引导错误**：新工作记录无标签页时提示「新建一个标签页开始工作」并平铺 4 个 Agent 类型——不引导新人从流水线起点（需求分析）开始，求职 PM 可能随意选一个 Agent 走错入口。
3. **Agent 自我说明不足**：选择标签页时每个 Agent 只有一句话「做什么」，没说「需要你提供什么 / 会产出什么 / 在流水线中的位置」——新人不知道「带什么来、能带走什么」。
4. **对话框缺市面 LLM 聊天框标配**：无复制、无重新输出、无停止生成（中断只发生在切换标签页时且无提示）、无删除消息；流式期间输入框禁用；新 token 强制滚动拽走翻历史的用户；自己的消息不能编辑重发。
5. **已写入文件无法更新（bug，实测发现）**：正式文件（需求分析.md/原型.md/prd.md）写入后，继续对话让 Agent 修改，不会再触发写入判定——文件永远不更新。工作文档（静默写入路径）不受影响，issues/ 编号文件概率低。

## Solution

从用户视角：v1.1 让工作记录全程可命名、空状态把新人导向流水线第一步、每个 Agent 说清「带什么来、带走什么」、对话框补齐市面标配交互，并修复「文件写入后无法更新」的 bug。

- **工作记录命名**：创建时可填名称（可选），留空仍走 AI 自动命名兜底；列表页行内 + 工作区顶栏两处改名入口；用户手动命名后 AI 不再覆盖。创建流程顺手一步化（名称 + 回车即建，去掉「确认创建」冗余步骤）。
- **空状态引导**：无标签页时展示四步流水线全景（每步一句话职责），仅「需求分析」可点击创建，后三步锁定（显示「完成前置步骤后开启」）；已有标签页后新建 tab 仍走完整 Agent 选择。
- **Agent 自我说明**：选择标签页时每个 Agent 重写一句话 + 四段结构化说明（职责 / 需要你提供什么 / 会产出什么 / 流水线位置）；tab 空状态保留并重写「现在该说什么」的操作提示。
- **对话框功能**：复制（渲染后文本）/ 替换式重新输出 / 删除单条消息（确认弹窗）/ 停止生成（保留部分内容）/ 智能滚动 / 流式期间可打字 / 编辑并重新发送。
- **补充体验**：任务拆分多文件批量确认、上下文长度预警（粗估、不阻塞主流程）、重生成与已写入文件的一致性提示。
- **文件更新 bug 修复**：写入判定依据从「文件名是否已存在」改为「该消息是否已写入」，历史重放扫描保留文件名兜底；需求分析.md append / 其他 replace 的写入语义不变。

## User Stories

未列出的 MVP / v1.0 stories 继续有效（账户、项目、工作记录、文件系统基础、四环协议、错误与边界）。

### 工作记录命名

1. 作为一个用户，我想在创建新工作记录时填写名称，以便不用等 AI 自动命名。
2. 作为一个用户，我想创建时留空名称（显示「未命名」），以便 AI 在首次对话后自动命名（兜底不变）。
3. 作为一个用户，我想在工作记录列表页对任意工作记录点击「改名」，以便整理和识别。
4. 作为一个用户，我想在工作区顶栏点击工作记录名称直接改名，以便正在使用时顺手改。
5. 作为一个用户，我想一旦我手动起名（创建时或改名），AI 自动命名不再覆盖它，以便名字始终由我掌控。
6. 作为一个用户，我想创建工作记录时输入名称后回车即创建，以便不经过冗余的「确认创建」步骤。

### 空状态引导

7. 作为一个新用户，我想在空工作记录里看到四步流水线全景（需求分析 → 原型 → PRD → 任务拆分）且每步有一句话职责说明，以便一眼看懂这个产品是干什么的。
8. 作为一个新用户，我想空状态下只有「需求分析」可点击创建标签页，以便从流水线起点开始，不被其他 Agent 带偏。
9. 作为一个用户，我想点击锁定的流水线步骤时得到轻提示（「完成前置步骤后开启」），以便知道为什么不能点。
10. 作为一个已有标签页的用户，我想 TabBar「+」仍能选择任意 Agent 类型，以便自由开新标签页（不受空状态锁定限制）。

### Agent 自我说明

11. 作为一个用户，我想在创建标签页时看到每个 Agent 的四段说明（职责一句话 / 需要我提供什么 / 会产出什么 / 在流水线中的位置），以便知道「带什么来、能带走什么」。
12. 作为一个用户，我想空标签页里的操作提示重写得更直白（「描述你想做的产品或想解决的问题，我来帮你一步步梳理」），以便知道现在该说什么。

### 对话框功能

13. 作为一个用户，我想 hover 任意消息出现复制按钮，复制我看到的文本（不含协议 marker），以便转发和留存。
14. 作为一个用户，我想对最后一条 AI 回复点击「重新输出」，旧回复被替换为重新生成的新回复，以便得到更好的回答。
15. 作为一个用户，我想可以多次重新输出直到满意，以便比较不同版本。
16. 作为一个用户，我想删除任意单条消息（用户/AI 均可，删除前有确认弹窗，不可恢复），以便清理不满意的内容。
17. 作为一个用户，我想 AI 生成期间点击「停止生成」立即中断，已生成的部分内容保留在对话中并标注中断，以便及时止损且不丢已有成果。
18. 作为一个用户，我想向上滚动翻历史时新 token 不把我拽回底部（仅在接近底部时自动跟随），以便安心回看。
19. 作为一个用户，我想 AI 生成期间仍能打字（只是不能发送），生成完成后直接发送，以便不浪费等待时间。
20. 作为一个用户，我想编辑自己已发送的消息并重新发送，该消息之后的所有消息被移除，以便修正错别字或补充内容。

### 补充体验

21. 作为一个用户，我想任务拆分 Agent 一次输出多个文件时在一次弹窗里勾选并批量写入/丢弃，以便不用逐个点确认（现状 6 个文件点 6 次）。
22. 作为一个用户，我想在输入框附近看到对话上下文的粗略用量，接近上限时预警，以便了解还能聊多久。
23. 作为一个用户，我想重新输出时若旧回复的文件已写入项目且新回复不再输出该文件，收到「文件可能不同步」提示并选择是否更新，以便 vibe coding 链路不拿到新旧不一致的文件。

### 文件更新修复

24. 作为一个用户，我想需求分析.md 写入后继续对话提出修改，能再次看到写入确认并更新文件，以便文件不永久冻结。
25. 作为一个用户，我想原型.md、prd.md 同样能通过后续对话更新，以便各环交付物都可迭代。
26. 作为一个用户，我想拒绝写入时文件不落盘（保留现状语义），以便我对每次写入有控制权。

## Implementation Decisions

- **工作记录命名**：工作记录创建接口扩展可选 `name` 字段（空 = 现状「未命名」）；新增/复用工作记录级改名接口（列表页行内按钮与工作区顶栏点击共用）。自动命名触发条件不变（仅「未命名」时），用户手动命名后不再覆盖——既有判定逻辑已满足，需验证。创建面板一步化：面板内含名称输入框，回车即创建，移除「确认创建」中间步骤。
- **空状态引导**：流水线步骤元数据（icon / 名称 / 职责一句话 / 步骤序号 / 锁定规则）收敛到 Agent 类型常量模块，空状态渲染与 Agent 选择弹窗共用同一数据源（避免两处文案漂移）。空状态仅「需求分析」可创建 tab；锁定步骤灰显 + 点击轻提示。
- **Agent 自我说明**：Agent 类型常量扩展结构化说明字段（职责 / 输入 / 输出 / 流水线位置）；Agent 选择弹窗卡片渲染四段；tab 空状态操作提示文案重写（与四段说明互不重复）。
- **对话框消息操作区**：消息 hover 显示操作按钮——复制（写入剪贴板的是渲染后纯文本，即剥离协议 marker 的文本）/ 删除（确认弹窗后调删除接口）/ 重新输出（仅最后一条 AI 回复出现）/ 编辑（仅用户消息出现）。
- **替换式重新输出**：聊天接口扩展「重生成模式」——服务端不保存新用户消息、移除最后一条 assistant 消息、以既有上下文重新生成；前端以新回复替换旧回复显示。可连续多次。
- **删除单条消息**：新增标签页内删除指定消息的接口；删除后该消息不再出现在历史中（服务端历史查询天然生效）。
- **停止生成**：流式期间发送按钮切换为「停止」，点击触发既有中断机制；中断后已生成内容落为正式消息（标注中断，如「[回复已中断]」），刷新后仍可见——与现状错误分支保存 partial 的行为一致。
- **智能滚动**：仅当滚动容器接近底部（阈值内）时自动跟随新 token；用户向上滚动后停止跟随，回到接近底部再恢复。
- **流式期间可打字**：输入框在流式期间不禁用，仅发送按钮禁用。
- **编辑并重新发送**：编辑用户消息 → 删除该消息之后的所有消息 → 以编辑后的内容走既有发送流程（服务端按新消息处理，不重复保存用户消息）。
- **文件批量确认**：待确认文件队列弹窗改为列表形态（一次展示全部待确认文件，勾选 + 批量写入/丢弃）；工作文档静默写入路径不变；「拒绝不落盘」语义保留。
- **上下文长度预警**：输入框附近辅助位显示粗略用量（字符数/4 粗估），接近上限预警。**实现红线**：估算必须便宜；显示在辅助位，失败/异常静默降级为不显示；不得阻塞或拖慢聊天主流程（与 auto-name 20s 超时同理：辅助功能可牺牲，核心链路不可阻塞）。
- **重生成与文件一致性**：重新输出完成后，比较旧回复已写入的文件集合与新回复输出的文件集合——新回复不再输出旧文件时，提示「已写入文件与新回复可能不同步」，用户选择更新（走既有写入流程）或保持不变。
- **文件更新 bug 修复**：写入判定依据从「文件名是否已存在」改为「该消息是否已写入」（消息级写入状态，页面刷新后由历史消息重放 + 文件名兜底重建）；仅历史重放扫描使用文件名兜底，正常对话中的新消息总是走写入判定。需求分析 append / 其他 replace 的服务端写入语义不变。

## Testing Decisions

- **好测试的标准**：只测外部行为——UI 可见状态（按钮出现/消失、弹窗、文案）与 API 数据（文件内容、消息列表、工作记录名）；不测实现细节（组件内部 state、函数签名）。
- **验证模式**：默认使用 `AI_MODE=replay` 固定回放，不调用真实模型、不消耗 API。回放覆盖 UI、SSE、marker、确认框、冻结状态、文件写入、数据库断言和协议行为；这些外部行为不依赖真实模型验证。
- **测试缝（seam）**：最高测试缝是 v1.1 综合回放验证入口，沿用现有 verify 脚本的 Playwright 驱动 UI、直调 API、幂等新用户建号和 `check()` 断言模式。`scripts/verify-v11-ux.mjs` 当前尚不存在，应由 ticket08 在 ticket02-ticket07 完成后实现；在此之前不能把它描述为现有能力。现有验证脚本保持不变；`verify-v1-flow.mjs` 作为已有四环回归入口，按风险和发布候选纪律运行，不构成日常真实模型回归要求。
- **覆盖模块**：工作记录创建/改名（含一步化流程）、空状态渲染（流水线全景 + 锁定）、Agent 选择弹窗四段说明、消息操作区（复制/删除/重新输出/编辑重发）、停止生成、智能滚动、流式可打字、文件批量确认、文件更新修复、上下文长度预警显示。断言应优先通过回放和 UI/API 外部行为完成。
- **真实模型边界**：`AI_MODE=live` 只用于检查 prompt 和模型行为是否符合预期，不负责重复验证 UI、SSE、marker、确认流、文件写入或数据库协议。单个功能默认最多进行一次真实对话；完整四环真实回归默认最多进行一次，且仅在发布候选或确有必要时安排。
- **真实验证审批**：每次 live 验证前，必须先说明验证假设、预计对话轮数和 token/API 成本，并取得用户同意。整体耗时目标不能成为调用真实模型的理由；日常回归使用 replay。
- **ticket01 迁移后审计**：ticket01 的产品实现保持已完成状态；迁移后的验证缺口只补一次回放审计，不重新开发、不重新打开 ticket01。该审计与产品完成状态是两个独立事实。
- **风险分级**：文案和参数类验证按 L0 处理；单层体验逻辑按 L1 处理；文件更新判定和跨 Agent 共享协议按 L2 处理。L2 使用相关回放验证脚本完整检查；只有需要确认 prompt 理解时，才额外安排经批准的一次 live 冒烟。
- **先例**：verify-v1-flow.mjs（Playwright + 幂等新用户 + check 断言）、verify-agent-types.mjs、verify-protocols.mjs（marker 字面量断言）。

## Out of Scope

- v1.2+ 各 Agent 专属 bug 与体验（需求分析 / 原型 / PRD / 任务拆分依次各占一个子版本）。
- 模板案例、新手引导、成果导出增强（v1.0 已划出）。
- 「清空整个对话」变体——删除能力只做单条消息（v1.1 决策）。
- 上下文长度预警的精确 token 计算（红线：粗估即可）。
- 中断后「继续生成」（v1.1 只做到停止即止）。
- 消息编辑的撤销/历史版本（编辑即替换，无版本回退）。
- OpenAI 兼容客户端迁移本身；它属于工程基础设施，不是 v1.1 的用户功能。
