核心词汇

MongoDBMySQLPM 需要理解的含义
DatabaseDatabase一组业务数据的容器，例如当前项目的 pm_assistant。
CollectionTable 表同一类数据的集合，例如用户表、项目表。
DocumentRow 行一条具体记录，例如一个用户或一条消息。
FieldColumn 列记录的一个属性，例如邮箱、名称、创建时间。
ObjectIdPrimary Key 主键一条记录的唯一身份。具体用数字、UUID 还是字符串，由实现方案决定。
嵌套对象/数组关联表或 JSON 列要先判断它是独立业务对象，还是只适合整体保存的附属数据。
Mongo QuerySQL查询、创建、更新和删除数据的表达方式不同，不能机械翻译。
TransactionTransaction 事务一组操作要么一起成功，要么一起回滚，常用于高风险写入。

当前项目的业务关系

users -> projects -> work_records -> tabs -> messages

项目文件、文件上下文、原型快照和操作记录也有自己的归属关系。迁移验收时，不能只问“表有没有创建”，还要问“删除项目后，所有应该删除的记录是否一起消失”。

四个 PM 判断

  • 关系是否清楚：一个项目能否准确找到它的工作记录、标签页、消息和文件。
  • 数据是否完整：迁移前后记录数量、关键字段和业务行为是否一致。
  • 失败是否可恢复：迁移中断后能否重试，是否有备份和回滚路径。
  • 权限是否保留：用户 A 不能读取用户 B 的项目、文件或消息。

看到这些词时怎么问

实现方案里的词你可以追问
ORM / Driver它负责让代码连接 MySQL；为什么选它？是否支持当前 Next.js 和部署环境？
Migration旧数据怎么备份、转换、校验？失败后怎么重跑？
Foreign Key父记录删除时，子记录怎么处理？是否符合产品删除语义？
Transaction哪些操作必须原子完成？当前本地和部署环境都支持吗？
Seed / Fixture这是演示数据还是生产数据？是否会污染真实数据库？
